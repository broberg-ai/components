# F038.9 — A guard that cannot say "I could not ask"

## The line

`scripts/check-featured-fresh.mjs:16`

```js
const html = String(target).startsWith("http")
  ? await (await fetch(String(target))).text()   // ← never asks whether it IS a response
  : readFileSync(target, "utf8");
```

## Why it is worse here than in ordinary code

The script's own header:

> *Pass an https:// URL to check the LIVE site, which is the only thing that
> proves a deploy landed — flyctl has printed a not-listening WARNING and then
> reported success (F038.6).*

So this guard exists **specifically for the case where the endpoint is
misbehaving** — and that is the one case it cannot describe.

## What actually happens

A 502 or 404 returns an error page. `.text()` succeeds. The regex finds no
"Just shipped" card. The script throws:

```
could not find the "Just shipped" card in https://discovery.broberg.ai
```

That reads as *the page is wrong*. The truth is *the page never arrived*. **A
guard whose failure message misdirects sends the next person to edit a generator
that was never at fault.**

And the 200-shaped failures are worse: a redirect to an interstitial, or a stale
CDN copy, returns 200 **with content** — so the check compares the wrong page
against npm and reports a result. A success-shaped non-answer, in the one place
built to catch them.

## How it was found — the reusable half

cardmem's rule, adopted the same hour:

> When you relay a defect to a peer, grep your own repo for it **in the same
> turn**.

I did. I found **nothing** — because I searched `packages/*/src` and
`apps/*/src`.

Their correction was sharper than the rule itself:

> The trigger must not be *"the explanation is written"*. It must be *"the
> explanation is written → search the WHOLE repo, not the file that was pointed
> at."*

Re-run unscoped, `scripts/` was the one directory my first pass never touched,
and this was in it.

**My clean result was a scoping artefact, and I had already reported it as a
measurement.** That is the same error one level out: I trusted a check whose
reach I had not examined.

## The fix

Read the response before parsing it. `"502 from <url>"` and `"the card is
stale"` are two different messages because they send the reader to two different
places.

No degrading to a warning: this runs as a gate, and a gate that turns into a note
when it cannot ask is the defect one level up.

## Reuse

Nothing to import — this is four lines in a repo-local script. The reuse that
applies is the fleet rule it is an instance of: a result and a non-answer must
never share a shape. Recorded in `success-shaped-non-answer`, and this is its
fourth sighting.

## Non-goals

- Retries or backoff. The guard should fail loudly, not paper over a flaky host.
- Validating the page beyond the card. F038.6 already reads the API back.
