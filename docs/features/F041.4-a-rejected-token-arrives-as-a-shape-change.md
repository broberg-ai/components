# F041.4 — a rejected token arrives as a shape change, not a 401

**Status:** Ready · **Epic:** F041 (`@broberg/cron`) · **Written:** 2026-09-15

> Sibling of **F041.3** (contract-drift detector, in Review). Read the last
> section before building either — they overlap in a way that matters.

## What arrived

helpdesk (#28091) measured their clock-watchdog against the real service and
found that `@broberg/cron` 0.2.0 turns an auth failure into a shape failure.

## Measured here before accepting it

```
curl -H "Authorization: Bearer <wrong>" https://cronjobs.webhouse.net/api/jobs
  without -L :  HTTP 307  ->  https://cronjobs.webhouse.net/login
  with    -L :  HTTP 200, 12,057 bytes
  first bytes:  <!DOCTYPE html><html lang="en"><head><meta charSet="utf-8"...
```

**The service does not answer 401.** It redirects to the NextAuth login wall —
the exact wall this package's own file header says it exists to keep consumers
away from.

`src/index.ts:162`:

```ts
const res = await doFetch(`${baseUrl}${path}`, { method, headers: {...} });
const text = await res.text();
const data = text ? safeJson(text) : undefined;
if (!res.ok) throw parseError(res.status, data);
return data as T;
```

No `redirect` option, so `"follow"` applies. The 307 is followed, `res.ok` is
**true** on the resulting 200, `safeJson` cannot parse HTML and returns the raw
string *by design*, and the last line casts it. `listJobs()` returns 12 kB of
login page typed as `Job[]`.

### What it costs a consumer

helpdesk's watchdog could only say *"the service's answer is not a list of
jobs"*. It went red, so nobody was in danger — but **an expired token was
reported as "the API has changed"**, and those two send a person to two
different places. One is a dead end.

Their red was luck, not design: they happened to check the shape. A consumer
doing `jobs.length` gets `12057` — a number that looks like an answer.

## The second half is not where they put it

They wrote that `listJobs()` is typed `Job[]` while `request()` returns whatever
arrives. True — `return data as T` is the line. But they also reported
`lastRunAt` as an ISO string on the wire against our `number`, and concluded our
type was a promise rather than a measurement.

Our type is neither. It is **generated from the service's own published spec**:

```
package.json:27  "gen": "openapi-typescript https://cronjobs.webhouse.net/api/openapi.json -o src/schema.ts"
```

And the live spec, fetched while writing this:

```json
"lastRunAt": { "type": "integer", "nullable": true, "description": "Unix ms" }
```

So if helpdesk measured a string, **the service's spec is wrong, not our copy of
it.** That moves the defect from one consumer to every consumer: anyone
generating a client from that spec gets the same wrong type and has it confirmed
by their compiler. *A wrong spec is worse than no spec, because it manufactures
confident clients.*

**Not verified here.** No valid `CRONJOBS_API_TOKEN` exists locally and cardmem's
vault was unreachable at the time (`ENOTFOUND services.cardmem.com`). helpdesk's
measurement stands as **theirs**, unconfirmed by us — recorded that way on
purpose, because *"we checked and it was fine"* and *"we never checked"* are
indistinguishable a week later.

## ⚠️ The gap between this card and F041.3

F041.3 builds a drift detector comparing **our generated types** to **the spec**.
If the spec disagrees with the wire, *both sides of that comparison are wrong
together and the check goes green.*

Two sibling cards about one contract, and neither can currently see a spec that
lies. So whatever this card builds for shape must compare against the
**RESPONSE**, never against the spec.

## Scope

1. `redirect: "manual"` on the client fetch, so a 3xx becomes a `CronError`
   carrying its real status and `Location`.
2. `request()` stops casting a non-JSON body to the caller's type — it throws,
   naming content-type and a short prefix of what arrived.
3. Route the wire-vs-spec question to cronjobs and record their answer.
4. README: this service answers a bad token with a redirect, not a 401.

### Non-goals

- **Not** a validation library. The package has no runtime dependencies and that
  is deliberate; the shape check is a handful of lines or it does not belong.
- **Not** a hand-edit of `src/schema.ts`. It carries an auto-generated header; a
  wrong type is fixed at the spec and regenerated.
- **Not** asserting "your token expired" on every 3xx. A future 308 on a moved
  endpoint must not be diagnosed as an auth failure — that trades one wrong
  answer for another.

## Reuse

Discovery reuse check (`discovery.broberg.ai/api/search`) for "http client",
"fetch wrapper", "redirect": `@broberg/http` owns header/response primitives
(`contentDisposition()` and friends) and **not** fetch policy — no redirect or
envelope handling to adopt. Nothing else in the roster wraps `fetch`. The change
is local to this package's own `request()`; nothing to extract, because a
one-package fetch policy is not yet a shared pattern. Revisit if a second
`@broberg/*` client needs the same 3xx rule — rule of three, not of one.

## Rollout

One commit: fix + tests + mutation proof + README, then a patch release. Consumers
need no change — a call that used to resolve with nonsense now throws, which is
the point. helpdesk's local wrapper can stay until they upgrade; it is harmless
and currently the only protection that exists.
