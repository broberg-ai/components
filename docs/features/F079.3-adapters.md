# F079.3 — Stack A + Stack B adapters: the HTTP half, still carrying no version pin

> Parent: [F079 — `@broberg/chat`](./F079-chat.md) · Core: [F079.1](./F079.1-chat-core.md)

## Why this before the retrievers

The plan-doc's numbered order puts retrievers at F079.2. **This is being built first anyway**, and the reason is the blockers rather than a preference:

- The Trail retriever is **partly blocked on a decision that is Christian's** — Trail has no retention at all, its EU fallback has never been run end to end, and a tenant is only created by a human Google login. Those block fd-sundhed *going live*, not building; but they do mean a Trail retriever cannot be *proven* today.
- The adapter is **blocked on nothing**, it is where fd-sundhed's measured shape actually lands (Next 16.2.6, App Router, `app/api/admin/<ting>/route.ts`, profile re-read server-side per route), and it is what turns the core from a contract into something they can mount.
- It is also the reason `@broberg/chat` is not on npm yet: **a core without adapters is not installable-useful.**

## The one decision that shapes everything: the adapter does not own the model

It would be natural to have `@broberg/chat/next` import `@broberg/ai-sdk` and wire the model for you. **That would undo the core's best property.**

F061.2, measured this week: `@broberg/logger` promised it *"cannot leak a secret"* while shipping a `secret-scan` four minors stale, because **a caret on `0.x` locks the MINOR**. Every `@broberg/*` package is `0.x`. A package that depends on another `@broberg` package hands its consumers a version they did not choose and cannot see.

So:

| | |
|---|---|
| **Core** | zero dependencies. Model injected. |
| **`/next`, `/hono`, `/client`** | zero runtime dependencies. Next/Hono are types-only or peer; the model is still passed in. |
| **`/ai-sdk`** (a thin convenience, if it ships at all) | `@broberg/ai-sdk` as a **peerDependency with a `>=` range, never a caret** — so the consumer's installed version is the one that runs. |

`scripts/check-internal-pins.mjs` already understands `>=` and refuses to approve a range it cannot reason about, so this is enforced by the gate rather than by remembering.

## What the adapter actually owns

Request parsing · caller resolution · SSE framing · abort. Nothing else.

```ts
// app/api/admin/chat/route.ts
import { createChatRoute } from "@broberg/chat/next";

export const POST = createChatRoute({
  chat,                                   // built with createChat(), model injected
  getCaller: async (req) => await readProfileServerSide(req),   // THEIR pattern, unchanged
  getCtx:    async (req, caller) => ({ api: apiFor(caller) }),
});
```

`getCaller` is **required** and the handler refuses to build without it. Same reasoning as `can` in the core: an "anonymous by default" would look like configuration and behave like an open door.

### `getCaller` returning null is a 401, not an empty tool list

Tempting to hand an unauthenticated visitor a chat with no tools. **That is still an LLM bill**, on a surface where the visitor decides the volume. On an internal admin chat it is also simply wrong. The request never reaches the model — asserted with a spy that must record **zero** calls.

### The caller can never come from the request body

The body is written by the browser. Reading a role, a user id, or a permission list out of it is the same defect as cms's filter, moved to the wire. Asserted: a forged caller in the body is ignored.

## Streaming is the point, so it is asserted as a property, not a feature

13.1 seconds measured average, on the *fastest* tier. The test that matters is not "SSE events came out" — it is **"the first event arrived before the run finished."** Mutation: collect frames into an array before writing, and that test must go red. Everything else about the response would look identical.

**A closed tab must stop the work.** Aborting the request stops pulling from the model, with a negative control — the same fixture *without* the abort runs to completion — so the test proves the guard rather than the fixture.

## Errors are data, never a dead stream

A stream that just stops is indistinguishable from a slow answer. That is the exact failure `@broberg/seti-client/sse` exists for, and it is why a thrown tool **and** a thrown model both arrive as an `error` event followed by `done`, with the HTTP status still 200 because the stream had already begun.

## Two adapters, one table of cases

Both adapters are driven by **one shared table of cases**. *Fix-one-half-of-a-pair* is a measured fleet defect, not a hypothetical — a behaviour that holds in Next and not in Hono should be a red test, not a discovery in production.

## The client half

`@broberg/chat/client` reads the SSE and yields the same typed frames the core produced. Proven by a **round-trip with strict deep-equality** — core frames → SSE bytes → client frames — including the two shapes that break naive SSE parsers: a multi-line text delta, and a payload containing a blank line.

## Non-goals

- **Not the widget.** No React, no Preact, no markup. That is F079.4.
- **Not the model.** No provider SDK, no key handling, no tier selection.
- **Not persistence.** The adapter stores nothing; retention is F079.6 and is a required value with no default.
