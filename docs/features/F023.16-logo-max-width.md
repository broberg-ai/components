# F023.16 — The sized logo must never be wider than the screen

## Why
Reported by beacon, 22 Oct 2026 (intercom 3912), measured on a real mail: FIRST COAT's confirmation mail uses a banner image as logo with `logoWidth: 440`. `renderShell` writes `style="display:block;margin:0 auto;width:440px;height:auto;border:0"` with no `max-width`, so in a 452 px frame the card grows wider than the frame and the body text is cut off on the right. Phones are ~390 px, so this hits real recipients. The same mail without the image fits at 450 px.

## Scope
- `packages/mail-core/src/index.ts`: when `logoWidth` is set, the img style becomes `width:${logoW}px;max-width:100%`. The `width` HTML attribute stays — Outlook ignores CSS widths and needs it (that is why `logoWidth` exists).
- Unsized logo (`max-width:180px`) unchanged.
- Patch release 0.9.1, release report (D-b7eb14).

### Non-goals
- Any other layout change in the shell.

## Verification
Unit test on the exact style string + negative control; Lens capture at 390 px of 0.9.1 vs 0.9.0 output.

## Reuse
This IS the shared package (`@broberg/mail-core`); fixing it here fixes every consumer.

## Rollout
Tag `mail-core-v0.9.1` → OIDC publish → report to beacon (+ known consumers). Rendered output changes ONLY for mails that pass `logoWidth`, and only by adding `max-width:100%`.
