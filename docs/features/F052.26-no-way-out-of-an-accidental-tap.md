# F052.26 — An accidental tap has no way out

**Parent:** F052 · **Status:** backlog · 2026-08-28
**Found by:** fd-sundhed, while asking about something else.

---

## Their question, and its answer

> "Fjern-knappen er gated på `current &&`, altså først når en intensitet er valgt.
> Trækker man på en kropsdel og fortryder straks, er der ingen fjern-knap — kun
> tryk-igen. Er det med vilje?"

**Yes, and it should stay that way.** `current` is the region's entry in the
report. Selecting a region writes **nothing**; only choosing an intensity does. So
with no intensity there is genuinely nothing to remove, and a «Fjern punkt» button
there would tell the user something had been stored when nothing had.

## What checking it turned up

Measured — Lens `e9075e5e`, iphone-15, real WebGL. Tap a region, then tap **the
same region again** without choosing an intensity:

| | |
|---|---|
| panel still open | **true** |
| remove button | absent |
| report points | **0** |

`decidePick` correctly returns `"select"` both times — an unmarked region is not in
the report, so F052.20's rule is right and this is not a bug in it.

**But the consequence is that an accidentally opened region has only two exits:**

1. mark it — writing something you did not mean, or
2. tap a different body part — opening one you did not mean either.

On a phone that is the likely case, not the rare one: the body is small and the
finger covers the target. F052.8 already established this component is primarily a
touch surface.

## Why nobody saw it

Every test and every flow in this package taps a region **in order to mark it**.
Nobody ever tested *changing their mind*. Nothing here is wrong — it is a path with
no exit, and **paths with no exit do not fail, they strand people.**

## Constraints on the fix

- Do **not** show a remove button when nothing is marked.
- Do **not** change `decidePick` — that rule is shared with the 2D renderer, and
  overloading it would make the same gesture mean different things depending on
  whether the region happened to be marked.
- Keyboard-reachable, `data-testid`, real feedback states (F052.11 is a legal duty
  here).
- Closing must **never** write to the report — assert on the serialized
  `bodymap/v1` record, not on the panel.

## Not started

Filed from a peer report, not an owner-in-session defect, so it queues normally
rather than jumping the board. Small — 1 point.
