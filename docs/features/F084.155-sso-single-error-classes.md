# F084.155 — Én fejlklasse, ikke to

**Rapporteret af:** appkit 10/10 2026 (#2498), udledt af bundlen. **Målt af components samme dag** på 0.14.1 fra npm: `SsoReauthError` er defineret i både `dist/index.js:176` og `dist/hono.js:177`; `hono.SsoReauthError === main.SsoReauthError` er false.

## Hvorfor det betyder noget
`getAccessToken` (fra `@broberg/sso/hono`) kaster `SsoReauthError`, når brugeren skal logge ind igen. Den naturlige kode i en app er `catch (e) { if (e instanceof SsoReauthError) redirect(login) }` med klassen fra `@broberg/sso`. Den gren rammes aldrig: appen viser en fejl i stedet for at sende brugeren til login. Det fejler i stilhed, fordi koden ser rigtig ud.

## Årsag
`tsup.config.ts` bygger `index` og `hono` i to separate configs. Hver bundle inlines `src/client.ts`, så klasserne findes to gange.

## Løsning
Én tsup-config med begge entries og code splitting (esm, og cjs via tsup's splitting-flag), så `client.ts` havner i én delt chunk. `dist` renses stadig én gang af build-scriptet. verify-exports udvides til at fejle, hvis en fejlklasse er defineret mere end ét sted.

## Bevis
vitest mod den byggede dist (esm + cjs): fejl fra `/hono` er `instanceof` klassen fra roden. Ren installation mod 0.14.1.

## Reuse
Rettelse i @broberg/sso; ingen ny kapabilitet.
