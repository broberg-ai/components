# F001.11 — The bridge that points at itself, and the round-trip that could not see it

**Status:** ready · **Parent:** F001 (@broberg/theme) · **Priority:** high · **3 SP**

Reported by **cardmem** via **cms** (who do not use the package at all — 0 hits in
their `package.json` and code, so they could neither confirm nor fix it). Verified
here by generating output from a fixture before writing a line of this doc.

## What was reported — and it is wider than reported

### 1 · The self-referencing bridge, in THREE namespaces

```js
root.push(`  --radius-${name}: ${value};`);
theme.push(`  --radius-${name}: var(--radius-${name});`);   // ← points at itself
```

A custom property whose value is `var(--itself)` has **no computed value**. It
resolves to nothing.

cardmem pointed at `rounded`. The same two lines, with the same names on both
sides, are also in **`spacing`** and **`typography.fontSize`**. Colours escape
only because the raw name differs (`--ivory` → `--color-ivory`).

Measured from a fixture:

```css
:root {
  --ivory: #FFFFF0;
  --radius-DEFAULT: 8px;
  --radius-lg: 12px;
  --spacing-gutter: 16px;
  --text-body: 16px;
}
@theme inline {
  --color-ivory: var(--ivory);          /* fine — different names */
  --radius-DEFAULT: var(--radius-DEFAULT);   /* ← self */
  --radius-lg: var(--radius-lg);             /* ← self */
  --spacing-gutter: var(--spacing-gutter);   /* ← self */
  --text-body: var(--text-body);             /* ← self */
}
```

**cardmem's observation is the sharp one:** it *appears* to work, because
Tailwind's theme block lands before the imported plain CSS, so the real `12px` is
the last declaration and wins. **Correctness rests on cascade order, nothing tests
it, and it flips the day an import moves.**

### 2 · `DEFAULT` becomes a literal suffix

`rounded: { DEFAULT: "8px" }` emits `--radius-DEFAULT`. In Tailwind, `DEFAULT`
means *the bare name* — `--radius`. cardmem measured **30 uses of
`border-radius: var(--radius)` with nothing behind them**: square corners on
modals, cards and inputs, and a bare `.rounded` falling back to Tailwind's
0.25rem. `vite build` said nothing.

### 3 · Whole namespaces dropped in silence (open from #23742)

`fontFamily`, `shadow`, `motion` and any arbitrary namespace are parsed and
discarded — **58 of 72 tokens** in cardmem's file. `typography` reads only
`fontSize`; `fontWeight`, `lineHeight` and `letterSpacing` are in the TypeScript
interface and never emitted.

### 4 · The output carries its own `@import "tailwindcss";`

A consumer with an existing import has to strip it.

## THE PART WORTH LEARNING FROM — F001.8's own verification

F001.8's completion note says: *"round-trip vs neutral-preset.css verified
EXACT"*. It was, and it proved nothing about any of this, because it compared our
generator's output to a file written in the same shape. **Every defect above is
invisible to a test that asks "does the generator produce the string we expect?"
and visible only to one that asks "does a browser resolve these to the intended
value?"**

Same family as everything else this week: a green that holds because of what it
compares, not because of what is true.

## Approach

1. **The bridge must not self-reference.** Either emit raw tokens under a distinct
   prefix (`--rounded-lg` raw → `--radius-lg` themed, the shape colours already
   use), or emit the value directly in `@theme` with no `var()` at all. Decide
   once and apply to all four namespaces identically — the asymmetry is what made
   this survive.
2. **`DEFAULT` → the bare namespace name**, for every namespace, not just radius.
3. **Nothing is dropped in silence.** Either emit the namespace or *report* it.
   A generator that discards 58 of 72 tokens and exits 0 is the same
   success-shaped non-answer this repo has now hit five times in a week.
4. **`@import "tailwindcss";` becomes opt-out** (or opt-in), documented either way.
5. **Test what a BROWSER resolves, not what the string looks like.** At minimum,
   assert that no emitted property references itself, and that every
   `var(--x)` in the theme block has a definition that is not `--x`.

## Non-goals

- Not rewriting the generator's scope. DESIGN.md's namespace list is the input;
  this card makes the ones we accept correct and the ones we drop loud.
- Not adding a Tailwind runtime dependency to test resolution.

## Coordination

cardmem has neutralised 1 + 2 locally with a mutation test **that goes RED when we
fix it upstream**, so they find out and can remove their patch. **Tell them on
release.** That is a good pattern and worth naming: a workaround that announces
its own obsolescence.
