# F105.4 — Motoren melder imagets base og distro

> Story under F105 (image-hygiejne-motoren). Bestilt af cardmem 23/10 2026 (#4082, cardmem-F401.7) efter ejerens slim-standard.

## Hvorfor
Ejeren vedtog 23/10: kørende images i alle Fly-apps er `node:24-slim` (Node) eller `oven/bun:1-slim` (Bun), flydende i majoren, aldrig `:latest`, fuld Debian/Ubuntu eller Alpine. cardmems audit — og Discovery-oversigten (#4083) — skal kunne se hvem der følger den. Dockerfiles på disk er målt forældede (pitch/cronjobs), så kilden er motorens nattlige rapport om det image der FAKTISK udrulles.

## Scope
1. `scripts/image-hygiene-base.mjs` (testbar, ingen afhængigheder): `parseOsRelease(text)` → `"debian 12"`; `lastFrom(dockerfile)` → billedet i sidste `FROM` (springer `--platform=` og `AS name` over). CLI: `node image-hygiene-base.mjs <os-release-fil> <Dockerfile>` → JSON `{ base_os, base_image }`, null for det der mangler.
2. `image-hygiene.yml`: efter pull af digest: `docker create` + `docker cp <cid>:/etc/os-release` (kræver ingen shell i imaget, så distroless virker), og Dockerfilen ved build-sha. Felterne `detail.base_os` og `detail.base_image` i rapporten. Additivt; en fejlet måling = null, aldrig en fejlet kørsel.
3. Renovate-presettet: `node` kun lige majors med `-slim` (LTS), `oven/bun` kun `-slim`. Renovates docker-versionering holder i forvejen suffikset som kompatibilitet; reglen gør det eksplicit og afviser ulige Node-majors.

### Non-goals
- Ingen håndhævelse: motoren melder, cardmem afgør om appen følger standarden.
- `base_image` er Dockerfilens tekst (kan indeholde `${ARG}`) — ikke en opløst digest.

## Reuse
Udvider den eksisterende motor (F105.1) og preset (F105.2). Ingen ny pakke.

## Udrulning
Ny tag `v1.0.4`; cardmem flytter sin `hygiene.yml` til den. Bevis: en rapport med udfyldt `base_os` + `base_image`.
