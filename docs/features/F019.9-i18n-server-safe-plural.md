# F019.9 — @broberg/i18n: ren server-vej + flertal

> **Udløser:** cms intercom 3747, 22/10 2026. Ejeren vil have ægte i18n i cms-admin (Next 16, ~200 skærmfiler): dansk først, så LLM-oversat til ~10 sprog. cms vil bruge `@broberg/i18n` frem for at rulle eget.
> **Status:** backlog — ikke bygget. Punkt 1–2 i cms' liste; punkt 3 (lazy-loading) er F019.5, punkt 4–5 er F019.10.

## Problemet

0.1.0 er bygget til browseren: en `globalThis`-singleton med `getLocale()`. I en Next server-komponent deles den mellem samtidige requests, så én brugers sprog kan lække til en andens side. cms' faste regel er ingen process-global tilstand i request handlers.

## Hvad der bygges

1. **Ren funktion:** `translate(messages, locale, key, vars?)` — ingen tilstand, ingen `globalThis`. Evt. en tynd `createI18n({ locale, singleton: false })`, der returnerer en instans med egen `t`, til apps der vil have samme API pr. request.
2. **Flertal:** nøgleværdi kan være `{ zero?, one?, two?, few?, many?, other }`; `t(key, { count })` vælger form via `new Intl.PluralRules(locale).select(count)`, falder tilbage til `other`, og interpolerer `{count}`.

## Non-goals

- Singleton-API'et ændres ikke (browser-forbrugere mærker intet).
- Ingen ICU MessageFormat — kun flertal.

## Test

To samtidige `translate`-kald (da/en) interleaved med `await` → hvert sit sprog, singletonen urørt. Flertal for da og pl. Negativ kontrol: eksisterende tests uændrede. Mutationer.

## Rollout

Minor-version af `@broberg/i18n`, release-rapport til cms.

## Reuse

Hører i `@broberg/i18n`. Ingen ny afhængighed (`Intl.PluralRules` er indbygget).
