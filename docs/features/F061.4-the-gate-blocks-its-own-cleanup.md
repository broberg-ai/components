# F061.4 — The secret gate blocks the commit that REMOVES a secret

**Status:** In progress · **Epic:** F061 (build hardening) · **Written:** 2026-08-31
**Ordered by:** Christian

## Motivation

Not theorised — hit live, by the gate doing its job. Committing the deletion of a
stale plan-doc was refused:

```
COMMIT BLOCKED — @broberg/secret-scan recognised a credential format in this commit
  aws-access-key-id ×2
```

The file quoted AWS's public documentation key. Deleting the file produces a `-`
line containing that key, and `.githooks/pre-commit` scans `git diff --cached`
**in full** — additions and removals alike.

**So the commit whose entire purpose is to remove the credential is the one the
guard refuses.** The guard prevents exactly the cleanup it exists to force, and
the only workaround it leaves is `--no-verify`, which is the one thing that must
never be done to this gate.

It belongs under F061 beside F061.2 (internal pins that can never resolve) and
F061.3 (packages that cannot report their own version): **all three are a repo
guard that reads as enforced and is not.**

## Reuse

Checked `discovery.broberg.ai/api/search?q=pre-commit+secret+scan+hook`. The
capability is `@broberg/secret-scan`, which **this repo owns**, and the hook is
this repo's own `.githooks/pre-commit`. Nothing to adopt; the scanner package is
unchanged by this card — only what the hook feeds it. No provider integration.

## The defect, in both layers

```
layer 2 (:31)  git diff --cached > "$diff_file"          then greps for .env VALUES
layer 3 (:64)  git diff --cached -- . "${EXCLUDES[@]}"    then pipes to redactSecrets
```

Identical defect, identical reasoning: **a removed secret is already in git
history**, so refusing the removal helps nobody and actively blocks remediation.
What must stay refused is *adding* one.

Fixing only the layer that happened to fire would be the same half-of-a-pair
mistake this repo has named repeatedly this week — including inside the very
package this hook calls.

**Layer 1 is untouched.** It matches file *names*, and staging a `.env` is wrong
whichever direction the line points.

## Design

Extract added lines once, feed both layers from it:

```bash
git diff --cached -U0 -- . "${EXCLUDES[@]}" \
  | grep '^+' | grep -v '^+++' | sed 's/^+//'
```

**The trap is `set -euo pipefail`.** `grep` exits 1 when it matches nothing, which
kills the script — and a diff with zero added lines is not an error, it is exactly
the pure-deletion commit this card exists for. The extraction must tolerate an
empty result, and that case gets its own assertion rather than a comment, because
it is the one a reader would assume works.

## Scope

1. Added-lines-only extraction, applied to layer 2 **and** layer 3.
2. `scripts/test-precommit-secret-gate.mjs` — both directions, both layers.
3. Mutation pass: revert to full-diff → removal test red; scan nothing → addition
   test red. Each asserts its anchor applied first.
4. Wire into `pnpm test`.
5. Delete `docs/features/F035.12-the-half-that-had-no-numbers.md` — the original
   blockage, and the end-to-end proof.

## Non-goals

- Changing `@broberg/secret-scan` itself. Its defects belong to F035.12; this card
  is only about what the hook feeds it.
- Any `--no-verify` escape hatch, documented or otherwise. A gate with a published
  bypass is not a gate.
- Touching layer 1.

## Rollout

Hook only — no package release, nothing published. Takes effect for every
committer on this repo at the next commit, since `core.hooksPath` is already set
by `prepare`.
