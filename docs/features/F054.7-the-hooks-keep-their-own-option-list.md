# F054.7 — Both hooks silently drop two of the core's options

**Status:** Ready
**Parent:** F054 — `@broberg/pwa`
**Reported by:** fd-sundhed, against the installed `0.2.2` dist
**Measured here** — and it is broader than the report

---

## The measurement

| | options |
|---|---|
| `createPwaUpdater` (core) | `swUrl` · **`register`** · `pollIntervalMs` · **`updateOnFocus`** · `reloadOnControllerChange` · `disabled` |
| `usePwaUpdate` (react) | `swUrl` · `pollIntervalMs` · `reloadOnControllerChange` · `disabled` |
| `usePwaUpdate` (preact) | the same four |

**Two** options are silently dropped, in **both** adapters: `register`, which
fd-sundhed reported, and `updateOnFocus`, which nobody found.

The hook keeps its **own hand-written list**, and it has drifted from the core's.
That is the duplicate-definition shape this repo has been bitten by repeatedly:
the copy is not wrong the day it is written, it is wrong the day the other one
changes.

## Their case

`@serwist/next` already registers `/sw.js` for them. They set `register: false`
precisely so it would not happen twice, and have run that way since adopting. In
production `/sw.js` is therefore registered twice on the same scope.

**Their own limit, kept because it is the honest framing:** they do *not* claim
this causes a failure. One `Failed to register a ServiceWorker` in Upmetrics
(25 Aug, one occurrence, never repeated), and two registrations of the same URL
and scope are supposed to be idempotent per spec. They have not proven a link and
decline to guess one.

**What they are reporting is the shape: a setting that is silently ignored.** The
consumer reads their own code and believes they are safe; the code says one thing
and the package does another, with no signal. Their comparison is exact — the
same family as `@broberg/mail`'s `live` trap fixed in F005.8, in the other
direction.

## The fix is not two names

Adding `register` and `updateOnFocus` to the adapters' destructure would close
today's gap and leave the mechanism intact. **The hand-written list is the
defect.** A third option added to the core next month must not be able to go
missing.

And the test must drive `register: false` **to the boundary** — asserting
`container.register` was not called — rather than asserting that an option was
"passed through". The second proves the shape of an object; only the first proves
the behaviour a consumer depends on. fd-sundhed asked for exactly this test, and
noted that reading our dist is not a durable detector. It is not.

## Timing

They launch **Tuesday 1 September at 07:00** for 16,838 municipal employees and
explicitly do **not** want a new version before then. This ships when it is
ready; they adopt after.

## Rollout

1. Prove RED against 0.2.2: `register: false` still registers, in both adapters.
2. Remove the hand-written lists so the adapters cannot drift from the core.
3. Boundary tests with a fake container, both adapters, both options.
4. Mutation pass — reintroducing a hand-written list must turn a test red.
5. Publish, verify from the tarball reading the shipped dist for both adapters,
   tell fd-sundhed after their launch window.
