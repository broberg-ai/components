# F063.1 — Core logger

> Story under **F063 — @broberg/logger**.

## Motivation

This story IS the package. Everything else (`/hono`, adoption) is delivery.

Two properties justify its existence, and both are easy to build in a way that *looks* right and is not:

**1. Redaction must be proven on the emitted line.** A test that inspects the record before serialisation proves nothing about what reached stdout — that is the exact shape of failure this session hit three times (a guard that could not fire, a check that matched nothing, a flaky race). So the sink is injectable purely so a test can capture the **actual output string** and assert the secret is absent from it.

**2. It must never throw.** This sits in the request path of every app. A logger that crashes the request is strictly worse than no logger — the app was working before you added observability.

## Scope

```ts
createLogger({ name?, level?, pretty?, redact?, sink?, bindings? })
  -> { debug, info, warn, error, child }
```

- **Levels** `debug < info < warn < error`. Explicit option > `LOG_LEVEL` > `info`.
- **Redaction ON by default**, over the message *and recursively* over metadata values, via `@broberg/secret-scan`. `redact:false` opts out.
- **Output** one-line JSON (`pretty:false`) or readable text (`pretty:true`).
- **`child(bindings)`** merges and nests.
- **`Error`** → `{ name, message, stack }`.
- **`sink`** injectable — for tests, not as a transport system.

### Non-goals

No transports, rotation, buffering, sampling or aggregation. No `fatal`/`trace` — four levels is enough, and every extra level is a decision every consumer then has to make.

## Architecture sketch

```
level gate -> build record -> redact -> serialise -> sink
                               ^
                    secret-scan redactSecrets
```

The entire chain is wrapped in one try/catch that swallows. Redaction runs on the **serialised** payload rather than per-value where possible, so one pass covers message and metadata together and nested values cannot be missed by a traversal bug.

## Dependencies

`@broberg/secret-scan` only.

## Reuse

Redaction is reused, not re-rolled — `@broberg/secret-scan` is the canonical fleet pattern list (38 patterns incl. the Hue key beacon contributed 2026-08-07). Building a second redactor here would be exactly the drift the reuse rule exists to prevent.
