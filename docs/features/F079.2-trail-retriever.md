> **Christian, 2026-08-27:** *"ALLE CHATS SKAL anvende trail — det er IKKE til diskussion."*

So the four retrievers sketched in the epic become **one**. The others are not deferred for lack of time; they are **out of scope by decision**:

| Sketched | Status |
|---|---|
| `trailRetriever` | **This story.** Trail is the brain of every chat. |
| `documentRetriever` (a long text cc maintains per site) | **Dropped.** It would be a second knowledge store, which the epic already lists as a non-goal. fd-sundhed's admin knowledge is markdown — and that markdown goes *into* Trail, not into a competing local store. |
| `collectionRetriever` (live CMS content) | **Not now.** It is a live-data tool, not a knowledge base, so it does not compete with Trail — but no current consumer needs it. fd-sundhed's operational questions are about their *own* app data, which they answer with their own site-specific tools. It arrives with the Eir/CMS pilot (F079.7). |
| `schemaPrompt` (generated from the site's data model) | **Not now**, same reason. cms proved it works; nobody who is adopting today has a CMS schema. |

Writing this down so the omission reads as a decision rather than an oversight.

## Knowledge is a TOOL, not a prefetch

Eir's measured shape, and the reason it is right: **the model decides when to look something up, and does it in the user's own words.** A prefetch retrieves against the question as typed, before anyone has worked out what is actually being asked; a tool retrieves after.

It also means knowledge inherits the core's authorization for free — `trailRetriever()` returns a `ChatTool` with a declared permission, so a caller who may not use it is never offered it.

## Three outcomes, never two

The single most important property in this story:

```
found  ·  nothing found  ·  COULD NOT ASK
```

A timeout, a 5xx, a thrown socket error and a malformed body must each produce a result the model is told is **a failure to look** — textually distinct from a genuine empty hit.

**Why this one, above everything else:** Christian asked Eir whether Sanne sells anything and Eir said **no**, confidently, because the shop tool was missing. The model was not confused; it was blind and sounded certain. At the *retriever* level that same failure would hit **every chat in the fleet at once**, because every chat now shares one knowledge path.

So a test drives the whole loop — core plus retriever — against an unreachable Trail and asserts the model is handed language that **cannot** be read as *"no such thing exists"*.

## The knowledge base is configuration, never an argument

`kbId` is passed to `trailRetriever()` and **never appears in the JSON Schema the model sees**. A `kbId` arriving in the model's arguments is *ignored*, not merged.

If the KB were an argument, a model could be talked into reading another tenant's knowledge base — and trail's own code comment records that an older version resolved on id alone, without a tenant check. Two knowledge bases are already planned for fd-sundhed alone (admin and end-user), written for readers with different rights; the employee's chat must not be able to reach the manager's answers.

The bearer token is read inside `run()` and never placed on a frame. A test scans **every** emitted frame for it — including the error path, which is the likeliest leak.

## Freshness, and the absence of it

fd-sundhed's objection to a knowledge base was the strongest argument anyone made this week, and it survives as a requirement:

> All four of their prose answers are **decisions that have changed** — one of them flipped twice in four hours. A knowledge base carrying last week's answer is confidently wrong on exactly the question where being wrong means telling a manager something about an employee's body.

So: when Trail reports when a passage was last updated, the result carries it, and an answer can say *"as of 13/8"*. When Trail does **not** report it, the result says so **in words** rather than omitting the field — **a missing date must never read as "current"**. An absent verdict getting read as a verdict is a failure this fleet has now measured in both directions.

## A ceiling, and what it dropped

Passage count and total size are capped, and a truncated result **says** it was truncated.

cms measured a system prompt of 6,619 tokens that was **56% schema, with no ceiling, rebuilt on every message**. A retriever with no cap is that defect on a surface where the knowledge base only ever grows.

## `fetch` is injected

Same reason the model is: the package keeps **zero runtime dependencies**, every state above is provable with no network and no key, and nothing here can inherit a stale pin.

## The wire shape is asked for, not guessed

Both `trail` (the owner) and `sanne` (the only working implementation in production) have been asked for the exact endpoint, auth, response shape, failure behaviour and freshness metadata. Their answers go in this file **verbatim**, and **where they disagree that disagreement is written down rather than averaged** — a live implementation and a documented one diverging is itself a finding.

## Not live-verified — and it says so

Until Christian creates fd-sundhed's knowledge base — **a Trail tenant exists only after a human Google login, so only he can** — no call has been made against a real Trail. The card, this plan and the README all say that in plain words rather than implying coverage.

## Non-goals

- Not a second knowledge store, not a cache of Trail, not embeddings.
- Not conversation-history management — that is its own problem, filed separately after cms measured that an overflowing chat becomes permanently unusable.
- Not the widget, not retention.
