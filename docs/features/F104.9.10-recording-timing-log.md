# F104.9.10 — Optagelsestjenesten logger hvor lang tid det tager

**Ejeren 3/11 2026 (ordret):** «Du burde lave en log der tæller hvor langt tid det tager».

## Hvorfor

I dag findes starttiderne kun i målescripts kørt i hånden (36 s kold, ~4 s efter opvarmning). I drift kan ingen se, hvor lang tid en rigtig optagelse tog — og dermed heller ikke, om opvarmningen virker for brugerne.

## Hvad logges (JSON-linjer i voice-control)

| Linje | Felter |
|---|---|
| `recording started` | id, room, egressId, **layout**, **warmth** (cold/warming/warm ved «Optag») |
| `recording live` (én gang) | id, **startToLiveMs** (anmodning → egress ACTIVE), attempts |
| `recording saved` | id, **stopToFileMs**, bytes, durationSec |
| `recording not saved` | id, error, **stopToEndMs** (stoppet før den kørte) |
| `recording machine warmed up` (findes) | ms |

Tiderne måles i control's egen klokke; opløsningen er tick-intervallet (1 s).

## Ikke i scope

- Et dashboard eller Upmetrics-metrikker — kan bygges på linjerne senere.

## Reuse

Ingen ny pakke; control's eksisterende JSON-log.

## Bevis

Enhedstests med falsk klokke; de tre linjer i flyctl logs fra ejerens næste demo-optagelse.
