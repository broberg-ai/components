# F053.15 — Under Bun afviser webhook-handleren hver ægte Stripe-webhook

## Hvad er galt
`createStripeWebhookHandler` kalder `stripe.webhooks.constructEvent(rawBody, signature, secret)` — den SYNKRONE verifikation. Under Bun vælger stripe's `exports`-condition `bun` → `stripe.esm.worker.js`, som bruger `SubtleCryptoProvider`. Den kan ikke køre synkront og kaster. Handlerens `catch` gør det til en 400, som ligner en forkert signatur. Stripe retrier til den opgiver; intet bliver fulfilled.

Rapporteret af beacon (#4531, 25/10), blokerer deres F004.3 (kreditkøb). Reproduceret her: bun → sync kaster / async ok; node → begge ok.

## Rettelse
`await config.stripe.webhooks.constructEventAsync(rawBody, signature, secret)` i rotationsløkken. Virker i Node (NodeCryptoProvider er også async-kompatibel), Bun og edge. Ingen API-ændring for forbrugeren: handleren var allerede async.

## Non-goals
- Ingen ændring af dedupe (F053.9), refund (F053.8) eller direct charges.
- Ingen bump af stripe-peer-range.
