# F035.11 — `announced` eats the word after «secret:»

**Status:** Ready — a live corpus is being corrupted while this is open
**Parent:** F035 — `@broberg/secret-scan`
**Found by:** super · **verified by:** buddy, against 40,369 rows of real fleet prose
**Reproduced here** against a clean install of the published `0.5.1`

---

## Reproduced, not taken on report

```
'Set som secret: gh secret set MYPAT'
  -> 'Set som secret: [REDACTED:announced-secret] secret set MYPAT'
'indeholder ÉN secret: en openrouter-nøgle'
  -> 'indeholder ÉN secret: [REDACTED:announced-secret] openrouter-nøgle'
'client secret: abc'
  -> 'client secret: [REDACTED:announced-secret]'
'jeg siger det aldrig — secret: ALDRIG'
  -> 'jeg siger det aldrig — secret: [REDACTED:announced-secret]'
```

The rule is a label list followed by `\S+`. In Danish and English prose
«secret:» is ordinary text, so the next word disappears.

## buddy's measurement — why this is urgent rather than theoretical

23,801 intercom messages + 16,568 conversation turns:

| | |
|---|---|
| candidates after «secret:» examined | **110** — the reach, not zero |
| not recognised by any FORMAT rule | 106 |
| unique candidates | 49 |
| of those, <16 chars and digit-free = prose | **35** |
| hex-like (≥16 hex chars) | 0 |
| real secrets `announced` caught that the format rules did NOT | **0** |

On 40k rows of real prose the axis contributed **zero** unique catches and
**35 corruptions**. The format rules did fine in the same run — 61 real findings
across 17 labels. It is `announced` alone that is noisy.

They are running with `announced: true` **right now**, holding the originals
locally, and will re-redact when a fix ships.

## Why not simply turn it off

Their argument, and it is right: our own JSDoc says
`redactSecrets("Adgangskode: hunter2")` returns `findings: []` without the axis —
**that hole is exactly what it exists to cover.** Trading the protection away to
stop the noise is the wrong direction.

They also deliberately did **not** build a local filter around us. That is the
drift the reuse rule exists to prevent, and declining to do it is what makes this
a package problem instead of a private workaround.

## The half that decides the test

Theirs, and it is the important one:

> **The check must run in BOTH directions.** An over-broad redaction destroys a
> corpus as effectively as a narrow one leaks it.

So the fix needs *a real key still disappears* **and** *text that merely mentions
the word is untouched character for character*. The second assertion is strict
equality on the whole string — "no finding" is a weaker claim than "unchanged".

## Design

A **plausibility test on the CANDIDATE**, before it is judged.

Narrowing the label list would be the tempting fix and it is the wrong one: the
greedy `\S+` would still sit behind every label that remained.

buddy's 35 prose cases are all short and digit-free, so the threshold is derived
from their numbers rather than chosen. A candidate that any **format** rule
already recognises is redacted regardless — the two axes must not be able to
cancel each other.

**`scanned` must still report `'announced'`** even when the plausibility test
rejected every candidate. "We looked and found nothing" staying distinguishable
from "we never looked" is 0.3.0's whole contract, and a fix that quietly drops
the axis from `scanned` would break it while looking correct.

## Rollout

1. Prove RED against published 0.5.1 with buddy's four real strings.
2. Plausibility test + format-rule precedence.
3. Both directions asserted; the negative one byte-for-byte.
4. Mutation pass — harness refuses to run on an uncommitted file, every mutation
   asserts its anchor.
5. Publish, verify from the tarball with the probe printing the version it
   resolved, tell buddy so they can re-redact from their originals.
