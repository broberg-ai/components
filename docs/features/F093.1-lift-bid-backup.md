# F093.1 — @broberg/backup 0.1.0: lift BID's proven nightly backup

## Motivation
F093 was written 4/10 as an interim plan with five open questions. On 9/10 broberg-id reported (#2430) that its `src/db-backup.ts` has run in production since 29/9: 11/11 nights read back and sha-checked. Three consumers wait for a shared package: broberg-id (moves over), fd-sundhed F006.432, appkit F010.1 (blocked by F093). Porting running code beats designing from scratch (house rule: port, never rewrite).

## What BID's code answers (the F093 open questions)
1. What: a logical JSON dump of the app's own tables (not a raw file copy).
2. Proof: read back + sha every night; we add restore-to-an-empty-instance as a test.
3. Retention: 30 days, one copy per day. GDPR erasure in old backups is answered by the window: an erased person is gone from every backup after 30 days. Stated, not solved further here.
4. Encryption: AES-256-GCM per backup, data key wrapped with RSA-OAEP. The machine holds only the public key, so a stolen machine cannot open old backups. Private key in the cardmem vault.
5. Source: BID's db-backup.ts.

## Scope
- `createBackup({ dump, publicKeyPem, media, prefix })` → gzip → AES-256-GCM → wrapped key → store via @broberg/media under `<prefix>/<date>.bak`.
- `restoreBackup({ object, privateKeyPem })` → the JSON dump. Never writes into a database itself.
- `pruneBackups({ media, prefix, days })` — only under the given prefix.
- `backupFreshness({ media, prefix, maxAgeHours })` → `{ ageHours, ok }` for an Upmetrics probe.

## Non-goals
- Restoring into a LIVE database (destructive; needs the owner's own words each time).
- Postgres physical backups, volume snapshots.
- A scheduler: the app calls it from its own cron (@broberg/cron / cronjobs.webhouse.net).

## Architecture
Framework-free Node/Bun core, node:crypto + node:zlib, no new runtime dependency beyond @broberg/media as a peer. Dump/restore format is plain JSON so it outlives the app's schema version.

## Dependencies
@broberg/media (R2, EU jurisdiction). broberg-id's db-backup.ts as source (read via their repo or ask_peer bid).

## Reuse
Discovery: no backup package exists. Builds on @broberg/media and the BID implementation; @broberg/cron for scheduling at the consumer.

## Rollout
Port + tests + mutations → bootstrap publish 0.1.0 (first publish of a new name needs the owner's npm OTP) → Trusted Publisher → Discovery row → release report to broberg-id, fd-sundhed, appkit. broberg-id moves over first (it is the source, so a diff against its own output is the proof).
