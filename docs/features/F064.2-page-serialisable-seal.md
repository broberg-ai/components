# F064.2 — Seal the page-serialisable contract

> Story under **F064**. Raised by **cardmem** (#19270) after they read our `dist`.

## Motivation

`page.evaluate(fn, arg)` does not send a closure. It serialises the function to
**source** and re-evaluates it inside the browser. So a page-serialised function
must be **free-standing**: it may reference its own arguments, its own locals,
and browser globals — nothing else.

cardmem's observation, which is the important half:

> … den egenskab `page.evaluate` kræver, og præcis den som **INGEN Node-side
> unit-test kan se**, fordi et direkte kald lykkes uanset.

That is true of **every test shipped in F064.1**. They import `evalAssertBody`
and call it directly, so the module scope is right there. Add a module-scope
helper tomorrow and all 17 stay green — then the first real flow run throws
`ReferenceError: helper is not defined`, in the browser, on someone else's
machine.

**This is the same defect family as the bug it was written to fix:** a guard
that cannot fire. Fixing the false green with a suite that has its own blind
spot would have been an unusually neat way to repeat the mistake.

`isEditableElement` has the identical exposure — it is serialised via
`locator.evaluate` — and the identical absence of a test.

## Scope

One seal, applied to both page-serialised functions:

```ts
// Reconstruct from source, exactly as page.evaluate does — the rebuilt copy has
// NO access to module scope, so an outside reference throws on call.
const detached = new Function(`return (${fn.toString()})`)();
```

Then: call `detached` on the real probes and assert it behaves identically to the
imported function.

**Prove the seal can fire** by reconstructing a deliberately-offending variant
the same way and asserting `ReferenceError`. A seal that has never been shown to
fail is not a seal — which is the whole lesson of F064.

### Non-goals

- No allow-list of permitted identifiers to hand-maintain; that drifts, and it
  approximates the mechanism instead of using it.
- No runtime change ⇒ **no version bump, no publish**. The shipped artifact is
  byte-identical.

## Dependencies

None.

## Reuse

Raised by a consumer reading our built output rather than our source — worth
recording as its own lesson: cardmem verified the property in `dist/index.js`,
not in `src`, which is the only place the serialisation constraint is real.

## Rollout

1. Add the seal; prove it red with an offending variant.
2. `pnpm test` + `pnpm typecheck` green.
3. Commit. No publish.
