# F095.4 — sso 0.10.1: the README tells the truth about refresh tokens

> Story under F095 · docs-only patch · S

## Summary
sso 0.10.0's README and the fleet announcement said that Broberg ID issues no refresh token, so the account page would need a new login every hour. Since 6/10 BID does issue one, for apps registered and logging in with `offline_access`. This patch corrects the README and retracts the stale line, so no app builds around a limit that is gone.

## Motivation
broberg-id #1896 (6/10): F084.156 is live (634e76b). The refresh token rotates, and it dies with the user's BID sign-in (400 invalid_grant on logout, «log ud overalt», a new password or expiry). A note that was correct when written has become wrong, and only we can correct it (CLAUDE.md: tell them when a release makes an existing note WRONG).

## Solution
Rewrite the README paragraph: offline_access goes in the registration and in SSO_SCOPES, renewal is automatic, it ends with the BID sign-in, and per-process single-flight means a multi-machine race costs one «Log ind igen». Bump to 0.10.1, publish, and broadcast the correction.
