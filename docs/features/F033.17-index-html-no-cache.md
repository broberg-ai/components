# F033.17 — Hvid skærm efter udrulning: index.html må aldrig caches

**Meldt af:** Christian 26/10 2026 (HelpDesk-PWA'en starter hvid efter hver udrulning; kun Cmd+R hjælper), målt og videregivet af helpdesk #4942. Ejer-meldt fejl → kort og rettelse i samme tur (F180.6).

## Årsag (målt af helpdesk)
Fly Live-serveren i @broberg/deploy-core sender filer uden Cache-Control. Browseren må derfor selv gætte hvor længe index.html er frisk (heuristisk caching). Efter en udrulning er de gamle /assets/main-<hash>.js væk (404), men den cachede index.html peger stadig på dem → hverken JS eller CSS indlæses → hvid skærm.

## Rettelse
- Alle HTML-svar (index.html, SPA-fallback, *.html, 404.html): `Cache-Control: no-cache` — browseren må gemme siden, men skal spørge serveren hver gang.
- Hashede filer under /assets/ (fx `main-AbC123xy.js`): `Cache-Control: public, max-age=31536000, immutable` — navnet skifter når indholdet skifter.
- Alt andet: uændret.

## Non-goals
- Service worker-logik (@broberg/pwa). helpdesk lægger en lokal genindlæs-vagt; hvis den skal være fælles, er det sit eget kort.
- At beholde gamle assets efter udrulning.

## Reuse
Udvider @broberg/deploy-core (F033). Ingen ny pakke.

## Rollout
Patch/minor af deploy-core. Virker først hos en app, når den udrulles igen med den nye version — release-rapporten siger det, og helpdesk måler med curl -I.
