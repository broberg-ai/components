# F081.1 — The restore nobody checked

**Status:** In progress · **Epic:** F081 · **Written:** 2026-09-01

---

## What happened

Mid-way through a background `pnpm test`, `git diff` showed this in
`packages/secret-scan/src/index.ts`:

```diff
-  if (opts?.valueOnly) {
+  if (false) {
```

A security branch, disabled. I spent real time treating it as a defect.

It was secret-scan's own mutation harness, mid-run. The file was restored 60
seconds later.

**Verified afterwards rather than assumed:**

| Question | Answer |
|---|---|
| Did either commit in that window capture the mutant? | **No** — `git show <sha>:packages/secret-scan/src/index.ts` shows the original in both |
| Would a commit that HAD captured it ship? | **No** — the `valueOnly` tests fail on it, so the gate goes red |
| Cost | **Time**, mine. Not a shipping risk |

## The part that is actually dangerous — buddy's, not mine

From their own script's header: `mutate-guard.sh`'s **very first run**
(2026-08-14) left the file mutated. The test command contained a `cd`, eval ran
in the same shell, the working directory moved, and the restore's **relative**
path pointed at nothing. The alarm went to **stderr** and vanished into the test
output.

**The script committed the exact error it exists to prevent, and nobody saw it,
because a failed restore attempt looked like silence.**

Same shape as everything else this week: a failure outcome that merges with
*nothing to report*.

## Measured on our own four harnesses

After buddy named it — because they named the thing I had not checked:

| | secret-scan | mail | greppable | stripe |
|---|---|---|---|---|
| source path absolute | ✓ | ✓ | ✓ (`git rev-parse --show-toplevel`) | ✓ |
| restores via `git checkout` | no | no | no | no |
| **reads the file back after restoring** | **no** | **no** | **no** | **no** |

The first two rows are good news and neither is the point.

`git checkout <file>` reads the **index**, so a file staged while mutated
"restores" *to the mutation* — silently, green. All four write a saved copy back
instead, so that trap is closed, and buddy's relative-path trap with it.

**But every restore is a `writeFileSync` / `copyFileSync` in a `finally` whose
success nobody checks.** If it fails, the result is precisely buddy's
2026-08-14. That hole is ours.

## Why a note is not enough

I broadcast a warning and **got the scope wrong twice**:

1. *"Do you have a mutation harness?"* — lets every session without one close
   the tab. **super** caught it: they read other projects' state, that is the
   whole job.
2. *"The risk is per machine."* — too broad. **buddy** caught it: a harness
   resolves its target inside its own repo, so it cannot touch another repo's
   working tree.

Two corrections on one hazard is the evidence that the fix is not a sentence.

## Design

**1 · A marker file.** Each harness writes `.mutation-running` in the repo root
**before the first mutation** and removes it in a `finally`. Written after the
first mutation, it leaves open the exact window it exists to close.

**2 · The marker explains itself.** Which harness, which file is mutated right
now, and the PID. buddy's point, and it is the one that reaches the reader:
*when they read our diff, they are in our repo*, so the file is already visible
to them — but the hook's message is not. Same filename in every repo, so the
reader's check is one stat call and needs no knowledge of who has a harness.

**3 · The pre-commit hook refuses while it exists** — naming the harness and the
command to clear a stale one. `--no-verify` is forbidden by the harness
contract, so the block itself has to carry the way out.

**4 · A read-back after every restore.** Compare the bytes on disk to the bytes
read at start; on a mismatch print to **stdout** and exit non-zero. buddy's
alarm died on stderr. **This is the more important half** — the marker shortens
a window, the read-back closes a silent failure.

## What this does NOT cover

**A reader who never looks at the marker.** It is a file, not an interrupt.
buddy read fd-sundhed's tree twice in one hour; a fleet audit touches ten repos
at once. The marker makes a mutated tree *self-explaining to whoever opens it*
— it cannot make anyone open it.

Stated rather than quietly implied. Two wrong scopes on this hazard already; a
third would be worse than none.
