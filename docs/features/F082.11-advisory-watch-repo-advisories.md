# F082.11 — advisory-watch: repository advisories as a third source

**Reported by:** bid 28/11 2026 (intercom #56991, bid-F084.252, ordered by Christian).

## The blind spot (measured)
BID ran better-auth 1.7.14; Better Auth published 12 advisories on 3/11, fixed in 1.7.16. advisory-watch v1.0.0 was green (bid run 46153527907). Both its sources — the package manager's audit and OSV.dev — read GitHub's REVIEWED advisory database. An advisory published only on the source repository (not yet reviewed; 25 days here) is in neither:
- `api.github.com/advisories/GHSA-fvxx-76fc-893x` → 404; OSV → 404; OSV query better-auth@1.7.14 → []
- `api.github.com/repos/better-auth/better-auth/security-advisories?state=published` → 200, 49 advisories (components measured 28/11), incl. GHSA-4wq4-2ppv-q3hg **critical** `< 1.7.16`.

## Design
- Third source `repo`, beside `audit` and `osv`, in the same `decide()` — so gate and watch still measure the same.
- Scope: DIRECT dependencies (root + workspace package.json files, outside node_modules). All locked packages would be hundreds of calls; direct deps are where an app owner acts, and the big frameworks (Better Auth) are direct.
- Repo: npm registry `/<pkg>/latest` → `repository` (string or {url}); GitHub only; deduplicated (a monorepo's packages share one call).
- Advisories: `GET /repos/{o}/{r}/security-advisories?state=published&per_page=100`, paginated, with the workflow's `GITHUB_TOKEN` (per-repo quota, not the owner's).
- Match: `vulnerabilities[]` with ecosystem npm, package name == a locked name, locked version inside `vulnerable_version_range` (GitHub's comparators, `, ` = AND, prereleases by SemVer precedence). Withdrawn advisories skipped.
- Merge by (pkg, GHSA id) with audit/OSV, so a later-reviewed advisory does not double.

## Honest failure
- 403/429 (rate limit) or 5xx → an error → red, closes nothing (v1.0.0's rule).
- 404 / non-GitHub repository / no repository field → `repo_unchecked` in the report and the log — not an error (a private or moved repo is common), never counted as checked.

## Tests
Pure engine: range matching on the real Better Auth ranges, repo URL parsing, findings from a recorded advisory payload, merge with OSV. End to end: a scratch repo locking better-auth@1.7.14 → red with GHSA-4wq4-2ppv-q3hg; at 1.7.16 → no Better Auth finding.

## Reuse
The engine itself (F082.10) — one more source into the same decide(). No new dependency: a small comparator instead of the `semver` package, because the engine is checked out sparse and runs without install.

## Release
Tag `advisory-watch-v1.1.0`; bid bumps `engine-ref`. v1.0.0 stays as it is for callers that pin it.
