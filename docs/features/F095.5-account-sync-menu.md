# F095.5 — The user menu follows the account page

> Story under F095 · sso 0.11.0 + app-shell 0.5.0 · S

## Summary
When a user changes her name or picture on the account page, the user menu at the top of the app shows the change straight away and after a reload, without a new login. The «Gem» button is only active when there is actually something to save.

## Motivation
appkit measured both on a real BID login (6/10, #1944/#1945). (1) The menu kept the old name and initials, because it reads the session cookie and nothing told the host or updated the cookie. That blocks appkit-F004.3, whose criterion is «the top bar shows the new name and picture without a new login». (2) A fresh load showed «Gem» enabled for an unchanged name (Lens cd4cd122 step 3).

## Solution
Two halves, so both «at once» and «after reload» hold:
- **sso:** `ssoRoutes` gains `refreshSessionProfile(c, {name, picture})`. accountRoutes calls it with BID's answer on every successful call (GET included, so a change made in BID itself also lands). It re-signs the session cookie with only the convenience copies changed: sub, sid, iat and exp are kept, Max-Age is the remaining lifetime, and nothing is written when nothing changed.
- **app-shell:** `AccountPage` gains `onProfileChange(profile)`, called with the server's answer after a save, an upload or a removal. The host passes it to `AppShell`'s user. «Gem» is disabled while the trimmed name equals the server's.

## Reuse
None new. Extends @broberg/sso and @broberg/app-shell themselves.

## Design
No new surface. The disabled state of «Gem» uses the existing `.bas-account__btn.is-primary:disabled` rule.

## Scope
### In scope
- packages/sso/src/hono.ts (`refreshSessionProfile`, accountRoutes `answer`), tests, README.
- packages/app-shell/src/preact.tsx (`onProfileChange`, `unchanged`), tests, README.
### Out of scope
- Avatar cropping. BID does not crop and we do not plan it. appkit-F004.3's AC mentions «upload + beskæring», and keeping or dropping that is Christian's call.
- Pushing the change to OTHER apps the user is logged into. They show the new name at their next login or account-page visit.

## Acceptance criteria
1. accountRoutes re-signs the cookie after a successful write; sub/sid/iat/exp unchanged; Max-Age = remaining; no Set-Cookie when unchanged or refused. Measured in vitest on the raw Set-Cookie, mutation-checked.
2. onProfileChange gets the server's answer after save, upload and remove; never on load or failure. Measured in vitest on the rendered page, mutation-checked.
3. «Gem» is disabled for an unchanged (trimmed) name. Measured in vitest.
4. In appkit-lean-demo with a real BID login, the menu shows the new name at once and after a reload. Measured by appkit's Lens on the deployed build, because only the live build can see the host's wiring.

## Rollout
Additive: a new optional prop and a new optional input field. An older host without `onProfileChange` still gets the cookie refresh, so it is right after a reload.
