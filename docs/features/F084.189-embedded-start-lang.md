# F084.189 — sso.embedded.start sends the customer's language

**Reported by:** vnlekerv2 #55390 (26/11 2026), F008.20 — moving the shop's embedded login to @broberg/sso on the owner's order «alt skal køre på BID nu».

## Why
BID's `POST /embedded/start` accepts `lang: "da" | "en"` (broberg-id `src/embedded-login.ts:385`) and uses it for the code mail when the address is not yet a BID user (a known user gets the language saved on their account, line 486). `@broberg/sso` 0.27.1 never sends it, so a new English-speaking customer gets the code mail in Danish. vnlekerv2 sends `lang` in its own fetch today: switching to the package would be a step back.

## Scope
- `EmbeddedStartInput.lang?: "da" | "en"` → `body.lang`.
- Omitted: no field, the request is byte-for-byte the 0.27.1 request.
- Anything else: refused before the call (TypeError) — never sent as an unknown value BID would silently treat as Danish.

## Non-goals
- `lang` on the passkey frame (`/embedded/passkey/start` also takes one, line 778) — its own card if a consumer asks.
- A server-side passkey frame variant (vnlekerv2 asked; answered #55389: the browser module already runs the ceremony in BID's frame).

## Reuse
Extends `@broberg/sso` (F084). No new dependency.

## Rollout
Minor (0.28.0). Release report to broberg-id and every known consumer BEFORE anyone is asked to upgrade (D-4d0783), then vnlekerv2 migrates.
