# F111.5 — @broberg/s3: putObject kan gemme bytes

## Hvorfor
vnlekerv2 (#50820, 17/11 2026) formindsker varebilleder server-side med `@broberg/media-transform` (→ WebP) og vil gemme derivatet i R2 (`products/w480/x.webp`). `putObject` i 0.2.2 tager kun `body: string` (målt: `src/server.ts:94`), så et billede kan ikke skrives. I mellemtiden formindsker de ved hvert kald (F007.15, a67af9c) — virker, men koster CPU på hver visning.

## Scope
- `putObject({ key, body: string | Uint8Array, contentType? })`.
- SigV4 skal hashe de rå bytes (ikke en tekst-konvertering), og Content-Length skal være byte-længden.
- `string` forbliver byte-identisk med 0.2.2.

## Non-goals
- Streams / meget store filer — dem tager multipart-upload-delen allerede.
- En `getBytes` — tages hvis nogen beder om den.

## Prioritet
Ikke hastende («later» er fint fra vnlekerv2) og ikke prioriteret af ejeren. Ligger i Backlog.

## Rollout
Minor → rapport til vnlekerv2, drive, fysio.work (D-b7eb14) → live-måling mod R2 EU.

## Reuse
Udvidelse af eksisterende `@broberg/s3` (F111).
