# F038.8 — The syntax check that caught a broken push was an accident, not a check

> Parent: [F038 — Discovery](F038-discovery-api.md). Self-filed after breaking `main` today.

## What happened

I pushed a `scripts/inventory-data.mjs` that did not parse — straight quotes inside a double-quoted `desc` field, **the exact trap recorded in my own notes**. CI went red on `f5e498d`; fixed and green again on `ad2cbbf`.

## The red was incidental

Measured: **`inventory-fresh` has no syntax check.** Its steps are the greppable guard, `bun scripts/build-inventory.mjs`, `bun scripts/build-onboarding.mjs`, then a staleness diff.

A file that cannot parse cannot regenerate — so the *regenerate* step failed, and the job went red **for a reason nobody designed**.

That is a check working by accident. It covers this case today. A refactor that made the generators tolerate a bad import, or moved the data behind a loader with a fallback, would remove the coverage **silently**, and nothing would announce it. A guard nobody chose is a guard nobody maintains.

It is also the week's shape one level out: the signal was correct, and correct for a reason other than the one a reader would assume.

## My own failure, which this card does not fix

I **ran** `node --check`. It printed a `SyntaxError`. The git commands were on the next shell line rather than chained with `&&`, so the push went out anyway — and the terminal showed `SyntaxError` and `pushed ✓` in the same output.

**A gate that runs before an unconditional push is not a gate.** No CI change fixes shell discipline. What CI *can* do is make the red **deliberate**, so the next person meets a named failure instead of a confusing generator error.

## Scope

An explicit syntax check on the Discovery single source, running **before** the regenerate step.

The ordering is the point. The coverage already existed by accident; what was missing was a red that **names its own cause**.

## Deliberate non-goal: a local pre-commit hook

It is the standard answer, and it would have caught this before the push. It also changes behaviour for every commit in the repo, and Christian did not ask for it. CI catches this within a minute, which is the right cost for the risk.

Recorded here so the omission is a **decision**, not an oversight.

## Reuse

Nothing to adopt — a workflow `components` owns, guarding a file `components` owns. The greppable guard already in this job came from [`@broberg/greppable`](F068-greppable.md); this is a second, unrelated failure mode in the same file.

## Rollout

One step added to `.github/workflows/inventory-fresh.yml`. No consumer impact.
