# F083.7 — The daily fleet scan died on a rebase of generated docs

**Epic:** F083 · **Written:** 2026-10-31 · red on main

## What happened

Scheduled run 41192689798 (31/10 10:25Z) scanned the fleet, regenerated `docs/`, committed, and then `git pull --rebase origin main` failed: `CONFLICT (content): Merge conflict in docs/llms.txt`. While it ran, the `@broberg/notifications` 0.6.0 release had bumped the roster (deba9ffc) and regenerated the same docs. Two regenerations of a generated file conflict line for line, so a rebase can never resolve them.

## Fix

The move publish.yml's roster job already makes (and `scripts/test-roster-bump-workflow.mjs` seals): keep the new `data/fleet-deps.json` aside; in a loop of up to 5 attempts, `git fetch` + `git checkout -B main origin/main`, put the scan back, regenerate `docs/` from both, commit, `git push origin main`; back off and retry if the push is rejected. Nothing to commit after regenerating → exit cleanly.

## Seal

`scripts/test-workflows-parse.mjs` fails on a fleet-deps.yml that rebases, or that does not re-fetch main and regenerate before each push attempt. Proven red on the pre-fix file.

## Non-goals

- No change to what is scanned or to the «only the timestamp moved» rule.

## Reuse

The recovery pattern is publish.yml's own; no shared package involved.
