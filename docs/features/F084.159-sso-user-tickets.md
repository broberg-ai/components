# F084.159 — createTicketVerifier godtager bruger-billetter

> Story under F084 (Broberg ID). Priority high. 2 SP. Status: backlog.

## Summary
Broberg ID kan nu udstede en billet på vegne af en BRUGER (ikke kun en maskine): en app som Trail Clipper bytter sin brugers login til en billet, der kun gælder hos ét bestemt system. Denne historie lærer @broberg/sso's billet-tjek at godtage den slags billet og fortælle modtageren både hvilken bruger og hvilken app det er.

## Motivation
broberg-id #2988 (12/10): Christian har sagt GO til bruger-billetter (BID F087.37), og BID-siden er bygget. Spec: broberg-id `docs/BILLETTER.md` §4b + `docs/features/F087.37-bruger-billetter.md`. I billetten: `sub` = brugerens id, `client_id`/`azp` = appen der byttede, `principal_type` = `"user"`, `ver` = 1. @broberg/sso 0.17.0 afviser den i dag: `PRINCIPAL_TYPES` i `packages/sso/src/ticket.ts` er `human | service | agent`, så en bruger-billet ender som `SsoError("ticket has no valid principal_type")`. Første modtager er Trail-motoren (trail-clipper → https://engine.trailmem.com, scope trail:clip).

## Solution
Tilføj `"user"` til `PrincipalType`. For en bruger-billet SKAL appen være navngivet: `clientId` = `client_id`, ellers `azp`, ellers afvist. Den eksisterende faldbagud `clientId = sub` gælder kun maskin-billetter, hvor sub og client er det samme — på en bruger-billet ville den gøre brugerens id til en app, og en modtager der kræver `clientId === "trail-clipper"` ville så kunne narres af en bruger der hedder det.

## Reuse
- `@broberg/sso` itself (extend `createTicketVerifier`, `src/ticket.ts`) — no new package.
- `jose` (already a dependency) for verification. No new dependencies.

## Design
None — no visual surface.

## Scope

### In scope
- `packages/sso/src/ticket.ts`: `PrincipalType` gains `"user"`; `TicketPrincipal` exposes `principalType` (if not already) and reads `clientId` from `client_id` → `azp` for user tickets, refusing a user ticket that names neither.
- `packages/sso/test/ticket*.test.ts`: user-ticket cases, azp fallback, refusal, unchanged machine-ticket answers.
- README section «Bruger-billetter».
- Minor release + clean install + release report.

### Out of scope
- The token-exchange call itself (the app swapping its token for a ticket) — that belongs in the clipper base (F099.5) or a later sso client helper; not this story.
- Any change to BID (broberg-id owns F087.37).
- Trail's receiver code (trail owns it).

## Architecture
```ts
export type PrincipalType = "human" | "service" | "agent" | "user";
// user ticket → { principalType: "user", principal: payload.sub, clientId: payload.client_id ?? payload.azp }  (neither → SsoError)
// machine ticket → unchanged: clientId = payload.client_id ?? payload.sub
```

## Acceptance criteria
1. A user ticket verifies to `{ principalType: "user", principal: <user id>, clientId: "trail-clipper" }` — vitest with a fake JWKS, strict equality on the whole principal object.
2. Missing client_id with azp present → clientId = azp; neither on a user ticket → SsoError; a user ticket never falls back to clientId = sub. vitest, mutation-checked.
3. Machine tickets answer unchanged — the existing ticket suite passes with no changed expectations.
4. Released as an @broberg/sso minor, clean install against 0.17.0, release report to broberg-id, trail and every known consumer (D-4d0783).
