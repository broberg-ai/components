# F082.8 — zod-sårbarheden: ud af zod 3 i de pakker der leverer den

> Story under F082. Christians sikkerhedsordre via bid/buddy 24/10 2026.

## Hvorfor
GHSA-mrhx-c7xc-m3w5: zod <4.6.6 kan læmmes med et stort array fra netværket (høj, ingen login). buddy målte at zod 3.25.76 også er ramt, og der kommer ingen 3.x-patch — eneste reelle rettelse er zod ≥4.6.6. En grænse på request-størrelse begrænser skaden, men forhindrer ikke angrebet.

## Målt i components
| pakke | zod | betyder |
|---|---|---|
| @broberg/bodymap | dependency ^3.23.8 (z.array ×2) | leverer sårbar zod til forbrugeren |
| @broberg/mail-templates | dependency ^3.23.8 (z.array ×3, z.record) | samme |
| @broberg/config | peer >=3 | forbrugerens valg |
| @broberg/mcp | peer ^3\|\|^4, dev-alias zod4@^4.4.3 | forbrugerens valg; vores test-alias er sårbar |

## Scope
1. bodymap + mail-templates → zod ^4.6.6, test + typecheck, ny minor, release-rapport med clean install og forrige version som negativ kontrol.
2. Lockfilen: mcp's alias → ^4.6.6; pnpm-override `zod@^4` → ^4.6.7, så ingen 4.x under 4.6.6 er tilbage.
3. config + mcp README: forbrugeren skal køre zod ≥4.6.6.
