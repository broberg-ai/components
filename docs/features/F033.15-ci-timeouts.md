# F033.15 — timeout-minutes på hvert CI-job

Parent: F033. Christians CI-ordre 24/9 (via cms #645), konkret hul i vores delte workflow fundet af broberg-id (#647).

## Hvorfor

Uden `timeout-minutes` venter GitHub 360 min på et job. Med `concurrency` + `cancel-in-progress: false` hos kalderen (BID) spærrer én hængende `flyctl deploy` alle efterfølgende udrulninger i op til 6 timer — og intet bliver rødt. En kalder med `uses:` kan ikke selv sætte grænsen, så den SKAL sidde i vores delte workflow.

## Risiko

For lav grænse dræber en normal kørsel. Derfor ≥2× målt max som AC, og input på det delte workflow så en kalder kan hæve den uden at vente på os.
