# F001.15 — The round-trip I documented cannot be performed through the published entry point

**Status:** Backlog
**Parent:** F001 — `@broberg/theme`
**Found by:** cardmem, 2026-08-29, measuring my sentence against the published `0.6.0` tarball

---

## The measurement

```
generateTailwindV4(tokens)      → THROWS: content.match is not a function
generateTailwindV4(serialised)  → ok, 48 declarations
exports on ./design-md          → checkContrastAA, designMdToTailwindV4,
                                  designTokensFromCss, generateTailwindV4, parseDesignMd
```

## The claim was mine and it is false

`designTokensFromCss`'s doc comment says its result

> *feeds straight back into `generateTailwindV4` without a translation step*

It does not. The exported `generateTailwindV4` takes the **markdown string**. My
own round-trip test passes because it serialises inline —
`` `---\n${JSON.stringify(tokens)}\n---\n` `` , which works only because JSON
happens to be valid YAML — and I then described that as if it were the API.

cardmem read the sentence the way a consumer would, and measured it.

**And there is no tokens → DESIGN.md serialiser exported at all**, which is the
half the actual use case needs: cardmem's seeder hand-rolls the YAML in
`buildSeed` because we do not ship one.

## What is and is not broken

Stated plainly, because the distinction is the point:

- **The code is correct.** 0.6.0 needs no patch. The round-trip property is real
  and tested.
- **A sentence is wrong**, and it sits in the one place a consumer looks for the
  call shape.

Same family as everything else this week, one level out: not a success-shaped
non-answer *in* the code, but a true-sounding claim *about* it. Second time today
a peer measured one of my sentences against a published tarball and found the
sentence wrong rather than the code.

## The trap cardmem hit while measuring, which nearly produced the opposite error

Their first probe lived in `/tmp`. **Node resolves a bare specifier from the
FILE's location, not from cwd**, so it answered from a stale hoisted copy and
reported the alias defect as *still present* — one step from filing a regression
against a version that was already fixed.

It fails **success-shaped in both directions**: the same mistake can just as
easily report *fixed* about a package that is not. Their fix — pin the installed
version in the test — is the right one, and this card's AC adopts it: the probe
prints the resolved package version it measured, so a stale copy cannot answer
silently.

## Design

- Export a **tokens → DESIGN.md** serialiser, round-tripping through **our own
  parser** rather than relying on JSON being valid YAML.
- Let `generateTailwindV4` **also** accept `DesignTokens`, additively. A markdown
  string must behave exactly as it does in 0.6.0 — asserted as a negative
  control, because widening a signature is where a quiet break lives.
- **Fix the false sentence in the same change.** The missing function is the
  reason it was tempting to write; the sentence is the defect.

## Non-goals

- No YAML formatting options, no comment preservation, no round-tripping of the
  markdown BODY. Tokens only.

## Rollout

1. Serialiser + additive overload + corrected comment, one change.
2. Full loop through published exports only, no hand-rolled YAML in the test.
3. Publish, verify from a clean install, probe run from the directory whose
   `node_modules` is under test and printing the version it measured.
4. Tell cardmem, so their `buildSeed` can drop its hand-rolled front matter.
