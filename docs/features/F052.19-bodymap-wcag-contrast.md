# F052.19 — WCAG AA contrast pass, chrome colours honour the palette

> Story under **F052 — @broberg/bodymap**. Consumer-filed defect from **fd-sundhed** (#18980).
> **Deadline-bearing:** fd-sundhed launches to Aalborg Kommune 1 September; a public authority is covered by the EU web accessibility directive, so WCAG AA is a legal requirement.

## Motivation

fd-sundhed's Lens DOM critic flagged, on their production reporting screen at iPhone-15 viewport:

```
Low contrast on "bodymap3d-empty": 2.56:1 (WCAG AA needs 4.5:1)
```

The source is `packages/bodymap/src/three.tsx:428` — `color:"#94a3b8"` on `background:"#fff"`. Re-measured here: **2.56:1**, matching their number exactly. At `fontSize: 13.5` it does not qualify for the large-text exception, so it fails however you turn it.

Why it matters in their product: the text is not decoration. It is the **only** instruction in the core interaction — *"Træk for at dreje kroppen · tryk hvor det gør ondt"*. A user who cannot read it never learns the body map rotates or responds to touch.

fd-sundhed deliberately did **not** patch locally: the styles are inline in the package, so their only local option was `!important` overrides — precisely the drift reuse-first exists to prevent. They filed it instead. They also flagged that their list covers only what they happened to measure.

**That caveat was correct.** Re-measuring every shipped colour pair found the problem is broader:

| Location | Pair | Ratio | |
|---|---|---|---|
| `three.tsx:428` empty hint | `#94a3b8` on `#fff` | **2.56** | FAIL (their finding) |
| `three.tsx:413` INTENSITET label | `#94a3b8` on `#fff` | **2.56** | FAIL |
| `three.tsx:419` KVALITET label | `#94a3b8` on `#fff` | **2.56** | FAIL |
| `three.tsx:425` remove button | `#ef4444` on `#fff` | **3.76** | FAIL |
| `three.tsx:410` region-code badge | `#64748b` on `#f1f5f9` | **4.34** | FAIL (marginal) |
| `three.tsx:422` pain-type button | `#64748b` on `#fff` | 4.76 | pass |

The same hex values also appear in **`react.tsx`** (the 2D renderer), which fd-sundhed does not use — so the 2D consumers have the identical defect unreported.

Second, deeper point (fd-sundhed's option 2, and they are right): they already pass `palette={AK_PALETTE}`, but the panel chrome ignores it and uses its own hardcoded colours. **A palette that does not cover the whole component is half a palette.**

## Scope

1. **Fix the defaults** — `#94a3b8` → `#475569` (slate-600, **7.58:1**) for muted label/hint text; `#ef4444` → `#dc2626` (red-600, **4.83:1**) for the remove action; darken the region-code badge so it clears 4.5:1 against its own `#f1f5f9` background. Applied in **both** `three.tsx` and `react.tsx`.
2. **Extend `BodymapPalette` additively** with an optional `ui` token group — `{ text?, mutedText?, panelBg?, border? }` — consumed by the panel chrome in both renderers. Omitted ⇒ the (now AA-safe) defaults.
3. **Seal it** — a contrast unit test over every shipped text/background pair that REDs the build if any default regresses below 4.5:1. This is the anti-drift guard fd-sundhed offered to write; it belongs in the package.

### Non-goals

- No change to the region taxonomy, the `bodymap/v1` wire format, or any layout/sizing.
- Not a full theming system — `ui` is four optional colour tokens, not a design-token pipeline.
- Not touching `heat`/`body`/`hover`/`selected` (those are body colours and already consumer-controlled).

## Architecture sketch

```ts
export interface BodymapPalette {
  body: string; hover: string; selected: string;
  heat: { low: string; mid: string; high: string };
  regions?: Record<string, string>;
  /** NEW — panel chrome. All optional; AA-safe defaults when omitted. */
  ui?: { text?: string; mutedText?: string; panelBg?: string; border?: string };
}

export const defaultUi = {
  text: "#1e293b", mutedText: "#475569",   // 7.58:1 on white
  panelBg: "#fff", border: "#e2e8f0",
} as const;
```

Both renderers resolve `const ui = { ...defaultUi, ...palette.ui }` once and use `ui.mutedText` where `#94a3b8` is hardcoded today. The contrast test imports `defaultUi` + the renderers' pair list, so the assertion tracks the actual shipped values rather than a copy.

## Dependencies

None. No new runtime dependency; the test needs no browser (pure luminance maths over the exported colour constants).

## Reuse

Reuse-first as intended: fd-sundhed hit a wall inside a shared package and **filed the gap rather than `!important`-ing around it**, so the fix lands once for every consumer. We extend `BodymapPalette` instead of adding a bespoke prop. Precedent: F052.14, F052.16/.17, F052.18 — all fd-sundhed-filed gaps that grew the package. No Discovery search applies (we own the package being fixed).
