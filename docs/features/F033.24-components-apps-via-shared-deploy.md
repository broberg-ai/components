# F033.24 — components' egne Fly-apps udrulles kun via det fælles workflow

> **Udløser:** målt 1/11 2026: en hånd-udrulning af broberg-legal (`flyctl deploy` lokalt, F110.16) efterlod 2 maskiner (v3 + v4) — netop den fejl F033.21–.23 beskytter mod, fordi legal intet workflow havde. Ejerens ordre samme dag: «sørg for at ALLE repos anvender samme flyctl og de andre ting» (det fælles workflow). components selv skal følge den.

## Målt
components ejer fire Fly-apps: broberg-discovery (har workflow via inventory-fresh.yml), broberg-legal, broberg-voice og broberg-voice-turn (alle hånd-udrullet).

## Rettelse
- `legal-deploy.yml`: push til apps/legal eller packages/legal/src → test (vitest i packages/legal) → fly-server-deploy (config apps/legal/fly.toml, dockerfile apps/legal/Dockerfile, ha:false, expected_machines:1, health_url /health).
- `voice-deploy.yml` og `voice-turn-deploy.yml`: push til apps/voice resp. apps/voice-turn → fly-server-deploy (working_directory = app-mappen, expected_machines:1). Ingen kodetest; workflowets egne tjek er porten.
- Concurrency pr. app, aldrig to udrulninger samtidig.

## Ikke i scope
Ændringer i LiveKit-/coturn-opsætningen.

## Reuse
Det fælles fly-server-deploy.yml.
