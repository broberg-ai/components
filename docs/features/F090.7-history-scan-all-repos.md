# F090.7 — Historik-scanning af alle cardmem-repos

**Bestilt af:** Christian 4/11 2026: «Ja, kør historik-scanningen af alle repos først». Del af «top-notch secrets security» (F090.7–F090.10).

## Hvorfor
Spærren (F090 + F090.6) stopper NYE nøgler. En flådenøgle (trail_, pa_, uk_, cfut_, fm2_ …) der blev committet før reglerne fandtes, ligger stadig i historikken — og på et offentligt repo kan alle læse den. Kun en scanning af hele historikken finder den.

## Scope
- De 55 repos der er cardmem-projekter (D-a6931b: flådens sikkerhedsarbejde dækker kun cardmem-projekter). Listen hentes fra `cardmem_list_projects` → `github_repo_full_name`, ikke hardkodet.
- `git clone --mirror` i scratchpad (alle refs), `gitleaks git --log-opts=--all --redact` mod `secret-gate/gitleaks.toml`.
- Rapport pr. repo: regel, fil, commit, dato, offentligt/privat repo, findes filen stadig på HEAD.

## Non-goals
- Selve rotationen — den sker hos ejer-repoet (det ejer nøglen). Vi melder fundet.
- Omskrivning af git-historik (force-push) — kræver Christians egen ordre pr. repo.
- Repos uden for cardmem.

## Sikkerhed
- Ingen værdi forlader maskinen: `--redact`, rapport-JSON indeholder kun `REDACTED`. Kloner slettes efter scanning.
- Klassifikation: ægte (→ rotér + intercom til ejer) / fixture / falsk alarm (→ stram regel eller `.gitleaksignore`).

## Reuse
Genbruger F090's gitleaks.toml + F090.6-reglerne. Intet nyt værktøj.

## Bevis
Rapport som artifact på kortet; repos der ikke kunne scannes står med årsag.
