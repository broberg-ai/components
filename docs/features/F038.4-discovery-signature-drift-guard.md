# F038.4 — Fix the `@broberg/http` signature in Discovery, and guard documented call-shapes

> Story under **F038 — Discovery**. Consumer-filed defect from **beacon** (#18983, repeated in #18985).

## Motivation

Discovery (`/api/search?q=http+header+response+primitives`) documents:

```
contentDisposition({ filename, type? })
```

The actual export (`packages/http/src`, line 33) is **positional**:

```ts
contentDisposition(filename: string, opts?: { disposition?: 'attachment' | 'inline' })
```

Call the documented form and you land in the package's own first line — `(filename ?? "").replace is not a function` — because the object arrives where the string belongs. The option is also named `disposition`, not `type`. Both wrong, in the one sentence a consumer reads before writing their call-site.

beacon hit it, fixed their call-site (`packages/api/src/routes/snapshots.ts`, snapshot export with `æøå` in the filename — precisely the bug the package exists for, working perfectly now), and filed the description as debt.

They were explicit, and correct, about the direction of the fix: **change the description, not the package.** The positional form is already in use and changing it would break cardmem F224.8.

Their deeper point is the one worth acting on. The fleet rule is *check Discovery before you build*. That makes the description the only thing standing between a consumer and their first call-site — so **a wrong signature there is worse than no signature at all**, because it is confidently wrong and gets copied. They asked whether the signature line could be generated from the package's `.d.ts` so it cannot drift again.

## Scope

1. **Fix the text** in `scripts/inventory-data.mjs` (the canonical single source) → rebuild → redeploy Discovery.
2. **Add a call-shape drift check.** For every `fn(…)` call-shape appearing in an inventory `desc`, resolve the owning package's built `.d.ts` and compare the **first-argument kind**: documented-object vs actual-positional, or the reverse. Report every mismatch; wire it into the discovery test run so it fails CI.

The check deliberately targets the *specific* class of error that bit beacon rather than attempting full signature equality — object-vs-positional is the mismatch that produces a runtime crash on the first call, and it is cheaply and reliably detectable. Parameter names and types inside the object are left to prose.

### Non-goals

- **Not** auto-generating the whole description from the `.d.ts`. The descriptions are curated prose that explain *why* a package exists and when to reach for it — that is their value and a generator would flatten it. We guard the one machine-checkable claim inside the prose instead.
- Not changing `@broberg/http` in any way.
- Packages whose source is not in this repo are skipped by the check (no `.d.ts` to compare against) — the script reports how many it skipped rather than silently passing.

## Architecture sketch

```
scripts/check-signature-drift.mjs
  for each DATA entry with .pkg resolvable to packages/<name>/dist/index.d.ts:
    documented = [...desc.matchAll(/\b([a-zA-Z][\w.]*)\(\s*(\{)?/g)]   // name + is-object-call
    actual     = parse `export declare function <name>(<first param>` from the .d.ts
    mismatch when documented-object !== actual-first-param-is-object
```

Run it against the **pre-fix** inventory text as a fixture: it must report `contentDisposition`. That is the proof the guard has teeth — a check that has never been shown to fail is not a check.

## Dependencies

Requires packages to be built (`dist/*.d.ts` present) before the check runs — already true in the discovery test/CI path.

## Reuse

No Discovery search applies; this fixes Discovery itself. Notable as the reuse loop closing properly: beacon read Discovery before building (the rule working), found it wrong, fixed their side, and filed the debt instead of quietly living with it. beacon also enrolled their `@broberg/http` 0.1.0 adoption themselves.

## Rollout

1. Correct the `desc` in `scripts/inventory-data.mjs`.
2. Add `scripts/check-signature-drift.mjs` + its fixture test; wire into the discovery test run.
3. `node scripts/build-inventory.mjs`; `cd apps/discovery && bun run typecheck && bun run test`.
4. Deploy to Fly (`arn`); verify the live `/api/search` returns the corrected signature.
5. Commit + push; tell beacon it is live.
