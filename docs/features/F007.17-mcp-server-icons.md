# F007.17 — serverInfo.icons + websiteUrl i @broberg/mcp

> **Udløser:** jam intercom 3742, 21/10 2026, ejer-rapporteret i jam: i claude.ai viser Jam-connectoren broberg.ai's «b.»-logo i stedet for Jam-krukken, selv om jam.broberg.ai/favicon.ico og /apple-touch-icon.png er krukken (målt 200 image/png af jam).
> **Status:** backlog — ikke bygget.

## Åbent spørgsmål (øverst, fordi det afgør om rettelsen virker)

**Hvad slår claude.ai faktisk op?** `[Guessing]` To muligheder: (a) `serverInfo.icons` fra MCP-initialize, eller (b) faviconet for det *registrerbare* domæne (broberg.ai), hvilket ville forklare «b.»-logoet. Pakkeændringen er rigtig uanset (det er en del af MCP 2025-11-25), men den løser kun jams problem i tilfælde (a). jam måler det efter udgivelsen; viser det sig at være (b), er det ikke en pakke-sag, og det skrives her.

## Hvad der bygges

- `icons?: { src: string; mimeType?: string; sizes?: string[] }[]` og `websiteUrl?: string` på options for `createHttpMcpHandler` og stdio-fabrikken.
- Feltet videregives i `serverInfo` til SDK'ets `Server` (`{ name, version, icons, websiteUrl }`). SDK'et i pakken kender allerede felterne.
- Én fælles type for de to fabrikker.

## Non-goals

- Ingen hosting af ikoner i pakken; `src` er appens egen URL.
- Ingen favicon-håndtering på domæneniveau.

## Test

En rigtig `initialize`-request mod handleren; `serverInfo` sammenlignes strict. Negativ kontrol: uden felterne er `serverInfo` præcis `{ name, version }`. Mutation: drop felterne → rød.

## Rollout

Minor-version af `@broberg/mcp`, release-rapport til jam; jam sætter `icons` til krukken og måler i claude.ai.

## Reuse

Hører i `@broberg/mcp` (ejer MCP-server-fladen). Ingen ny afhængighed.
