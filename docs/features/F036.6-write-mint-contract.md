# F036.6 — write access only when asked for, explicitly

## Why

helpdesk (intercom #1449, helpdesk F052.34, Christian's order): Lens must play the receptionist and WRITE in live chat. cardmem's standard (their D-b20c50 + D-d720ac): the mint door gives a READ principal by default; a WRITE principal only when the body is `{mode:"write", writes:true}` (both keys; a bare `{mode:"write"}` is 400), and every write mint is audited. @broberg/lens 0.1.3 never reads the body, so a consumer has to hand-roll this part, in the one package whose whole job is minting sessions safely.

## Contract

| body | result |
|---|---|
| none / empty / `{}` / `{mode:"read"}` | read principal (0.1.3 behaviour, unchanged) |
| `{mode:"write", writes:true}` | write principal, IF the app enabled writes |
| `{mode:"write"}` · `{writes:true}` · unknown mode · non-object · bad JSON | 400, nothing minted |
| write request, app has no `writePrincipal` | 403, nothing minted |

Why both keys: a single field is one typo or one default away from write access. Two independent keys mean asking for writes is never an accident.

## Options

- `writePrincipal?: string`: a SEPARATE identity for writes. Never blank, never cb@webhouse.dk, never the same as the read principal (one identity for both would make the audit unable to tell them apart).
- `onWriteMint?: (e: {principal, host, expiresAt, at}) => void | Promise<void>`: REQUIRED when `writePrincipal` is set. Called after `createSession` and BEFORE cookies are returned. If it throws, the response is 500 and no cookies leave: an unaudited write session is never handed out. (The minted session row expires with the TTL, max 10 min.)
- `ctx.mode: "read" | "write"` is passed to `createSession` so the app can mint different roles.

## Adapters

`/next` and `/hono` read the body as text and JSON-parse it (empty → none). The core validates it, so the two cannot disagree.

## Release

0.2.0 (minor). Read path unchanged; the daemon sends no body today and keeps getting read sessions.

## Reuse

This IS the shared mint package (F036). Contract per cardmem's standard; cardmem owns the spec (docs/LENS-MINT-ENDPOINT.md).
