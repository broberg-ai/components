# F078.3 — Tier-1 client collector, behind consent

> Story under **F078 — @broberg/device-stats**. Follows F078.1 (`5a5c3c8`) and F078.2 (`949ea20`).

## The property this story is really about

> **"We read the device and discarded it" and "we never read the device" produce IDENTICAL output.**

Only the first is a legal problem. ePrivacy art. 5(3) prohibits the **access**, not the retention — so a gate that reads first and throws the result away is non-compliant while looking perfect from the outside. No assertion on the return value can tell the two apart.

So the gate is proven by **spying on the accessors themselves** and asserting **zero touches**.

And the spy has to work in both directions. A test that only checks "zero reads when consent is absent" passes just as well on a collector that never reads anything at all, ever — so the same spies must record **non-zero** reads when consent IS granted. Otherwise the test is green for the wrong reason.

This is the week's recurring failure shape pointed the other way. Every other instance was *a guard that reported success because it never ran*; here the requirement is that **the read** never runs, and the proof needs the same discipline.

## What Tier 1 actually buys

Tier 0 must answer `unknown` for the OS version on modern Chromium, because UA Reduction pins it — `Android 10; K` on every device in the world, whatever it runs.

`navigator.userAgentData.getHighEntropyValues(['platformVersion'])` returns the real one.

That is exactly the trade the README already promises: *the real version costs you a consent prompt — an honest trade, made visible.* This story is where that sentence becomes true, and AC#2 asserts the two tiers side by side on the same UA so the difference is demonstrated rather than claimed.

## Reuse

`@broberg/consent-cookie` 0.1.0 is shipped and owns the consent record — categories, `policyVersion`, `has()`, `subscribe()`, `withdraw()`. Its API was **measured before designing against it**, not assumed.

This package uses exactly one method: `has(category)`. Taken **structurally**, per the F008.8 lesson already applied in F078.2 — so a consumer with their own consent system passes their own object and is never forced to install ours. Tests prove both paths give identical results, one with a hand-made object and one with a **real** `createConsentManager()`.

## Shape

```ts
import { collectDeviceDetail } from "@broberg/device-stats/client";

const detail = await collectDeviceDetail({ consent });   // { has(category): boolean }
// null when consent is absent — and nothing was read
// {
//   displayMode:    "standalone" | "browser" | "unknown",
//   viewportBucket: "361-768",
//   screenBucket:   "769-1024",
//   dprBucket:      "3x",
//   os: { family: "Android", majorVersion: 14 },   // the REAL one
// }
```

Async because `getHighEntropyValues` is.

## Degrades, never throws

Older Safari has no `navigator.userAgentData`. With consent granted but the API missing, the call still resolves and returns the viewport/screen/display-mode facts it **could** read, with `os.majorVersion: "unknown"`.

Each read is guarded individually: one missing API must not cost the other four facts. A collector that throws on an old browser is a collector that silently under-reports exactly the population you most wanted to measure.

## Non-goals

- **No sending.** This story collects; the sink is F078.4.
- No new runtime dependency, no network call.
- No identifier, no hash, no sessionisation — unchanged from the core.
- **No publish.**
