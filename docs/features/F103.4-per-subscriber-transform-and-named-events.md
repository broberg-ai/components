# F103.4 — transform pr. abonnent og navngivne events i @broberg/realtime

## Hvorfor
helpdesk (#4574, #4582, 25/10) vil erstatte sin poll-baserede chat-strøm med `@broberg/realtime`, men to ting mangler:
- **Filtrering pr. abonnent.** En besøgende må kun se synlige beskeder, og bilag afhænger af hendes klients meldte evne; konsollen på samme sag ser alt. Med 0.1.3 er eneste vej én kanal pr. kombination, og det skalerer ikke.
- **Navngivne events.** Deres ramme er `event: klar|message|state|typing` + `data:`, og en ekstern klient (cms' consumeSSE) læser den form. 0.1.3 skriver altid `data: {type,data}`.

## Scope
`stream(channel, { lastEventId, signal, transform?, named? })`:
- `transform(event) => event | null` pr. abonnent, på både live og replay; `null` = spring over.
- `named: true` → `event: <type>\ndata: <JSON af data>\n` (+ `id:`).
- Klienten `connect()` får `named` så den kan læse samme form.
Uden options: byte-identisk med 0.1.3.

### Non-goals
- Autorisation (hvem der må abonnere) — det er værtens rute.
- At gemme pr.-abonnent-tilstand i pakken; transform er en ren funktion værten lukker over.

## Fælder (testes)
1. Replay skal også gå gennem transform, ellers lækker genoptagelse det live-stien skjuler.
2. Et filtreret varigt id må ikke ødelægge genoptagelse.
3. `$ping` og presence kan ikke filtreres væk.

## Reuse
Dette ER flådens realtime-pakke (F103); udvidelsen lander her frem for i helpdesk.

## Rollout
Minor (0.2.0), additiv. Release-rapport til helpdesk og jam.
