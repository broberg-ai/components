# F084.160 — introspectToken without a client secret is a config error

> Story under F084. Priority high. 1 SP. Ships with F084.159 in @broberg/sso 0.18.0.

## Summary
When an app that has no client secret asks Broberg ID whether a login is valid, @broberg/sso 0.17.0 answers «BID is down, try again». That is wrong: the problem is the app's setup and it never goes away, so a caller following the F099 contract would retry forever. This story makes it a setup error, raised before any call to BID.

## Motivation
trail #2994 (12/10), measured in production on trail-admin de0eddd with an invalid token: `SsoIntrospectionUnavailableError`, status null, «introspection needs this app's client secret (SSO_CLIENT_SECRET) — a public client cannot introspect». The BID call was never made, because Trail's BID client is public. Under the F099 contract Unavailable means 503 → retry with backoff, so the class sends callers down the retry path for a permanent fault. 0.17.0 chose it on purpose (test «a public client (no secret) cannot introspect — unavailable, not inactive»): «not inactive» was right, «unavailable» was the wrong alternative.

## Solution
At the top of `introspectToken` in `packages/sso/src/client.ts`, before the cache and discovery: no `config.clientSecret` → throw `SsoConfigError` (already exported from `src/config.ts`). Not at `createSsoClient`: public clients construct a client to log in and never introspect; failing construction would break them.

## Reuse
- `SsoConfigError` already exists in @broberg/sso and is exported — no new class.

## Architecture
```ts
if (!config.clientSecret) throw new SsoConfigError("introspection needs this app's client secret (SSO_CLIENT_SECRET) — a public client cannot introspect");
```
Caller: SsoConfigError → 500 + alarm, never retry.
