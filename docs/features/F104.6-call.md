# F104.6 — `@broberg/voice` bliver `@broberg/call` (og F104.7–.9: video, skærmdeling, servermåling, optagelse)

> **Ordre:** ejeren 1/11 2026, ordret: «Skift til @broberg/call og medtag video og skærmdeling». Optagelse: ejeren spurgte om samme pakke eller `/record`; svaret er samme pakke (se F104.9), men optagelsens INFRASTRUKTUR kræver eget GO.
> **Udløser:** jam intercom #5639 (jam-F029: Voice Jam får skærmdeling → kamera → optagelse).
> **Ændrer F104:** F104-voice.md havde «Ikke i scope: video, skærmdeling, optagelse». Ejeren har nu flyttet video + skærmdeling IND.

## Hvorfor én pakke, ikke to
Et videoopkald er det samme opkald med flere spor: samme LiveKit-server (voice.broberg.ai), samme billet (JWT bundet til ét rum), samme webhook, samme forbindelse. En separat video-pakke ville enten duplikere billet/webhook-koden eller kræve to forbindelser til samme rum. Navnet `voice` passer ikke længere → `call`. Billigst nu, hvor jam er eneste forbruger.

## F104.6 — omdøbning (denne fil)
- `git mv packages/voice packages/call`, navn `@broberg/call`, version 0.1.0, API uændret.
- Første udgivelse af et nyt navn kan ikke gå via OIDC → bootstrap lokalt (`npm publish --access public`, OTP via ARS), derefter Trusted Publisher (`npx npm@12 trust github …`) og job i publish.yml (tag `call-v<ver>`).
- **Ingen nøgen overgang:** `@broberg/voice` står urørt på npm til jam har migreret; derefter `npm deprecate @broberg/voice "moved to @broberg/call"`.
- Discovery-roster + release-rapport til jam.

## F104.7 — video + skærmdeling i `@broberg/call` 0.2.0
- **Server:** `createRoomToken({ …, sources })` hvor `sources` ⊆ `microphone | camera | screen_share | screen_share_audio`. Default forbliver `['microphone']` — en app der ikke beder om video får stadig en ren lyd-billet. `canPublish:false` (lytter) lukker fortsat for ALT.
- **Klient:** `setCamera(on, {deviceId?})`, `setScreenShare(on)` (getDisplayMedia via LiveKit), og når brugeren stopper delingen med browserens egen knap, opdateres tilstanden + hændelse udsendes. Deltagernes video- og skærmspor eksponeres med `attach(el)`, plus hændelser `trackAdded/trackRemoved` pr. deltager og kilde.
- **2–10 personer:** simulcast på kamera, `adaptiveStream` + `dynacast` slået til (klienten henter kun den opløsning der vises; serveren stopper lag ingen ser). `audioOnly`-tilstand: slå indgående video fra på svag forbindelse.
- Kun lyd-forbrugere mærker ingen forskel (test).

## F104.8 — måling af serveren med video
Serveren (`broberg-voice`, Fly arn, shared-cpu-2x / 2 GB) er dimensioneret til lyd. Video er groft 10–50× mere trafik `[Likely, ikke målt]`. Måling: 2, 5 og 10 deltagere med kamera + én skærmdeling i 15 min: CPU, RAM, udgående trafik, frys/fald i kvalitet; samt trafikpris pr. time. Resultatet afleveres til ejeren som tal + anbefalet maskinstørrelse. **Ændring af maskinstørrelse / ny pris kræver ejerens eget GO** — målingen gør det ikke selv.

## F104.9 — optagelse (Backlog, kræver GO)
- **Pakke (samme pakke):** server: `startRecording(room, {target})` / `stopRecording(id)` via LiveKits Egress-API med appens egen nøgle; webhook-hændelser `egress_started/egress_ended` dækkes af den eksisterende `verifyWebhook`. Klient: `recording`-tilstand så alle deltagere SER at der optages (krav, ikke pynt).
- **Infrastruktur (det dyre):** LiveKit Egress er en separat tjeneste (headless Chrome, ~4 CPU pr. samtidig optagelse) + Redis delt med LiveKit-serveren. Lagring i R2 med EU-jurisdiktion (D-2287db). Ny Fly-app i arn, ny månedspris → ejerens GO før noget oprettes.
- Samtykke/oplysning om optagelse er appens (jams) ansvar; pakken leverer tilstanden.

## Ikke i scope
Transskription af optagelser, opkald til telefonnumre, isolation pr. app (genovervejes ved app nr. 2, jf. F104).

## Reuse
Discovery tjekket: `@broberg/voice` er den eksisterende primitiv — den udvides og omdøbes. Ingen anden pakke dækker WebRTC/SFU.

## Rollout
F104.6 (0.1.0, rent navn) → jam migrerer → F104.7 (0.2.0, video+skærm) → F104.8 måling → ejer-GO på maskinstørrelse → jam tænder skærmdeling, derefter kamera → F104.9 når ejeren giver GO til Egress.
