# F084.29 — de fire sociale logins mangler kun registreringerne

**Status:** Ready · **Epic:** F084 (Broberg ID) · **Skrevet:** 2026-09-17

## Motivation

Koden understøtter alle fem udbydere. Kun Google er tændt.

```
UDBYDERE = ["google", "microsoft", "github", "apple", "linkedin"]   src/socials.ts
live i dag: data-providers="google"
```

Der mangler **ingen kode**. `socials.ts` tænder en udbyder hvis og kun hvis begge
dens hemmeligheder findes — halvt konfigureret er slukket, ikke en knap der
fejler når nogen trykker. Det der mangler, er fire registreringer i fire fremmede
konsoller, og dem kan kun Christian lave: de kræver hans konti hos Microsoft,
GitHub, Apple og LinkedIn.

Kortet findes fordi den viden ellers kun lever i en samtale. Hver udbyder har
præcis én adresse der skal skrives af, og præcis to værdier der kommer retur —
og Apple har en fælde de tre andre ikke har.

## Reuse

Discovery-tjek kørt 17. sep.: `GET discovery.broberg.ai/api/search?q=social login provider`
→ **`@broberg/auth` 0.6.2** (F008, L1 Identity, shipped) dækker netop dette og er
allerede i brug: BID bygger sin auth gennem den, og `pruneSocials` dér gør samme
oprydning som `tændteUdbydere()` her.

**Genbrug, ikke byg.** Der skrives ingen ny OAuth-kode i dette kort. Den eneste
kode der overhovedet kan blive tale om, er Apples secret-generator (se nedenfor),
og hvis den bliver bygget, hører den hjemme i `@broberg/auth` så hele flåden får
den — ikke i BID.

## De fire adresser

Callback-adressen er **målt, ikke gættet** (`better-auth/dist/oauth2/utils.mjs:29`
+ basePath `"/"` i BID's `auth.ts`), og udbyder-id'et er læst af bibliotekets egen
registrering:

| Udbyder | Redirect-adresse | Hemmeligheder |
|---|---|---|
| Microsoft | `https://id.broberg.ai/callback/microsoft` | `MICROSOFT_CLIENT_ID` + `MICROSOFT_CLIENT_SECRET` |
| GitHub | `https://id.broberg.ai/callback/github` | `GITHUB_CLIENT_ID` + `GITHUB_CLIENT_SECRET` |
| Apple | `https://id.broberg.ai/callback/apple` | `APPLE_CLIENT_ID` + `APPLE_CLIENT_SECRET` |
| LinkedIn | `https://id.broberg.ai/callback/linkedin` | `LINKEDIN_CLIENT_ID` + `LINKEDIN_CLIENT_SECRET` |

**MICROSOFT HEDDER `microsoft`, ikke `microsoft-entra-id`.** Filen i biblioteket
hedder `microsoft-entra-id.ts`, men den registrerer sig som
`id: "microsoft"` (`@better-auth/core/src/social-providers/microsoft-entra-id.ts:188`).
Målt netop fordi filnavnet er dét en velmenende læser senere ville "rette" efter
— og en forkert redirect fejler EFTER at brugeren har sagt ja hos Microsoft,
altså den dyreste slags fejl, fordi den ser ud som om det er os der er i stykker.

## Hvad der skal gøres hvert sted

### Microsoft — `https://entra.microsoft.com` → App registrations

1. **New registration**. Navn: `Broberg ID`.
2. **Supported account types**: vælg den der dækker BÅDE arbejdskonti og
   personlige Microsoft-konti, hvis private konti skal kunne logge ind.
   Vælges "kun min organisation", kan kun webhouse-konti bruge knappen.
3. **Redirect URI** → platform **Web** → `https://id.broberg.ai/callback/microsoft`
4. Gem. **Application (client) ID** på oversigten = `MICROSOFT_CLIENT_ID`.
5. **Certificates & secrets** → **New client secret** → vælg længste udløb.
   Værdien vises ÉN gang = `MICROSOFT_CLIENT_SECRET`.
   ⚠️ Kopiér **Value**, ikke **Secret ID** — de står ved siden af hinanden.
6. Noter udløbsdatoen. Microsoft-secrets udløber også.

### GitHub — `https://github.com/organizations/broberg-ai/settings/applications`

Vælg **organisationen**, ikke din personlige konto — ellers hænger login på ét
menneskes konto.

1. **New OAuth App**.
2. Application name: `Broberg ID` · Homepage URL: `https://id.broberg.ai`
3. **Authorization callback URL**: `https://id.broberg.ai/callback/github`
4. Gem. **Client ID** = `GITHUB_CLIENT_ID`.
5. **Generate a new client secret** → vises ÉN gang = `GITHUB_CLIENT_SECRET`.

### Apple — `https://developer.apple.com/account` (den besværlige)

**APPLE ER IKKE «TO VÆRDIER DU KOPIERER».** Målt i bibliotekets kode
(`@better-auth/core/src/social-providers/apple.ts`): det tager `clientSecret` som
en færdig streng og **genererer den ikke**. Apples client secret ER en JWT man
selv skal signere med en `.p8`-nøgle, og Apple tillader den højst ~6 måneder.
Så Apple kræver et lille værktøj plus en påmindelse, ikke en indsætning.

1. **Identifiers** → **App IDs** → dit App ID → slå **Sign in with Apple** til.
2. **Identifiers** → **Services IDs** → ny. Denne identifier ER `APPLE_CLIENT_ID`
   (fx `ai.broberg.id`). Ikke App ID'et — det er den hyppigste forveksling.
3. På Services ID'et → **Configure** → domæne `id.broberg.ai`, Return URL
   `https://id.broberg.ai/callback/apple`. Apple kræver https og verificerer domænet.
4. **Keys** → ny nøgle med **Sign in with Apple** → hent `.p8`-filen.
   **Den kan kun hentes ÉN gang.** Noter Key ID og Team ID.
5. `.p8`-filen, Key ID og Team ID lægges i **cardmems Secrets Vault** — ikke kun
   på Macen. En nøgle der kun findes ét sted er væk ved næste maskine.
6. Derefter skal JWT'en genereres. Det er cc-arbejde, ikke dit.

**Fornyelsen er den egentlige opgave.** En hemmelighed der udløber om et halvt år
uden at nogen har sat en påmindelse, er et login der går ned en tilfældig dag —
og med BID går det ned for alle apps på én gang. Fornyelsen skal derfor
automatiseres (fx som et job på `cronjobs.webhouse.net`) eller som minimum stå i
kalenderen, og det hører til dette kort.

### LinkedIn — `https://www.linkedin.com/developers/apps`

Kræver en LinkedIn **Company Page** at hænge app'en på.

1. **Create app** → knyt til WebHouse' side.
2. Fanen **Auth** → **Authorized redirect URLs** → `https://id.broberg.ai/callback/linkedin`
3. Fanen **Products** → anmod om **«Sign In with LinkedIn using OpenID Connect»**.
   Uden det produkt virker knappen ikke — og godkendelsen kan tage et stykke tid,
   så start DEN ansøgning først og lav de tre andre mens du venter.
   Bibliotekets scopes er `profile`, `email`, `openid`
   (`@better-auth/core/src/social-providers/linkedin.ts:45`), altså netop det produkt.
4. Fanen **Auth** → Client ID = `LINKEDIN_CLIENT_ID`, Client Secret = `LINKEDIN_CLIENT_SECRET`.

## Sådan afleverer du værdierne

**Værdierne må ALDRIG gå gennem chat, intercom eller en kommandolinje.**
Skriv dem i en fil — fx `~/bid-secrets.env`, én pr. linje:

```
MICROSOFT_CLIENT_ID=…
MICROSOFT_CLIENT_SECRET=…
GITHUB_CLIENT_ID=…
GITHUB_CLIENT_SECRET=…
```

Sig så til. cc tager dem med `flyctl secrets import` over stdin (aldrig
`secrets set KEY=værdi`, som ville lægge dem i skallens historik) og lægger dem
samtidig i Secrets Vault, så de overlever denne maskine.

**Én udbyder ad gangen er helt fint.** Har du kun GitHub i dag, tændes GitHub i
dag — `tændteUdbydere()` viser præcis dem der er fuldt konfigureret.

## Acceptance criteria

Se kortet. Kort fortalt: hver tændt udbyder skal kunne føre et ægte menneske hele
vejen ind i en browser — ikke kun vise en knap.

## Non-goals

- Ingen ny OAuth-kode. Findes i `@broberg/auth` og i BID's `socials.ts`.
- Facebook. `@broberg/auth` understøtter den; BID's liste gør ikke, og der er
  ikke bedt om den.
- Tenant-udrulninger (id.fdaalborg.dk m.fl.) skal have deres EGNE registreringer
  hos alle fem — redirect-adresser er pr. domæne, og samtykkeskærmen viser
  udbyderens eget app-navn, så en kunde kan ikke låne broberg.ai's. Det er
  F084.12's regning, ikke denne.

## Afhængigheder

Ingen i koden. Kortet er blokeret på Christians adgang til fire fremmede konsoller.
