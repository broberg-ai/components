# F084.190 — the passkey frame speaks the customer's language

**Reported by:** vnlekerv2 #55455 (26/11 2026), F008.20 — the last blocker before the shop's passkey login moves to `@broberg/sso/embedded-passkey`.

## Why
BID's `POST /embedded/passkey/start` accepts `lang` (BCP-47, ≤35 chars, BID F084.247) and appends it to `frame_url` itself (broberg-id `src/embedded-login.ts:778`, `:806`); the frame renders Danish for a `da…` tag, otherwise English. `loginWithEmbeddedPasskey` in 0.28.0 never sends `lang`, so a Norwegian or Swedish customer gets a Danish button. vnlekerv2's own path sends it today.

## Scope
- `EmbeddedPasskeyOptions.lang?: string` — a BCP-47 tag (`^[A-Za-z]{2,8}(-[A-Za-z0-9]{1,8})*$`, ≤35 chars) → `body.lang` on `/embedded/passkey/start`.
- The package does NOT edit `frame_url`: BID owns the address and already carries `lang` on it.
- Omitted: no field; the request is the 0.28.0 request.
- Invalid: `TypeError` before any fetch (same rule as `embedded.start`, F084.189).

## Answered, not built
- `cancelled` rejects the promise by design (the function always settles). A retry is a NEW flow: `begin()` on the server + `loginWithEmbeddedPasskey` again. A flow id is single-use at BID, so re-using one is not offered.

## Reuse
Extends `@broberg/sso` (F084). No new dependency.

## Rollout
Minor (0.29.0); release report to broberg-id and every known consumer (D-4d0783).
