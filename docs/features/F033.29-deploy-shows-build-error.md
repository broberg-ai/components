# F033.29 — En fejlet udrulning viser selve byggefejlen

## Motivation
sanneandersen (#49600, 11/11 2026): det fælles `fly-server-deploy.yml` fejlede to gange på en uge i trinnet «Deploy (flyctl --remote-only)» (runs 42213736860 og 42938726227). Begge gange byggede samme commit grønt lokalt, og en ren rerun gik grøn. Det eneste, der kunne læses, var:

```
#19 28.26 > Build failed because of webpack errors
#19 28.46  ELIFECYCLE  Command failed with exit code 1.
+ RC=1
```

Workflowet sender hele flyctl-output videre, så den fulde log ligger i GitHub. Men sessionerne læser fejl gennem `cardmem_ci_log`, som kun tager fejl-mønstre med, og de linjer, der faktisk siger hvad webpack fejlede på, står før og matcher ingen af dem. Ingen kan derfor se, om det er Google Fonts-hentning, hukommelse på builderen eller noget tredje.

## Rettelse
Ved RC≠0 finder trinnet den første fejl-markør i sit eget output og skriver op til 40 linjer foran den:
- som `::group::Build output before the failure` (læsbart i GitHub),
- som `::error::`-linjer (så de kommer med i ethvert fejl-udtræk, også cardmems),
- i `GITHUB_STEP_SUMMARY`.
Begge deploy-stier skriver til en log-fil, så det gælder også uden `--only-machines`. Exit-koden er uændret.

## Non-goals
- Rette sanneandersens byggefejl — den er ukendt, til den kan ses.
- Gentage udrulningen automatisk ved byggefejl (en rerun skjuler en fejl, der skal ses).

## Reuse
Rettelse i components' fælles workflow. cardmem får besked om, at `ci_log` ikke viser kontekst før en fejl-markør — det er deres værktøj.

## Rollout
Main (forbrugerne bruger `@main`). Rapport til forbrugerne. Live-bevis ved næste fejlede bygning.
