# F035.10 — the hue pattern matches npm checksums

> Reported by **trail**, 2026-08-27, with the measurement. Reproduced here before accepting it.

## The defect

`hue-application-key` in 0.5.0 is a bare 40-character mixed-case entropy match with no anchor. Base64 is mixed-case alphanumeric, so it fires inside npm integrity digests.

Measured on **components' own `pnpm-lock.yaml`**: **33 matches, 32 of them `sha512-…` digests.**

```
resolution: {integrity: sha512-ABkD1WhyfPZprKRQI3bhATjeiFuNWC9PXhfGWqL+sg/…}
                                ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ matched
```

`-` is in the character class but is not a word character, so `\b` anchors happily *inside* a digest at the `sha512-` hyphen.

## Why this is worse than noise

trail's sentence is the whole argument:

> **A gate nobody can satisfy is a gate someone switches off.**

Any repo running this package as a pre-commit gate can no longer commit a lockfile change — so no dependency update at all, *including the next update of this package*. It already blocked the commit carrying trail's own 0.5.0 bump. The failure mode is not a false alarm; it is the entire guard being disabled, at which point the 38 patterns that work protect nothing.

## It is this package's own doctrine, inverted

The file header says it in its own words:

> *"NEVER a bare high-entropy/hex pattern (it would hit git shas/hashes)."*

Every other prefix-less secret here is **context-only** — `cloudflare-api-token`, `mistral-api-key`, `vimeo-access-token`, `labeled-hex-secret` all require a named field, precisely so they are not guessing at entropy. `hue-application-key` is the one pattern that guesses. It is the one that broke. That is not a coincidence; it is the rule earning its keep.

## What I got wrong, and where it was already written down

F035.9 widened this regex to *require* mixed case, to kill a false positive on hyphenated English prose. I mutation-tested the new property, saw green, and shipped. The mixed-case requirement fixed the prose case and **introduced this one** — base64 is mixed-case by construction.

This repo's own memory already carries the rule: *a correction is not safer, just newer — re-prove EVERY case after widening, and build the example where the old and new properties differ.* A lockfile is exactly that example, and I did not go looking for it.

## The fix

Anchor it on a field name, in the shape the package already uses four times:

```js
/\b(?:hue|bridge)[_-]?(?:application[_-]?key|username|user|key)\b\s*[:=]\s*["'`]?[A-Za-z0-9-]{40}(?![A-Za-z0-9-])/gi
```

Covers the shapes a Hue key actually occurs in: the v2 header `hue-application-key: …`, `HUE_APPLICATION_KEY=…`, and a quoted JSON field.

## What we give up, on purpose

A bare 40-character Hue key sitting in prose with no field name near it is **no longer detected**. That goes in the README's *Deliberately NOT detected* section as a decided boundary, with the reason — otherwise the next reader removes the anchor to "fix" it and we are back here.

The trade is the package's founding one: *accept missing an exotic token over false positives*, because a redacted real fact corrupts knowledge — and, as this week proves, a gate that cries wolf gets turned off.

## Two things from trail's report worth keeping

Their own two self-checks failed in **opposite** directions, which is why neither could have revealed the other:

- A `uk_` probe came back unmatched and looked like a dropped pattern. It was not — the pattern needs 48 hex and their fixture had 32. **A test value that lacks the real key's FORM proves nothing in either direction.**
- Their mutation-check of the gate went **green** with a planted key, because the file was unstaged and the gate reads `git ls-files`. The gate was right; the check was looking at the wrong set.

## Consumers

- **trail** carries a label-scoped suppression (deliberately not file-scoped — the lockfile is still scanned by the other 38 patterns) with a note saying it comes out when the pattern gets an anchor. Tell them the version.
- **beacon** contributed this pattern in F035.7 and is the Hue consumer. They get the measurement and what the pattern can no longer see — if they need the unanchored shape, that is a conversation, not a silent removal.
