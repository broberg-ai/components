# F035.21 — Personal data detection (CPR, phone, email)

## Why
scout (7/10 2026, #2115) has an owner requirement (Scout PLAN §14 krav 2, Christian): personal data must **never** reach Trail. Before any Trail write, Scout must refuse a candidate that contains a Danish CPR number, a phone number or an email address. Scout handles names from an organisation's user list itself (app data). Scout's Trail writer stays closed until this primitive exists.

Discovery has no PII primitive (searched cpr / pii / personal data on 7/10). `@broberg/secret-scan` already owns "find a sensitive thing in text and redact it", and every consumer that guards a write already imports it, so this lands as an additive part of that package rather than a new one.

## API (additive, root export)
```ts
findPersonalData(text) → { kind: 'cpr' | 'phone' | 'email', start, end }[]   // sorted, non-overlapping
redactPersonalData(text) → { redacted, findings: { kind, count }[], scanned: ['cpr','phone','email'] }
hasPersonalData(text) → boolean
```
`scanned` follows the package's existing rule: an empty `findings` must say which question was asked.

## Detectors
- **CPR**: `ddmmyy-xxxx` and `ddmmyyxxxx`, digit-bounded. It matches only on a real calendar date. The century comes from the 7th digit (CPR rule: 0–3 → 1900s; 4/9 → 2000s if yy ≤ 36, else 1900s; 5–8 → 2000s if yy ≤ 57, else 1800s), so 29 February is checked against the right year. There is **no modulus-11 check**: numbers issued since 2007 do not satisfy it.
- **Phone**: Danish 8 digits starting 2–9, contiguous or grouped 2-2-2-2 / 4-4 (space or hyphen), with an optional `+45` / `0045` prefix; plus E.164 (`+` and 7–15 digits, first digit 1–9).
- **Email**: a pragmatic local@domain.tld.

When spans overlap, the earliest start wins, then the longest match.

## Fails closed, deliberately
Any 8-digit number starting 2–9 counts as a phone number, so an order number can be refused. For a "must never reach Trail" gate, a refused write is the cheap error and a leaked phone number is the expensive one. This is stated in the README so nobody "fixes" it into a leak.

## Tests
Positive and negative cases per detector (leap-year century, impossible dates, 7/9 digits, ISO dates, version strings), exact offsets, and the redaction markers. Each detector is mutation-checked by hand. The package's mutation harness only rewrites `src/index.ts`.

## Reuse
This extends the shared `@broberg/secret-scan` (F035) instead of Scout rolling its own regexes, so the next repo that guards a write against PII gets the same rules.
