# F084.158 — @broberg/sso: introspect a BID access token

trail #2976 (12/10 2026), part of F099 (Christian's build order: one web-clipper base). BID issues no user tickets with their own audience (broberg-id #2972, #38634). So a receiver (Trail's admin server, Jam's backend) checks the clipper's BID access token by **introspecting** it at BID: POST https://id.broberg.ai/oauth2/introspect with the receiver's own client credentials, and requires `active: true` and `client_id = <the clipper client>`. @broberg/sso 0.16.0 has no introspect function; Trail must not hand-roll it.

## Measured 12/10
BID discovery: `introspection_endpoint` https://id.broberg.ai/oauth2/introspect; auth methods client_secret_basic, client_secret_post, private_key_jwt. Without credentials it answers 401.

## API
```ts
const r = await sso.introspectToken(accessToken, { requireClientId: "trail-clipper", cacheMs: 30_000 });
// → { active: true, sub, clientId, scope, exp }
// throws SsoTokenInactiveError        → answer 401 (inactive, wrong client, expired)
// throws SsoIntrospectionUnavailableError → answer 503 (BID down, timeout, 5xx, unreadable)
```
The split is the point: a BID hiccup must never look like an expired login, and an expired login must never be retried as if BID were down.

- RFC 7662 form body `token`, `token_type_hint=access_token`; client_secret_basic with the app's SSO_CLIENT_ID/SECRET.
- The token never appears in an error message.
- Optional cache keyed by a hash of the token: an active answer is reused up to min(cacheMs, exp); an inactive answer is never cached.

## Reuse
This IS the shared package (@broberg/sso); it uses the existing discovery() and timeout pattern.
