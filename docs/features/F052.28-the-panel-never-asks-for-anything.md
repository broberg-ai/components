# F052.28 — The panel never asks for anything, so a missing button reads as a broken button

**Status:** Backlog. **Not scoped for 1 September without Christian's word.**

## What happened

Christian reported that «Fjern punkt» was gone. Nothing was broken.

He had opened a body region without choosing an intensity. By design that writes
nothing to the pain report, so there is genuinely nothing to remove and the button
is correctly absent — F052.26 examined exactly this gating, confirmed fd-sundhed's
read that it is right, and made "do not widen it" a constraint.

The defect is not in the logic. It is that **the screen never asks a question**, so
the absence of the button has nothing on it to explain it.

## Why this is worth a card and not a shrug

The person who misread it is the owner of the product, who knows this component
better than any patient ever will. A patient will read it the same way and will not
file a report — they will decide the app is broken and stop.

An open panel currently shows a region name and a row of 0–10 buttons. Every state
looks identical, so *"you have not chosen yet"* and *"something went wrong"* are the
same picture.

## The trap: do not fix this by showing the button earlier

That is the tempting fix and it is wrong. A «Fjern punkt» offered while the report
is empty tells the user something was stored when nothing was — it trades a
confusing absence for a false claim about their data, in a clinical record.

**The button's absence is information. What is missing is the sentence that makes it
readable.**

## Shape of the fix (not decided here)

A prompt in the panel's empty state — *"Hvor ondt gør det?"* / *"How much does it
hurt?"* — that disappears the moment an intensity is chosen.

- Localised (da/en) and overridable through the existing `ui` label object, like
  every other string in this package. A fleet component that hard-codes Danish is
  the `defaultTitle` mistake from `@broberg/webpush`, repeated.
- Must not become permanent chrome. On a phone it competes with the region name for
  the little space there is.

## Both renderers, asserted separately

The 2D panel has the same empty state. F052.22 already caught the two renderers
answering the same tap differently — 3D reported `ignore` on a locked region while
2D reported nothing at all — and what caught it was an acceptance criterion worded
*"asserted per renderer, not once"*, which forced a second fixture that promptly
failed.

So the AC here is worded the same way. Not a reminder to check the sibling: a test
that cannot pass while the halves disagree.

## Reuse

Nothing to import. This is a string and a conditional inside a component this repo
owns, and both halves of the mechanism it needs — the `ui` label object and the
da/en locale — already exist in `@broberg/bodymap` (F052.10). Discovery searched for
`empty state`, `form prompt`, `intensity picker`: no `@broberg/*` package covers
panel copy, and one should not — UI copy belongs to the component that renders it.

The reuse that *does* apply is internal and is the point of the card: the prompt
goes through the existing label/locale objects rather than a new prop or a literal,
so a consumer who has already translated this component gets this string too.

## Non-goals

- Changing `decidePick` or the remove-button gating. Settled in F052.20 and F052.26.
- A tooltip, a coach-mark, or a first-run tutorial. This is one line of copy in a
  state that already exists, not an onboarding surface.
- Anything about the 0–10 scale itself. The numbers are the fd-sundhed clinical
  taxonomy and are not ours to redesign.
