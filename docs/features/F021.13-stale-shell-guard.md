# F021.13 — staleShellGuardScript(): a stale page reloads itself fresh, once

## Motivation
Owner-reported 26/10: installed apps on his Mac went white after deploys. Helpdesk measured the mechanism (#5081): the stored page points at `/assets/` files the deploy removed (404), and `location.reload()` can answer from the browser store with the same stale page. Helpdesk built a guard in `apps/console/src/pwa/foraeldet-side.ts` and asked for it in @broberg/pwa so every PWA gets it.

F033.20 fixes the 404 at the source for Fly Live apps (old hashed assets are served from kept deploys). This story covers everything else: other hosts, and assets older than the kept window.

## Scope
`staleShellGuardScript(opts?)` returns an inline script string for `<head>` (prepend before the app's own tags). It listens for `error` on the page's own same-origin `/assets/` `<script>` and `<link rel=stylesheet>`, then `location.replace(url + ?_v=<Date.now()>)`, at most once per 30 s (sessionStorage timestamp). On load, if `_v` is present, it is removed with `history.replaceState`.

## Non-goals
- Not a service worker change; not a fix for third-party script failures.
- Not a replacement for F033.20.

## Architecture
Port helpdesk's file function by function (house rule: port, never rewrite). Framework-free string; exported from `@broberg/pwa` and usable in Vite `transformIndexHtml` or a Next `<Script strategy=beforeInteractive>`.

## Dependencies
helpdesk's `foraeldet-side.ts` as the source (ask_peer helpdesk). Related: F033.20.

## Reuse
Extends @broberg/pwa, the fleet's PWA package; no other package owns this.

## Rollout
Port + tests (happy-dom) + mutations → pwa minor release via CI → release report to helpdesk, jam, cardmem, fd-sundhed, trail and the other pwa consumers.
