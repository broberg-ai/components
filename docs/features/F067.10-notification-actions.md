# F067.10 — Knapper i notifikationen (actions)

> **Status:** backlog. Bestilt til WebHouse-mailklienten (F021), Christian 23/10 2026.

## Hvorfor
Den nye WebHouse-mailklient (PWA, stak B, afløser Roundcube på jabba) skal sende push ved ny mail til iOS, Mac og Windows og genbruge `@broberg/webpush`. Pakken dækker allerede VAPID via env, ulæst-tal på ikonet (`badge`, `sendSilent`) og iOS-hjemmeskærms-PWA'er. Den dækker IKKE knapper i notifikationen: målt i 0.5.0 findes `actions` ingen steder i `src`; `showNotification` (sw.ts:127) sender kun title/body/icon/badge/tag/data.navigate, og `handleNotificationClick` (sw.ts:151) kender ikke `event.action`.

## Hvad der bygges
- Besked-feltet `actions: { action: string; title: string; navigate?: string; post?: string }[]`, båret i den klassiske del af payloaden (den deklarative Safari-sti har ingen actions).
- Service workeren sender `actions` videre til `showNotification`, begrænset til `Notification.maxActions`; overskydende rapporteres.
- `handleNotificationClick`: `event.action` tom → uaendret adfærd. `event.action` sat → knappens `navigate` (åbn/fokusér) eller `post` (fetch POST uden at åbne vindue; fejl synlig for appen via postMessage/klient-event).

## Platforme — måles, ikke antages
Chrome/Edge (Mac, Windows) viser actions. Safari (macOS og iOS-hjemmeskærm) har historisk ikke gjort det. Kortet er først færdigt når README siger hvad hver platform faktisk gør, målt.

## Non-goals
- Svarfelter i notifikationen (inline reply).
- Native push (APNs/FCM) — mailklienten er en PWA; Web Push når iOS via Apples egen tjeneste.

## Afhængigheder
F067.8 ændrer samme `handleNotificationClick` (tryk der lander forkert på iOS). Byg sammen med eller efter den.

## Reuse
Udvidelse af den eksisterende fælles pakke `@broberg/webpush` — ingen ny pakke.

## Rollout
Minor-version, release-rapport til de 10 forbrugere (appkit, cardmem, fd-sundhed, happy-little-place, helpdesk, sales, trail, xrt81, moovyy, fysiodk-aalborg-sport) og til mailklientens session.
