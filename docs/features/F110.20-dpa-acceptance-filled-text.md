# F110.20 — Kunden accepterer den udfyldte databehandleraftale i BID

## Hvorfor
cardmem F422.2 (ejerens ordre 18/11): kunder accepterer DPA og vilkår i cardmem-portalen via BID. BID (F084.243, PR #300) kræver nu for `doc: "dpa"`:
- `authorityConfirmed: true` — den der accepterer bekræfter at have bemyndigelse (ellers 400 `authority_required`);
- `text` — den UDFYLDTE aftale (≤200.000 tegn), og `contentHash` skal være `"sha256:" + hex(sha256(utf8(text)))` (ellers 400 `hash_mismatch` / `text_required`).
Svaret bærer `authorityConfirmed` og `copy: "sent"|"skipped"|"failed"` (kopi til kunden).

@broberg/legal 0.9.0 kan ikke sende felterne, og har ingen funktion til at udfylde `{customer.name}` osv. — README siger at Contract Manager gør det, men pakken giver kun PLACEHOLDERS-listen. cardmem bad om udvidelsen frem for en lokal omvej.

## Scope
1. `fillPlaceholders(doc, values)` → nyt `LegalDocument` med alle pladsholdere erstattet; afviser manglende, ukendte og tomme værdier med navn; `placeholders: []`; ny `contentHash`.
2. `renderText(doc)` — deterministisk ren tekst af dokumentet (titel, overskrifter, afsnit, lister med `- `, tabeller med ` | `).
3. `textHash(text)` — `"sha256:"+hex(sha256(utf8))`, så hash'en er over præcis den tekst kunden ser.
4. `recordAcceptance` får valgfri `text` og `authorityConfirmed`; lokalt tjek af hash og længde før kaldet; `AcceptanceRecord` får `authorityConfirmed?` og `copy?`; echo-tjek af authorityConfirmed.

## Non-goals
- Hvordan cardmem viser aftalen eller indhenter bemyndigelses-flueben (deres UI).
- Vedhæftede bilag / PDF.

## Bagudkompatibilitet
Uden de nye felter er request og svar som i 0.9.0. Ingen dokument-hash flytter sig.

## Rollout
Minor → rapport (D-b7eb14) → cardmem måler én rigtig DPA-accept.

## Reuse
Udvidelse af eksisterende `@broberg/legal` (F110).
