# F082.12 — advisory-watch `track-latest`

**Ordered by:** Christian via bid 28/11 2026 (intercom #57002, bid-F084.258): BID must ALWAYS follow the newest patch of Better Auth — no grace period.

## Why
A security fix often ships as a patch BEFORE any advisory is published or reviewed (Better Auth: 12 advisories fixed in 1.7.16, the advisories visible on the repo only, reviewed weeks later). For a few load-bearing packages the only safe rule is «the newest patch on the line you run».

## Design
- Workflow input `track-latest: "better-auth,@better-auth/oauth-provider,@better-auth/passkey"` → `--track-latest`.
- For each listed package: its LOCKED versions (lockfile) vs the npm packument. The newest STABLE version with the same `major.minor` as a locked version is the target. Locked below it → finding `{ pkg, id: "stale:<pkg>", severity: "high", title }`, source `latest` — through the same `decide()`: red, one issue, Upmetrics incident, ack by id, closed when the lock catches up.
- A newer minor or major exists → a report line only (moving a minor is the owner's call, not the watch's).
- Prereleases are never «newest».
- No grace period (the order says none); BID runs it hourly.

## Honest failure
A listed package that is not locked, or whose packument cannot be read → an error (red, closes nothing). A typo must not read as «up to date».

## Tests
Pure engine: stale on the minor line, newest minor only reported, prerelease ignored, ack, not-locked → error. End to end against real npm with a scratch lock of better-auth@1.7.14.

## Reuse
The engine (F082.10/.11) — one more source into decide(); the lockfile reader and semver comparator already there. No new dependency.

## Release
Tag `advisory-watch-v1.2.0`; bid sets the list and an hourly cron.
