# F005.21 — Webhook-styring via Resends nye API

> Christian 3/10 2026: «Ja, tilføj det med det samme» — efter gennemgangen af Resends nyheder.

## Hvorfor

Leveringsstatus (delivered/bounced/complained) findes kun på webhook-strømmen (F005.7). Når vores endpoint var nede eller svarede forkert, gik hændelsen tabt for os, og `last_event` stod forkert — uden nogen måde at hente den igen. Resend kan nu (16/9 2026):

| metode | sti |
|---|---|
| GET | `/webhooks/{webhook_id}/events` (`limit` 1–100, default 20; `after` = event-id) |
| GET | `/webhooks/{webhook_id}/events/{event_id}` |
| GET | `/webhooks/{webhook_id}/events/{event_id}/attempts` (`limit`, `after`) |
| POST | `/webhooks/{webhook_id}/events/{event_id}/replay` |
| POST | `/webhooks/{webhook_id}/signing-secret/rotate` → `{signing_secret}`; begge nøgler signerer i 24 timer |

Kilde: resend.com/docs/api-reference/webhooks/*, læst 3/10 2026. Event-status: `success | failed | attempting | pending`.

## Hvad vi bygger (i `@broberg/mail/webhook`)

- `createWebhookAdmin({ apiKey, webhookId, fetch? })` med `listEvents`, `getEvent`, `listAttempts`, `replay`, `rotateSecret` — tynde, typede kald.
- `replayFailed({ max })` — den værdifulde: gensend alle hændelser vores endpoint ikke tog imod, begrænset af `max`.
- `verifyWebhook` / `handleMailWebhook` accepterer en LISTE af nøgler, så et nøgleskift kan køres uden koordinering: sæt begge, fjern den gamle når 24 timer er gået.

Fejl kastes ikke; de returneres som `not_found` eller `could_not_ask`, samme form som `getInboundEmail` (F005.x), så en send-only nøgle (401) aldrig læses som «ingen hændelser».

## Nøglen

Webhook-API'et kræver en nøgle med fuld adgang — Resend har ingen læse-nøgle. De fleste apps har en send-only nøgle. Den fulde nøgle hører i vaulten og bruges af et driftsjob eller en agent, ikke af den kode der sender mail. `rotateSecret()` returnerer den nye signeringsnøgle til kalderen og logger den aldrig.

## Ikke med

- Statistik (`/emails/metrics`) og forbrug (`/usage`) — senere, hvis nogen beder om det.
- At oprette/slette webhooks.
- Automatisk planlagt replay — appen (eller et cron-job) kalder `replayFailed`.

## Reuse

Udvider `@broberg/mail` (F005), flådens eneste mail-chokepoint. Discovery: ingen anden pakke ejer Resend-webhooks. Ingen ny afhængighed (fetch + node:crypto).
