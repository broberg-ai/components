# F084.182 — @broberg/sso: verifyAgentCard + createA2AVerifier

**Bestilt af:** bid (#4626, 25/10 2026, BID F087.43). «Ingen hast.» Ligger i Backlog under F084.

## Motivation
BID udsteder nu signerede A2A v1.0.0-agentkort og agent-billetter. En agent der modtager et kald fra en anden agent skal kunne svare på to spørgsmål uden selv at slå kryptografi op: *er dette kort udstedt af BID?* og *er denne billet en agent (eller service/bruger) jeg kender?* Uden en fælles funktion skriver hver agent sin egen JCS + Ed25519 — og den farlige fejl (at stole på kortets egen `jku`) bliver gentaget i hver kopi.

## Scope
- `verifyAgentCard(card, { issuer, fetch? })` → `{ ok: true, kid }` | `{ ok: false, reason }`.
  - jwks-URL afledes af `issuer` (`<issuer>/.well-known/agent-card-jwks.json`); `protected.jku` skal være lig med den, ellers `untrusted_jku` uden at hente noget.
  - payload = JCS (RFC 8785) af kortet uden `signatures`; verificér `signatures[0]` som detached JWS (EdDSA) med `jose`.
  - Udfald: `bad_signature`, `unknown_kid`, `untrusted_jku`, `malformed`, `jwks_unreachable` — adskilte.
- `createA2AVerifier({ issuer, audience })` oven på `createTicketVerifier`: kræver `principal_type ∈ {agent, service, user}`, udstiller `principal.agentCard` (billettens `agent_card`).

## Non-goals
- Hente og verificere kortet automatisk inde i billet-verifikationen (forbrugeren vælger).
- Andre algoritmer end EdDSA.
- Caching af jwks ud over hvad jose allerede gør (beslut ved implementering, mål først).

## Arkitektur
```
card ──► strip signatures ──► JCS ──► detached JWS verify (jose, EdDSA)
          protected.jku ==? issuer/.well-known/agent-card-jwks.json  (else untrusted_jku, no fetch)
ticket ─► createTicketVerifier ─► principal_type check ─► principal.agentCard
```

## Reuse
Discovery-søgning «jcs canonical json ed25519 jws» (25/10): intet eksisterende @broberg-pakke-match. Genbruger `jose` (allerede sso's eneste dependency) og `createTicketVerifier` fra samme pakke. JCS skrives lille og testes mod RFC 8785's vektorer, medmindre en vedligeholdt, afhængighedsfri implementering findes ved byggestart.
