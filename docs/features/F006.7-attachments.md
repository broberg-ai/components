# F006.7 — Bilag på en besked: `@broberg/media/attachments`

> Christians ordre 2/10 2026: «lav kortet og løft bilagsdelen ind i pakken».
> Forbrugere: **helpdesk** F054 (billeder + PDF i live chat) og **Aidan** (`@broberg/chat`, broberg.ai). Begge skal bruge SAMME kontrakt.

## Problemet

`@broberg/media` 0.3.1 er ren lagring (upload/get/signedUrl/delete/publicUrl). Alt det, der gør et *bilag* sikkert — hvad er filen egentlig, må den komme ind, hvor ligger den, hvordan serveres den uden at kunne køre script i vores origin — har hver app håndrullet. cardmem har den bedste udgave (F006-vurderingen), men den bor i cardmems egen kode, og xrt81 har sin egen. Helpdesk var ved at bygge en femte.

## Hvad vi løfter (fra cardmem, origin/main 0bc57e7c)

| cardmem | her | ændring |
|---|---|---|
| `UPLOAD_FORBIDDEN_EXT` + `isForbiddenUploadExt` | samme liste | uændret — gulvet kan ikke krydses |
| `UPLOAD_ALLOWED_EXT` | default tilladt-liste for bilag | indsnævret til det en chat sender (billeder, pdf, office, tekst) — kalderen kan udvide, aldrig over gulvet |
| `validateUpload` (endelse) | `validateAttachment` | **+ type-sniffing på de første bytes**; den sniffede type vinder over klientens; endelse der lover billede/pdf uden at bytes gør det → afvist |
| `R2_MAX_BYTES` 25 MB | `maxBytes` default 25 MB | kan sættes |
| `attachmentKey(...filename)` | `attachmentKey(id)` → `attachments/<id>` | **filnavnet ud af nøglen** (F086 viste at nøgler fra input er farlige); `keyPrefix` giver tenant |
| `serveHeaders` | `attachmentHeaders` | disposition via `@broberg/http` `contentDisposition` i stedet for en kopi |

Nyt: `sha256Hex(bytes)` og typen `AttachmentRecord {id, messageId, key, contentType, bytes, filename, sha256}` — den form helpdesk og jeg aftalte 2/10.

## Form

En ny subpath `@broberg/media/attachments`, ren (ingen I/O, ingen provider). Roden røres ikke, så eksisterende forbrugere (broberg-id) er upåvirkede. Version 0.4.0 (minor: ny eksport).

## Ikke med

- En router/HTTP-handler (det er F006.2, stadig backlog) — appen ejer sin route.
- DB-tabellen — vi leverer typen, appen ejer skemaet.
- PDF-miniaturer, virusscanning, billed-omkodning (`@broberg/media-transform` gør det sidste).
- cardmems maskin-only-segment (DMARC-arkiver) — cardmem-specifikt.

## Reuse

Discovery søgt 2/10 (`attachment`, `upload`, `file upload`, `bilag`): kun `@broberg/media` (lagring), `@broberg/media-transform` (billeder), `@broberg/http` (`contentDisposition` — genbruges her). Ingen eksisterende bilagskontrakt. Kilde: cardmem r2.ts + upload-types.ts.
