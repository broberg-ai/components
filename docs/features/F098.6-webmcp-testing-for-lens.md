## What Chromium offers (measured 12/10 from Chromium source + the published protocol)
- **Turning it on:** `--enable-features=WebMCP` (content/child/runtime_features.cc: overriding kWebMCP controls both imperative and declarative WebMCP). chrome://flags/#enable-webmcp-testing is the UI for the same. Origin trial from Chrome 149 — not usable headless.
- **A test door already exists:** the DevTools protocol domain `WebMCP` (experimental): `enable` (fires `toolsAdded` for every registered tool), `invokeTool {frameId, toolName, input} → {invocationId}`, `cancelInvocation`, events `toolsAdded`, `toolsRemoved`, `toolInvoked`, `toolResponded {invocationId, status Completed|Canceled|Error, output, errorText, exception}`. Tool annotations include `readOnly` and `consequential`.

So the package needs no browser dependency: it speaks CDP through any session with `send`/`on` (Playwright's CDPSession is one).

## API
```ts
import { WEBMCP_LAUNCH_ARGS, createWebMCPTester } from "@broberg/webmcp/testing";
const browser = await chromium.launch({ args: [...WEBMCP_LAUNCH_ARGS] });
const cdp = await page.context().newCDPSession(page);
const mcp = createWebMCPTester(cdp);
const tools = await mcp.listTools();
const r = await mcp.invokeTool("list_services", {});          // read-only tool
await mcp.invokeTool("start_booking", {...}, { mutates: true }); // anything not readOnly needs this
```

## Safety
A tool not annotated `readOnly` is refused unless `mutates: true` (same rule as Lens' write tools, D-b20c50). Unknown name → refused with the known names. Timeout → `cancelInvocation` + a clear error.
