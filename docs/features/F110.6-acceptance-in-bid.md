# F110.6 — Accept af vilkår gemmes ét sted: i BID

> **Ordre:** ejeren 1/11 2026, ordret: «Vi gemmer, hvilken version af vilkårene du har accepteret, og hvornår. Gør vi det og hvordan? Ideen er FUCKING god men det skal virke. Jeg foreslår at det gemmes et sted i BID så det også kan aflæses via BID både i UI og via et API de forskellige apps kan trække ud».
> **Erstatter** F110-planens linje «Storage stays in each app».

## Målt (1/11 2026)
Vilkårene (terms, «accept.p2») lover: «Vi gemmer, hvilken version af vilkårene du har accepteret, og hvornår.» Intet system gør det i dag. Jam er i gang i egen database (F001.79). Løftet holder altså ikke.

## Model
- **Hvad en accept er:** `{ sub (BID-bruger), product, doc, version, contentHash, acceptedAt, clientId (appen der registrerede den) }`. Kun `terms` accepteres (privacy accepteres aldrig — F110). Gemmes **append-only**: en ny accept er en ny række, intet overskrives eller slettes ved ny version — historikken er beviset.
- **Hvornår igen:** når den gældende `terms` er `material: true` og dens `version` er nyere end brugerens seneste accept for produktet. Ikke-væsentlige ændringer meddeles, kræver ikke ny accept.

## Hvem bygger hvad
| Del | Ejer | Indhold |
|---|---|---|
| Lager | **bid** | tabel/collection for accepterne, append-only, pr. bruger |
| API | **bid** | app registrerer accept på brugerens vegne (appens egen klient-identitet + brugerens sub/token); app læser brugerens seneste accept pr. produkt+doc |
| UI | **bid** | «Vilkår du har accepteret» på BID-kontoen: produkt, dokument, version, dato |
| Hjælper | **components** | i @broberg/legal: `needsReaccept(latestAccepted, currentTemplate)` + `recordAcceptance`/`getAcceptance` mod BID's API (fetch, tokens fra appen) |
| Instruks | **components** | README trin 6 + Discovery-tip: registrér i BID, ikke i egen database |

API-formen aftales med bid FØR components' hjælper skrives, så de to dele passer.

## Sikkerhed / GDPR
- En app kan kun registrere og læse accepter for de brugere, der er logget ind i netop den app, og kun for sit eget produkt.
- Brugeren ser sine egne accepter i BID. Sletning af en BID-konto følger BID's øvrige regler. En accept er bevis, så opbevaringstiden aftales med advokaten (åbent spørgsmål).

## Migrering
Jam (F001.79) gemmer i egen database i dag → flyttes til BID, når API'et findes.

## Åbne spørgsmål
1. Opbevaringstid for accepter efter kontosletning (advokat).
2. Skal en accept på et produkt også gælde for en ny version af dokumentet, der ikke er væsentlig? (Forslag: ja — kun `material: true` kræver ny accept.)

## Reuse
BID (broberg-id) som identitets- og konto-system; @broberg/legal for tekster og versioner.
