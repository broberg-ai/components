# F061.5 — The credential-format layer is OFF in every fresh clone, and the hook says nothing

**Status:** In progress · **Epic:** F061 (build hardening) · **Written:** 2026-08-31

## Motivation

The pre-commit secret gate has three layers. Layer 3 — known credential FORMATS,
the one that catches a provider token pasted in from somewhere else — is gated on
a file that does not exist in a fresh clone.

```sh
SCAN="$ROOT/packages/secret-scan/dist/index.js"
if [ -f "$SCAN" ]; then
  …
fi
```

`dist` is gitignored (`.gitignore:83`). So until somebody runs a build, that `if`
is false, the layer never runs, and the hook exits 0.

**Measured** — throwaway repo, the real hook, no dist:

```
$ printf 'key = AKIA%s\n' "IOSFODNN7EXAMPLE" > added.txt
$ git add -A && git commit -qm "..."
$ git log --oneline -1
0bfdd1a add a real-format AWS key, NO secret-scan dist present
```

The commit succeeded. A real-format AWS access key went in clean, and the
developer was told nothing.

## The shape

This is the failure form this repo named this week, sitting inside the guard
built to prevent it: **a result shaped like success that is really a non-answer.**
A missing scanner is not a clean commit. The three states that keep collapsing
into two are *found / not-found / could-not-look*, and here `could-not-look`
silently became `not-found`.

The rule it violates is already written down in our own contract: *an unanswerable
question must read as **unanswered**, never as **compliant**.*

## How it surfaced

Not by review. By the instrument.

F061.4 added `scripts/test-precommit-secret-gate.mjs`, which copies that same
`dist/index.js` into each fixture repo. On CI there is no dist — the standalone
scripts in the root `test` script run before `turbo run test`, and only turbo's
`test` task carries `dependsOn: ["build"]`. So the script died:

```
Error: ENOENT: no such file or directory, copyfile
  '.../packages/secret-scan/dist/index.js' -> '/tmp/gate-I2dP5I/...'
```

That took the workspace gate red, which blocked `@broberg/mail@0.7.2`. The crash
is the small half of this card. The silent skip is the real one, and line 67 would
not have been read today without it.

## Scope

**In:**

1. `.githooks/pre-commit` — a missing `$SCAN` **refuses** the commit and prints
   the one command that fixes it.
2. `scripts/test-precommit-secret-gate.mjs` — build `@broberg/secret-scan` when
   dist is absent (test setup), plus a new fixture case asserting the refusal
   **and its message**.
3. `scripts/test-precommit-secret-gate-mutations.mjs` — a mutation restoring the
   old skip, with its anchor asserted.

**Out (non-goals):**

- Auto-building inside the hook. A commit hook that silently shells out to a
  build is a surprise with its own failure modes; print the command instead.
- Falling back to a `node_modules` copy of secret-scan. That is the F061.2 trap —
  a caret-pinned 0.x transitive dependency that can be many minors stale, so the
  fallback would scan with an older pattern list while reading as current.
- Touching layers 1 and 2. Neither needs a build; both are unaffected.

## Reuse

Checked Discovery for an existing primitive before writing anything:
`discovery.broberg.ai/api/search?q=pre-commit+secret+gate`. The pattern list is
already `@broberg/secret-scan` (F035) and this card does not re-implement it —
the change is entirely in how the hook reacts when that package is not built.
No new capability, nothing to extend, nothing to enroll.

## Rollout

Source-only, no version bump, no publish. The hook takes effect on the next
commit in any clone that has run `pnpm install` (which sets `core.hooksPath`).

One cost is accepted deliberately: a fresh clone must run
`pnpm --filter @broberg/secret-scan build` once before its first commit. That is
the honest trade — the alternative is the gate we have now, which asks nothing of
the developer and also protects nobody.

## Verification

1. Fixture without dist → **blocked**, message names the build command.
2. Fixture with dist → add refused, removal allowed (F061.4 unchanged).
3. Mutation restoring `if [ -f … ]` → the new test goes **red**; anchor asserted.
4. `pnpm test` green from a tree with no `dist/` anywhere — the CI condition.
5. The tag push publishes `@broberg/mail@0.7.2`, verified by installing it from
   npm rather than by reading the run's status.
