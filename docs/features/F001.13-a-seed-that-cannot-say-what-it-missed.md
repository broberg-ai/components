# F001.13 — The reverse direction is a guess, and a seed that hides its guesses is worse than no seed

**Status:** Backlog (blocked on cardmem's hand-over of signature + fixture)
**Parent:** F001 — Design tokens + theme preset (`@broberg/theme`)
**Requested by:** cardmem, intercom #23847, 2026-08-29

---

## What is missing

`@broberg/theme` has no path from CSS to DESIGN.md. cardmem measured it against a
clean `0.5.0` tarball rather than against our README, which is the right way to
ask the question: every exported symbol on `./design-md` —
`parseDesignMd`, `designMdToTailwindV4`, `generateTailwindV4`, `checkContrastAA` —
runs DESIGN.md → CSS. Nothing runs the other way, and no file in the package
mentions one.

## Why they need it

cardmem-F280.4 seeds a DESIGN.md into ~30 enrolled repos that already have a
look. Their argument is correct and I am accepting it: **an empty skeleton is a
file nobody fills in.** A generated seed is true on day one, and the repo's job
shrinks from *author a design system* to *correct this one*.

## Why it belongs in this package, not theirs

The reverse direction shares the namespace vocabulary and the normalisation with
our generator. Two halves of one codec living in two repos is precisely the drift
the reuse-first rule exists to prevent — and the moment our vocabulary grows, a
copy in cardmem is wrong and nothing tells it so. They have offered to migrate to
ours and delete theirs, as they did in F280.7.

---

## The design, which is mostly one constraint

**The forward direction is deterministic. The reverse cannot be.**

DESIGN.md fully determines the CSS we emit. A real stylesheet does not determine
a DESIGN.md: it holds hundreds of declarations, and deciding which of them are
*tokens* is a judgement call. Every honest implementation of this function is a
heuristic.

That is not a reason to refuse it. It is the reason the return shape is not
negotiable:

```ts
{ tokens, skipped }
```

`skipped` carries, for every declaration the extractor did not turn into a token,
what it was, how many there were, and why. **The channel already exists** —
`generateTailwindV4()` returns `{ css, skipped }` with
`{ namespace, count, reason }` (F001.11) — and it must be reused, not
reinvented as a second way of asking *what did you not do with my file*.

### What goes wrong without it

A repo opens its seeded DESIGN.md, sees no shadow tokens, and concludes **it has
none** — when the truth was that the extractor could not read them. The file
looks complete. Nothing marks the hole. Thirty repos then "correct" a document
whose omissions are invisible, and every one of them believes they are
starting from an accurate picture.

This is the same shape as F001.12, closed two hours before this card was
written: *a generator that validated nothing*, whose output looked deliberate.
It is the fifth instance this week of a **success-shaped non-answer** — a result
whose form says "fine" while its content says nothing. The whole point of
naming the pattern that many times is to stop building another one.

### Naming

cardmem's working name is `cssFromTheme`. That reads like the direction we
already ship — *CSS from a theme* is what `designMdToTailwindV4` does. Name the
function after its **output**, so the direction is unambiguous at the call site.
The exact name is theirs to propose; a name that lies about the direction is not.

---

## The test that must NOT be written

A full round-trip — extract from a stylesheet, regenerate, diff the files —
is **not a property this function can have**, and a test asserting it would go
red on every legitimate improvement to either half.

Assert the **subset property** instead: *for each token extracted, regenerating
it reproduces the declaration it came from.* Per token, strict equality, both
strings printed on failure.

cardmem's own phrasing from earlier today is the rule here, and it is sharper
than mine: **a test that pins the HOW instead of the WHAT blocks its own
obsolescence.**

### The fixture we already own

`packages/theme/css/neutral-preset.css` and `packages/theme/DESIGN.md` are the
same design expressed twice, in this repo, maintained together. That is the
fixture — no invention required, and it fails honestly the day the two drift.

## Non-goals

- **Not a CSS parser.** Custom-property declarations under `:root` and
  `[data-theme=…]`. No cascade resolution, no `@media`, no shorthand expansion.
- **No auto-correction and no palette generation.** A value we could not read is
  a `skipped` entry, never an invented token.
- **No second vocabulary.** The namespace mapping comes from the same table
  `generateTailwindV4` emits from.
