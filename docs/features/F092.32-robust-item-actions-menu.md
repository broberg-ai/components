# F092.32 — ItemActionsMenu: robust (value, separator, size, keyboard-only focus ring)

scout #2801 (11/10), owner-reported: Christian compared our menu side by side with Claude Desktop's filter menu: «vores er sådan lidt whimpy og den fra Claude Desktop er robust og det er ikke fordi den er i darkmode». Scout card scout-card-cd9acb368b83.

## Scope
1. `NavAction.value?: string` — a dimmed value right-aligned before the chevron/kbd («Type …… All ›»). Today scout writes «Type · All» in the label.
2. `NavAction.separator?: true` — a divider (role=separator) before the item. Not focusable; ↑↓ skips it because only buttons are in the item list.
3. Size, as tokens on `.bas-rowmenu` so a consumer can tune them: `--bas-menu-row-height` 44px, `--bas-menu-font-size` calc(17px × --bas-font-scale), `--bas-menu-radius` 14px, `--bas-menu-padding` 6px. Numbers are scout's measurement of Claude Desktop at 1×; components has not measured Claude Desktop itself. Applies to every ItemActionsMenu (sidebar «…» too) — scout asked for that.
4. Focus ring only for keyboard use. The menu moves DOM focus to the first item on open; with a mouse open that showed the browser's :focus ring. Now: `is-kbd` on the menu when the anchor matched `:focus-visible` at open (keyboard-focused anchor + Enter) or after any key inside the menu; the outline is drawn only under `.is-kbd`. Highlight background is unchanged, ↑↓/Enter/Escape unchanged.

Non-goals: changing positioning, width (240px) or keyboard model.
