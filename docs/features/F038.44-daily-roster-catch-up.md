# F038.44 — Discovery holder sig 100 % opdateret hver dag

**Ordre:** Christian 25/10 2026 — «hold discovery 100% opdateret på daglig basis».

## Motivation
F038.16 lader en udgivelse fra DETTE repo løfte sin egen roster-række. Pakker der udgives fra andre repoer (lens-daemon fra broberg-ai/lens, ai-sdk, db-sdk, …) har ingen sådan vej. Målt 25/10: lens udgav lens-daemon 0.1.37 og måtte bede components om et manuelt bump (#4613). Indtil da er rækken bagud, og check-roster-versions gør Discoverys deploy rød — også for urelaterede, korrekte ændringer. Den daglige kørsel (F038.33) opdager hullet men lukker det ikke.

## Scope
- `scripts/check-roster-versions.mjs --list-behind`: maskinlæsbar liste over BAGUD-rækker. FORAN → exit 1, aldrig listet.
- Nyt workflow `.github/workflows/roster-catch-up.yml`: daglig schedule (05:17 UTC, før Discovery 05:47) + workflow_dispatch. For hver bagud-række: `bump-roster-version.mjs` (som selv spørger npm), regenerér docs/, commit som bot, push med F038.16's retry-løkke.
- Discoverys planlagte kørsel 30 min senere checker main ud og udruller (en GITHUB_TOKEN-push starter ingen anden workflow — målt i F038.33).

## Non-goals
- Ændre rolle/beskrivelse (ejerens).
- Auto-rette FORAN (404-retningen).
- Fjerne eller svække check-roster-versions.

## Arkitektur
```
05:17 roster-catch-up  → check --list-behind → bump × N → build → commit/push (bot)
05:47 discovery        → check (0 behind) → deploy → live-fresh
```
Tre udfald pr. række som før: i takt · bagud (løftes) · foran (rød) · kunne-ikke-spørge (intet bump, advarsel).

## Reuse
Discovery-søgning ikke nødvendig: genbruger husets egne scripts — `bump-roster-version.mjs` (F038.16), `check-roster-versions.mjs` (F038.10) og publish.yml's roster-job-løkke. Intet nyt værktøj.

## Rollout
Commit → CI grøn → workflow_dispatch én gang på main (bevis) → den daglige schedule overtager.
