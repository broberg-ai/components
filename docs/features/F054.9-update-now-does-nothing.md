# F054.9 — «Opdatér nu» does nothing: the first-install guard eats the reload the user asked for

## Report

Owner-reported via helpdesk (intercom #1348, 1/10 2026): Christian pressed «Opdatér nu» 30 times in helpdesk and nothing happened. helpdesk read our dist and named the cause [Likely, not reproduced in a browser]. Confirmed by reading `packages/pwa/src/index.ts` @ 0.4.0.

## Mechanism

F054.6 added a guard so a FIRST install (clientsClaim on an uncontrolled page) does not reload a new visitor:

```ts
let hadController = !!container.controller;   // captured ONCE, at creation
onControllerChange: if (!hadController) { hadController = true; return; }
```

The guard cannot tell "a worker claimed me on first install" from "a worker took over because the user pressed update". A page opened with no controller (shift-reload bypasses the SW; or the first page after registration) while a worker is waiting, then:

1. banner shows (waiting worker exists)
2. user presses «Opdatér nu» → `SKIP_WAITING` → worker activates → `controllerchange`
3. guard: `!hadController` → swallow. **No reload.**
4. every later press posts `SKIP_WAITING` to `waitingWorker`, a worker that is now ACTIVE → nothing. `updateReady` stays true until the next focus tick.

And without `clientsClaim`, an uncontrolled page never gets `controllerchange` at all, so the same press is silently inert there too.

## Fix

- `applyUpdate()` sets `applied = true`. A `controllerchange` after an explicit apply ALWAYS reloads; the first-install guard only applies when nobody asked.
- `applyUpdate()` re-reads `registration.waiting` (not the cached `waitingWorker`). If nothing waits but an update WAS offered (`updateReady`), the worker already activated: reload directly instead of a no-op.
- After posting `SKIP_WAITING`, also watch that worker's `statechange` → `activated` → reload. Covers SWs without `clientsClaim`. Single `reloading` flag guards double reloads.
- `reloadOnControllerChange: false` keeps meaning "I reload myself": none of the new paths reload.

## Reuse

Fix inside the shared package that owns it (`@broberg/pwa`). No new dependency.

## Release

0.4.1, patch: a press that did nothing now reloads. No API change. Release report to helpdesk and known consumers (fd-sundhed, cardmem, pitch-vault, xrt81).
