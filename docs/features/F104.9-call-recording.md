# F104.9 — Optagelse af opkald

> **Status:** Backlog. Ejeren 1/11 2026 spurgte om optagelse skal i samme pakke eller en `/record`-pakke; svaret er samme pakke. Infrastrukturen kræver eget GO. Sammenhæng i `F104.6-call.md`. Jam vil have det som sidste trin (jam-F029.4).

## Pakke-delen (lille)
- `startRecording(room, { target })`, `stopRecording(id)` på `./server`, via LiveKits Egress-API med appens nøgle.
- Webhook `egress_started` / `egress_ended` — dækket af eksisterende `verifyWebhook`.
- Klient: `recording`-tilstand så alle deltagere ser at der optages.

## Infrastruktur-delen (det dyre — GO-krav)
- LiveKit Egress som egen Fly-app i arn (headless Chrome, ~4 CPU pr. samtidig optagelse `[Likely]`).
- Redis delt mellem LiveKit-server og Egress (LiveKit kræver det for Egress).
- Lagring: R2-bucket med EU-jurisdiktion (D-2287db), oprettet af cardmem.
- Månedspris beregnes og forelægges ejeren før noget oprettes.

## Ikke i scope
Transskription, redigering, afspiller-UI (sidstnævnte hører til `@broberg/video`, senere).

## Samtykke
At informere deltagere og evt. indhente samtykke er appens ansvar; pakken leverer tilstanden der gør det muligt.
