# F085.5 — BID's instant database switch as a shared package

**Requested by:** vnlekerv2 (VN F004.4, 25/11 + #56021, 26/11 2026). Owner decision D-444126: every dual-DB setup (primary + reserve replica) must have BID's full security setup — IP guard, reserve probe and runbook. VN and fd-sundhed run dual-DB setups today.

## Why
BID has the instant switch in its own repo (broberg-id src: `switchable-pool`, `db-switch-control`, `db-switch-cli`, `db-fence`, `db-reconcile`, ~1,900 lines incl. tests). Every other dual-DB app would otherwise have to write it again, and D-ad16af forbids that local workaround. VN's `db()` is already `@broberg/db-sdk` 0.2.0 (postgres), so the switch fits as a wrapper around `DbClient`.

## Scope
- `@broberg/db-sdk/switchable`: `createSwitchable({ primary: DbClient, reserve: DbClient, … })` → a `DbClient` that writes to exactly one side (fence), can switch at once, and reconciles afterwards — ported function by function from BID.
- BID's tests for the five modules are ported and run against two real Postgres instances in CI.
- The CLI (`db-switch-cli`) comes along as a bin entry if BID's tests cover it.

## Non-goals
- Logical replication setup itself (schema/subscription) — that is the dual-database guide (docs/guides/dual-database.md).
- Switching BID over: BID decides that, after its own test branch is green.

## Order
1. Read the five modules + tests in broberg-id; agree the seam with BID over intercom (D-590f05: one mechanism, one owner = components builds, BID reviews).
2. Port into broberg-ai/db-sdk with the tests; CI with two Postgres containers.
3. BID runs its switch test with the package in a test branch.
4. Release (minor) + release report.

## Reuse
`@broberg/db-sdk` (F085, the DbClient surface). BID's code is the source; nothing is redesigned.
