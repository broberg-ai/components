# F099.8 — The consumer's own fields in the popup

> Story under F099. Priority high. 2 SP. Ships in @broberg/web-clipper 0.2.0.

## Summary
Trail's current clipper lets the user type tags before clipping; Jam wants a note. The shared popup in 0.1.0 has no room for fields a consumer defines, so Trail's users would lose tags when Trail moves onto the shared base. This story lets a consumer add its own text fields to the popup; whatever the user types is handed to the consumer's destination with the clip, and the base never stores it.

## Motivation
trail #3040 (12/10), during F319.3 (Trail's migration onto 0.1.0): «popuppen har et felt til emneord (tags, kommasepareret), som sendes med i metadata … uden det mister nuværende brugere funktionen.» Trail's proposal, adopted as written: `ClipperPopup({ fields?: { id, label, placeholder? }[] })`, values in the send context as `ctx.fields: Record<string, string>`, not remembered by the base.

## Solution
- `/transport`: `SendOptions.fields?: Record<string,string>` → `SendContext.fields` (present only when given). Fingerprints are untouched: fields are metadata about a send, not part of a unit.
- `/ui`: `ClipperPopup` gets `fields?: ClipperField[]`; renders a labelled text input per field (theme tokens, `data-testid="clipper-field-<id>"`), keeps values in component state only, passes them to `sendClip`.
- Not remembered: no storage key, a fresh popup starts empty — tags for one page are not tags for the next.

## Reuse
- Extends @broberg/web-clipper itself; no new dependency. Input style mirrors @broberg/settings' input (bst-input__field) on the same tokens.

## Design
Guide silent on popups (consulted for F099.6, outcome `silent`); follows the nearest surface, @broberg/settings' text input: label above, full width, theme tokens, focus outline in --accent.

## Scope
### In scope
- `src/transport.ts`, `src/ui.tsx`, `css/clipper.css`, tests, README, 0.2.0 release.
### Out of scope
- Field types beyond a single-line text input (select, checkbox) — ask when a consumer needs one.
- Validation of field values — the destination's job.
- Remembering values — deliberately not.

## Architecture
```ts
interface ClipperField { id: string; label: string; placeholder?: string }
ClipperPopup({ ..., fields?: ClipperField[] })
sendClip({ ..., fields?: Record<string, string> })  →  destination.send(units, { ..., fields })
```

## Stories
- **F099.8** — this card.

## Acceptance criteria
1. A `tags` field renders with `data-testid="clipper-field-tags"`; what the user types reaches `send()` as `ctx.fields = { tags: … }` (strict equality, ui test with a fake destination); without `fields`, `ctx.fields` is absent.
2. Values are not remembered: a fresh popup starts empty and nothing about fields is in storage (read back); mutation: storing the value → red.
3. Released as 0.2.0 via tag `web-clipper-v0.2.0` (Trusted Publisher); clean install: red against 0.1.0, green against 0.2.0; release report to trail and jam.
