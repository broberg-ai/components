# F081.7 — the marker test reads the directory before the file exists

## Symptom

`test.yml` → `root-scripts` red on main at 1b05e9e and b9f19ac (1/10 2026); the same failure once locally on 30/9. Failing checks in `scripts/test-mutation-marker.mjs`, section "the marker during a REAL harness run":

```
✗ it named the harness, the file and the REAL pid   missing: "@broberg/stripe"  in: (empty)
✗ it warned the reader …                            missing: "BROKEN code"      in: (empty)
```

The harness itself passed and the marker was observed to exist. Only the body was empty.

## Cause

`writeMarker()` (scripts/mutation-marker.mjs) is two steps: `mkdirSync(MARKER_PATH)` then `writeFileSync(entryPath(), body)`. The test polls every 50 ms and, the FIRST time the directory exists, sets `seen.existed = true` and reads the marker once. A poll that lands between the two steps reads an empty directory, records `body = ""`, and never reads again. A race in the test, not a defect in the marker: a real reader that looks a moment later sees the full text.

## Fix

Keep polling until a non-empty body has been read (or the harness exits). `existed` still records the first sighting. No change to the marker or the hook.

## Reuse

Test-only change in this repo's own gate. Nothing in Discovery applies.
