# F081.2 — There were ten, not four

**Status:** In progress · **Epic:** F081 · **Written:** 2026-09-01

---

## The claim that was false

F081.1 shipped one hour before this card, and its commit, plan-doc and card
evidence all say **"our four harnesses"**. `git ls-files "*mutations.mjs"` finds
**ten**:

```
packages/{greppable, lens-engine, mail-identity, mail, notifications,
          pwa, secret-scan, stripe, theme, webpush}/test/mutations.mjs
```

I measured the four I knew about and wrote the number as if it were the
population.

**What caught it** is the useful part: the coverage check in
`test-mutation-marker.mjs` was changed from a **hand-written list of four** to
`git ls-files`. It went red immediately, on six files.

A hand-maintained list is a list someone forgets to add to — and this one had
already been forgotten before it was written.

## Two more findings from measuring all ten

### 1 · Six lacked the marker and the read-back

`lens-engine`, `mail-identity`, `notifications`, `pwa`, `theme`, `webpush`. Now
wired to the shared module.

### 2 · Six of ten are run by nothing

| package | `test` script |
|---|---|
| greppable | `vitest run && node test/mutations.mjs` |
| mail | `vitest run && node test/mutations.mjs` |
| secret-scan | `vitest run && node test/mutations.mjs` |
| stripe | `vitest run && node test/mutations.mjs` |
| **lens-engine** | `vitest run` |
| **mail-identity** | `vitest run` |
| **notifications** | `vitest run` |
| **pwa** | `vitest run` |
| **theme** | `vitest run` |
| **webpush** | `vitest run` |

`mail-identity`'s own header states it outright: *"NOT part of the published
package and not run by `pnpm test` — invoke it directly"*. That is the harness
contract's **"tests nothing runs are theatre"**, written down by the author and
then left standing.

**A mutation harness that never runs cannot tell you a decision became
undefended.** It sits there looking exactly like coverage.

### 3 · mail-identity's restore was outside any `try`

`writeFileSync(SRC, original)` sat bare after `failingTests()`. A throw left the
mutant on disk. Fixed, with a per-mutation read-back.

## My instrument was wrong twice while measuring this

Both in the direction that would have produced a **false finding**:

- `grep -c "git.*checkout"` counted **comments**. `theme` and `notifications`
  mention `git checkout` as recovery *advice* in an error message; neither
  restores with it. I nearly filed a defect against two clean harnesses.
- `grep -cE "rev-parse --show-toplevel"` **missed** `greppable`, which passes the
  same flags as an array (`["rev-parse", "--show-toplevel"]`). It reported
  `abs=0` for a harness that does resolve its path absolutely.

Same shape as super's `ps` finding two hours earlier: **a true count answering a
different question.** Third time in one morning.

## The rule that comes out of it

**Discover the population; never list it.** The check stays on `git ls-files`,
with a zero-length guard — because an empty list would pass every per-harness
check that follows it, silently, which is the same failure one level up.

## Not doing yet, and why

**Wiring the six into the gate before running them.** They have never run in CI,
so a stale anchor or an uncaught mutation would turn a gate red on somebody
else's next push — and the first thing anyone does with a gate that fails for a
reason that is not theirs is bypass it. Run first, then wire, or state in the
package why it does not run.
