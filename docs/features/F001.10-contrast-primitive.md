# F001.10 — Every repo measures WCAG by hand, because the shared checker only takes a DESIGN.md

**Status:** Backlog. Small (2 points), and it removes a duplicate rather than adding a feature.

## How this was found

Backfilling the `## Reuse` sections the plan-doc gate had been asking for on nine
documents. The gate flags a missing section as *non-blocking advisory*, which is
exactly why it had been skipped nine times — and running the check properly found
a real gap on the first search.

That is the meta-point worth keeping: the reuse check is not paperwork. Its whole
value is catching the case where a capability exists two directories away and
nobody looked.

## The gap

`@broberg/theme@0.2.0` already contains the correct implementation. Its
`/design-md` entry exports:

```ts
export function checkContrastAA(content: string, required = 4.5): ContrastIssue[]
```

and internally calls culori's `wcagContrast`. So the maths is present, tested, and
shipped.

**But the exported signature takes a DESIGN.md *string*** and measures four
hard-coded token pairs:

| foreground | background |
|---|---|
| `on-surface` | `surface` |
| `foreground` | `background` |
| `primary-foreground` | `primary` |
| `card-foreground` | `card` |

There is no way to ask *"what is the ratio between these two colours?"*. A
consumer whose colours are not design tokens has nothing to call — and that is
most real consumers: a palette passed in as a prop, a pixel sampled off a canvas,
a chart series, a per-region clinical colour.

## What happened as a result

`packages/bodymap/test/contrast.test.ts` carries its own implementation:

```ts
function relativeLuminance(hex: string): number { /* 8 lines of WCAG formula */ }
function contrast(fg: string, bg: string): number { /* ... */ }
```

It is correct. It is also a second implementation of something this monorepo
already owns, in the repo whose entire job is stopping exactly that — and it
guards a surface where AA is a **legal** requirement (fd-sundhed → Aalborg
Kommune). The fleet's accessibility measurement should be one function, not one
per package that happens to care.

## The rule this is an instance of

> *"If the shared package is MISSING something you need: EXTEND it, never work
> around it."*

The workaround already shipped. This card is the migration back.

## Shape

```ts
// @broberg/theme
export function contrastRatio(a: string, b: string): number;
export function meetsAA(a: string, b: string, opts?: { large?: boolean }): boolean;
```

`checkContrastAA` stays exactly as it is, rebuilt on top. It has a consumer
contract and there is no reason to disturb it.

### The one judgement call: `large`

AA is **3:1 for large text** and **4.5:1 otherwise**. A checker that silently
assumes one of them is how a real failure gets signed off, so `large` is an
explicit option and both thresholds are asserted.

bodymap's own test documents why this is not theoretical: its 13.5px hint and
11px bold labels are both *under* the large-text threshold, so neither qualifies
for the 3:1 exception — and someone reaching for a default could easily assume
otherwise about "bold" text.

## Reuse

This card IS the reuse check's output. Discovery searched `contrast`, `wcag`,
`accessibility`; the single hit was `@broberg/theme`, which components owns.
Nothing external is needed — culori is already a dependency of the package.

## Non-goals

- A colour library. No palette generation, no APCA, no auto-correction, no
  "suggest a passing colour". Expose what culori already computes and stop.
- Runtime contrast checking inside components. This is a build/test-time
  primitive; measuring every render would be a cost with no reader.
- Touching the four token pairs `checkContrastAA` checks. Widening that list is a
  separate decision with its own consumers.
