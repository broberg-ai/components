# F081.6 — The guard that catches a killed harness tells you to commit the damage

> Parent: [F081 — Mutation-harness safety](F081-mutation-harness-safety.md) · the hazard [F081.1](F081.1-the-restore-nobody-checked.md) named, met in the wild.

**Status:** Backlog · **Measured:** 2026-09-09, first-hand, in this repo, by me.

## What happened

`pnpm test` was **killed** for low memory partway through. It was inside `scripts/test-mutation-marker-mutations.mjs`, between apply and restore:

```js
230  writeFileSync(m.file, original.replace(m.from, m.to));   // apply
     … run the suite …                                        // ← killed here
235  writeFileSync(m.file, original);                          // restore — never ran
```

So `.githooks/pre-commit` sat mutated for an hour:

```diff
-    started="$(LC_ALL=C ps -o lstart= -p "$1" …)"
+    started="$(ps -o lstart= -p "$1" …)"
```

That is the harness's own mutation #115, *"LC_ALL=C dropped from ps (a Danish-locale date stops parsing)"*, gated on `when: localeChangesPs` — **true on this Mac, false on every CI runner.** Measured here:

```
without LC_ALL=C   "ons.  9 sep. 02:12:24 2026"    ← Danish; the hook's `date -j -f "%a %b %d %T %Y"` cannot parse it
with    LC_ALL=C   "Wed Sep  9 02:12:24 2026"
```

Effect: three checks red in `test-mutation-marker`, and the commit guard could no longer tell *"a harness is still running"* from *"I cannot determine that"* — which is the exact distinction this epic exists to protect.

The harness predicted it, three lines above the code that does it:

> `// A kill skips the restore, and mutated source reads exactly like working source — the whole subject of this card.`

## The part that cost someone else time

I found an unexplained modification to a **git hook**, did not find the mechanism in my own repo, and asked cardmem whether their scaffold owned `.githooks/`. They measured their entire write surface — every path they touch, plus a grep returning zero — to prove it did not.

The answer was in `scripts/` the whole time. I searched for who *else* could have done it before searching for whether *I* had.

That is why this is a card and not a quiet fix: the incident is cheap, the misattribution was not.

## The defect

The guard **does** catch it. Then it gives the opposite of the right instruction:

```
::error::refusing to mutate uncommitted files — commit first.
  M .githooks/pre-commit
```

Follow that literally and you **commit the mutation** — permanently breaking a git hook, in a repo where hooks are security-relevant.

Two states need opposite responses and share one message:

| state | right response |
|---|---|
| you have legitimate uncommitted work in a file the harness mutates | commit it, then re-run |
| a killed run left this file mutated | **restore it** — do not commit |

The harness can tell them apart with what it already knows: it holds every `from`→`to` pair it can apply. If the dirty content matches one of its own `to` values, it did this.

## Why it is the same shape as everything else tonight

Four instances, one evening, three of them mine:

| where | two states, one signal |
|---|---|
| the Stripe monitor's job | crash and "no drift" were both green |
| the seal's check loop | "passed" and "answered nothing" were both a tick |
| the seal's matching | a comment quoting a directive and the directive itself |
| **here** | "your work" and "my leftover mutation" |

And the general lesson, which cardmem put better than I did while we were comparing a different pair: **an explanation must be attached to the thing it explains.** The `LC_ALL=C` comment survived the removal of `LC_ALL=C`, so the file documented a protection it no longer had.

## Design sketch

In the dirty check, compare each dirty path's working-tree content against the `to` side of every mutation registered for that file. A match means we did it. Then:

- **matched** → "a previous run of this harness was interrupted and left `<path>` mutated. Restore it: `git checkout -- <path>`"
- **unmatched** → the existing "commit first" message, unchanged

The negative control matters as much as the fix: a file dirty for an ordinary reason must keep the ordinary instruction, or this trades one always-wrong message for another.

## Reuse

No Discovery check needed — this is a fix inside this repo's own harness tooling, not a capability. `@broberg/greppable` and the other shared guards are unaffected; nothing in the `@broberg/*` inventory owns mutation-harness safety, which is why F081 exists here.

## Non-goals

- **Surviving the kill.** A SIGKILL runs no handler, and pretending otherwise is how you get a cleanup path nobody tests. The fix is to make the *aftermath* unambiguous, not to prevent it.
- Restoring automatically. The harness must not silently revert a file — that is indistinguishable from the damage it is meant to surface, and it could eat real work if the match logic is ever wrong. It tells the human exactly what to run.
- Changing when harnesses run. That is [F081.5](F081.5-a-slow-gate-is-a-bypassed-gate.md).

## Rollout

Internal tooling; no package, no release. Lands with its own test and a mutation proving the two messages cannot collapse back into one.
