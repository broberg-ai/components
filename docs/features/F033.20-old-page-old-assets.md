# F033.20 — Installed apps go white after a deploy: serve old hashed assets from kept deploys

## Motivation
Owner-reported 26/10 (via jam): every installed app on his Mac (HelpDesk, Cardmem, Trail, FD Sport) shows a white screen; Cmd+Shift+R in HelpDesk does not help. Jam, on the same Mac and Chrome, is fine.

Helpdesk measured the mechanism (#5081): the stored page points at `/assets/<hash>.js/css` that the sync deploy removed → 404 → nothing drawn; `location.reload()` can answer from the browser's store with the same stale page. Jam is not hit because its service worker always fetches navigations from the network.

F033.17 (0.7.0) already sends `cache-control: no-cache` on HTML, but a page an installed app (or an app's own service worker) already holds is still the old one. Meanwhile the Fly Live server keeps the last 5 deploy directories on disk — the old assets EXIST — and `serveStatic` only looks in `current/`.

## Scope
In `FLY_LIVE_SERVER` (`src/deploy/fly-live-assets.ts`): when a path is not found in `current/` and it matches the HASHED-asset pattern (the same one that grants `immutable`), look in the kept previous deploys, newest first, and serve the first hit with the immutable headers. Bump `SERVER_VERSION` so running servers auto-update (F033.18).

## Non-goals
- No fallback for unhashed files or routes (an old `robots.txt` must not come back).
- The client-side stale-shell guard helpdesk proposed for @broberg/pwa is a separate story (it also covers non-Fly-Live hosts).

## Architecture
`findInKeptDeploys(rel)`: list `deploys/`, sort descending, skip the current id, `stat` `deploys/<id>/<rel>` with the same path guard as `safeJoin`. Pure fallback; the current deploy always wins.

## Dependencies
F033.17 (cache headers), F033.18 (server auto-update).

## Reuse
Inside @broberg/deploy-core itself; no other shared package owns static serving.

## Rollout
Test + mutations → patch release → every Fly Live app gets the new server on its next deploy → release report → owner checks an installed app after a deploy.
