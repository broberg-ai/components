# F038.48 — The "Just shipped" guard goes red whenever a release lands mid-run

**Epic:** F038 (Discovery) · **Written:** 2026-10-30

## Motivation

While measuring F038.11 the original defect turned out to be gone: since F038.16 the release itself bumps the roster once npm serves the version, and since F038.45 a package published from another repo is a warning. No check-roster-versions red in a release window since 25 Oct.

The same shape moved one guard over. check-featured-fresh.mjs compares npm's newest shipped @broberg/* release with the LIVE hero card. Over the last 40 discovery workflow_run runs: four reds, each with the newest release published minutes before or DURING the run, each green on the next run.

| run | card | newest | published | source |
|---|---|---|---|---|
| 41104681860 (30/10 18:11Z) | cron@0.4.0 | ai-sdk@0.69.1 | 18:12:55Z | another repo |
| 40605719176 (27/10 23:58Z) | lens-daemon@0.1.70 | lens-measure@0.1.4 | 23:51Z | another repo |
| 40549835500 (27/10 17:21Z) | app-shell@0.26.0 | bodymap@0.13.3 | 17:22:06Z | ours, back-to-back |
| 40163947444 (25/10 05:00Z) | pwa@0.8.0 | ui-controls-core@0.3.0 | 05:01:44Z | ours, back-to-back |

A guard red on every busy release day and always fine trains its reader to skip it, and the day the card is genuinely stale looks identical.

## Scope

A pure decision in scripts/featured-verdict.mjs, used by check-featured-fresh.mjs:

- ok (0) — the card names npm's newest.
- stale (1) — RED: newest is ours and its publish run finished before this run started, or GitHub could not be asked.
- pending (3) — newest is ours and its publish run (tag <name>-v<ver>) is running or finished after this run started; that publish triggers its own discovery run, which carries the answer.
- foreign (4) — newest published from another repo; the daily catch-up (F038.44) refreshes it. Same posture as F038.45.

inventory-fresh.yml maps 3 → ::notice and 4 → ::warning (green); 1 stays a failure. live-fresh gains actions: read.

## Non-goals

- No timer, retry or grace period — evidence only.
- check-roster-versions.mjs (F038.11) is not touched.
- How the hero card is generated is not changed.

## Reuse

No @broberg/* package owns CI-guard verdicts; this extends the repo's own script and reuses ownPackages() from scripts/npm-latest.mjs.

## Verification

Unit tests for every outcome including the RED replay of a genuinely stale card and "GitHub could not be asked" → RED; a mutation on the started-before comparison; wired into test:root; a real run of the step against discovery.broberg.ai.
