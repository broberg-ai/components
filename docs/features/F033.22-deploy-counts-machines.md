# F033.22 — Udrulningen tæller maskiner

> **Ordre:** ejeren 1/11 2026, ordret: «JA til alle fire, lås 0.5.1, og tilføj antal maskiner». Og: «hver fly org må kun have 100. Hvad bruger et simpelt website 20 maskiner til?»

## Målt
broberg-discovery havde 20 maskiner (1 kørende, 19 stoppede, alle v691, ingen volumes) — 19 slettet 1/11 på ejerens ord. broberg-jam 6 (5 stoppede). Mønster `[Likely]`: udrulningen ser en ufuldstændig maskinliste (målt: `machine list --json` giver jævnligt for få med exit 0) og laver nye; `auto_stop` stopper de overskydende, så de koster næsten intet men tæller i org-loftet på 100. F033.21's release-tjek fanger det ikke (samme release).

## Rettelse
- Input `expected_machines` (tal, default 0 = tæl og rapportér, ingen fejl — ingen ændring for eksisterende forbrugere). Sat → Machine-verify rød hvis antallet af udrulnings-styrede maskiner (alle tilstande) ≠ forventet, med listen.
- Discovery: `ha: false`, `expected_machines: 1` — et internt site med auto-stop behøver ikke to.
- Besked til BID (3) og jam (2, ejerens ord til jam).

## Ikke i scope
Automatisk sletning af overskydende maskiner (destruktivt — ejerens ord pr. app). Cardmem Operate-overblikket (cardmem, #47278).

## Reuse
Udvider F033.21's Machine-verify-trin og dets tests.
