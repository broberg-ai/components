# F079.8 — Rules that can FAIL: a policy seam over the outgoing stream

> Parent: [F079 — `@broberg/chat`](./F079-chat.md)

Two requests from **fd-sundhed** on 2026-08-27, an hour apart, that turn out to need the **same mechanism**.

## 1. "No diagnoses" must be provable

The guardrail on mockup screens 4 + 4b: an employee writes freely about an injury, the assistant asks one clarifying question at a time and ends in an **action** ("shall I find you a time?"), never in an assessment.

fd-sundhed sharpened why a detector is the wrong build, and their wording is better than ours:

> *«Ingen diagnoser» er ikke en mængde ord — det er en talehandling. Modellen kan overholde reglen i alle de formuleringer nogen har tænkt på og bryde den i den næste, og en detektor der er prøvet på de første ville være grøn.*

A phrase-matcher fails in the **green** direction, which is exactly why it would survive review. So we do not ship one.

They also settled ownership, correctly: **they write the rule, we give it a place to live.** Their wording will be narrower and duller than "no diagnoses" — probably *"must never name a condition"* — **because** it has to be provable. That is the right trade and it is theirs to make.

## 2. "This caller may never leave the EU" must be able to fail

Their own contract says *personal data → Mistral, Paris*. Their point about it is the one worth keeping:

> En kontrakt i CLAUDE.md … **virker for den der læser den.** Vi har ingen test der beviser at en art. 9-sti ikke KAN ende hos en amerikansk model.

And: *a fallback that quietly changes jurisdiction is a fault that by definition is not noticed by the person who causes it.*

### What `@broberg/ai-sdk` already guarantees — read, not assumed

From Discovery, `@broberg/ai-sdk` **v0.28.0**, in the owner's own words:

| | |
|---|---|
| Defaults | Since **v0.21 (F030)** every default tier is **Mistral EU**. Claude is override-only, non-PII. The Anthropic default was phased out. |
| On its own | *"The SDK never leaves the EU on its own — one region, one attempt, tested."* |
| **The hole** | *"**A fallback chain kills the EU route** — a caller-supplied fallback to a US route WILL be taken when the EU call fails."* |
| The sentence that decides this story | *"**A fallback is a route, and it is the ROUTE that decides residency, never the model name.**"* |

**So the hole is not in ai-sdk's defaults — it is in what the CALLER hands it. `@broberg/chat` *is* the caller.** That is why this belongs in the package instead of being re-derived in every repo that mounts it.

> Worth flagging separately: the canonical `## @broberg/ai-sdk` block in our own `CLAUDE.md` still lists `smart`=claude-sonnet, `powerful`=claude-opus, `vision`=claude-sonnet. That is **seven minor versions stale** — F030 phased those defaults out. Nobody is endangered by it (it understates how EU-safe the defaults are), but it is a canonical block copied into every repo, and it is wrong. Filed to ai-sdk.

## The design consequence — why a declaration is not enough

A check that runs **before** the call can only ever assert **configuration**. It reads as enforced and is true by luck. That is this week's recurring shape, one layer down, and we would be building it deliberately.

**The only check that can fail for the right reason reads the route that ACTUALLY answered** — after a fallback has had its chance to fire.

So:

- the injected model must report **provenance per response** (which provider / model / region actually answered);
- the core **refuses to emit text** that came from outside the declared requirement;
- and the abort is a **distinct frame**, not a silent stop — a caller that cannot tell "refused on residency" from "finished" has the same defect one level up.

Same seam serves both rules: the consumer's rule sees the outgoing frames and can **allow, block or rewrite**. One mechanism, two consumers' rules — exactly like the tool registry (shared) versus the tools (per site).

## Sharpened the same day: there must not be a route to detect

> Christian, via fd-sundhed: *"Alle modeller skal anvende Mistral i EU. Hvis en EU model ikke svarer så skal vi selvfølgelig kunne vise en fejl og **IKKE fallback til en US model**."*

This is a stronger requirement than the one asked for above, and the difference is **when it fails**:

| | Fails when | What has already happened |
|---|---|---|
| **Route check** (emit-time) | after the provider answered | the prompt **was sent**, the conversation **has left the EU**; we merely withhold the answer |
| **Configuration refusal** (setup-time) | before anything is sent | nothing left |

So both ship. A caller declared EU-only is **refused at construction** when the injected model attests any route outside the EU, and the route check stays as the net.

**But the authoritative refusal is not ours.** `@broberg/ai-sdk` owns the fallback chain; this package is only the caller, so a construction check here can only ever read an *attestation*. `createAI({ residency: "eu" })` refusing a non-EU fallback at setup is **filed to ai-sdk**, so the net does not become the only guard.

Video (Gemini EU) is out of fd-sundhed's requirement for now — they are not using it initially.

## Christian declined the setup-time barrier — 2026-08-27

ai-sdk put it to him directly rather than acting on it relayed through two sessions. **The answer was no:** the SDK will not refuse a non-EU fallback at configuration time — it is **the caller's** responsibility not to configure one.

**So no construction-time refusal ships here either**, and the reason matters more than the decision: with no `region` to attest, ours could only ever confirm *configuration* while reading as if it proved *residency*. That is exactly the defect class this card exists to prevent, built deliberately.

ai-sdk's own observation, made while delivering a no they disagreed with, is the one to keep:

> A setup-time barrier can only see the chain that was **configured**, never the route that actually replied. Had the answer been yes, **both** would still be needed — otherwise we would merely have moved the fault class into the package: a check that proves configuration and is read as proving residency.

**So the route check is not a net beneath a barrier. It is the half that measures.**

### ⚠️ And the ambiguity is flagged, not resolved by us

His answer reads differently from the quote relayed via fd-sundhed — *"ingen fallback til en US-model."* Both can be true: he may mean *the caller* must not configure one, rather than that a package must enforce it.

ai-sdk has put the discrepancy to him explicitly. **If a correction comes, this plan and its acceptance criteria are rewritten before any code** — nobody builds on the reading they prefer.

## What actually blocks this story now: `region`, and nothing else

Provider and model **are** reportable for the route that answered — `usage.provider`, `usage.model`, stamped only after a successful call, so a fallback route stamps itself. There is even a free fallback detector: `tier` is stamped **only** on the primary route, so a response without one means a fallback fired.

The jurisdiction is not reported. ai-sdk owns it, has it noted as our blocker, and **promises no date**. We do not approximate it locally.

**And the guard must be inert rather than permissive while the field is absent** — an unanswerable question has to read as *unanswered*, never as *compliant*.

## ⚠️ Do not ask `resolveModel` where the data went

fd-sundhed measured `@broberg/ai-sdk` **0.21.1 disagreeing with itself**:

```
resolveModel('smart')      → claude-sonnet-4-6      (aliases, dist/chunk-IT7HNKLY.js)
ai.chat({ tier: 'smart' }) → mistral-large-latest   (DEFAULT_TIER_MAP, dist/index.js)
```

Same word, two answers, **and one of them is outside the EU**. `pricing.ts`'s comment is stale in the same direction.

This is worse than the stale CLAUDE.md block noted above — that is a text, **this is code contradicting code**, and the lookup that disagrees is exactly the one a sensible person would reach for to *display* which model is running. `@broberg/chat` will not derive or show a model or a residency from the registry; the only trustworthy answer is what the response itself reports. Reported to ai-sdk.

## ai-sdk answered, and it moved the blocker — 2026-08-27

**The prerequisite below is answered YES, and it changes what this story blocks on.**

> *"`usage.provider` = the adapter's own name, `usage.model` = `spec.model` for the route that ran. `runCapability` stamps only AFTER a successful call, so a fallback route stamps itself."*

So the route that **actually answered** is reportable today. Two consequences:

1. **The emit-time route check can be built now.** It is not waiting on anything.
2. **A free fallback detector exists.** `tier` is stamped **only on the primary route** — `enrich(…, i === 0 ? opts.tier : undefined, …)` — so *a response with no `tier` means a fallback fired*. No new field required.

**But there is no `region`.** Provider and model are true about the route; residency has to be derived from them. **That is the real gap, and it is what this story blocks on — not provider/model.** Deriving it here would mean a provider→jurisdiction table inside `@broberg/chat`, which this card's own constraints forbid, and rightly: that table would be a guess maintained in the wrong repo.

`createAI({ residency: "eu" })` refusing a non-EU fallback **at setup** does not exist either. ai-sdk agrees with the argument and has taken it to Christian as a product decision about the SDK's contract, rather than acting on it relayed through two sessions. Nothing here is built on a guess about the answer.

### The registry defect is fixed, and how it survived is the useful part

ai-sdk fixed the tier disagreement in `9c0d2ac` on main — **not yet published** — by *deleting the second list*: tier aliases are now derived from `DEFAULT_TIER_MAP`, so the router decides and the registry follows. It was **worse than fd-sundhed reported**: `cheap` and `vision` were not in the registry at all, so `resolveModel('vision')` returned the string `"vision"` as a model id, with `ok: true`.

> **A success-shaped non-answer.** A consumer gating on `ok` — exactly as the fleet CLAUDE.md instructs — passes it through and sends `"vision"` to a provider as a model name. cms had fixed the identical shape in `@broberg/mail` the same morning, where four different causes all returned `{ok:true, skipped:true}` and an invitation reported "sent" about a mail that was never sent.

And the two reasons it survived three months, in ai-sdk's own words:

- **A test held the defect in place** — `expect(canonicalId("powerful")).toBe("claude-opus-4-8")`. A test that encodes the bug cannot report it.
- **Their first guard was not load-bearing, and they measured that rather than assuming it.** They could not make it fail: setting `smart` back to Claude by hand left the test green, because the seeding let the last writer win and the order happened to save it. The replacement records the conflict and fails on it (mutated: 12 pass → 11 pass / 1 fail).

**The standing rule here is unchanged:** nothing in `@broberg/chat` derives or displays a model or a residency from the registry.

`0.29.0` is now on npm with the tier fix — verified against `npm view`, not against a green workflow — and it adds `resolveModel(id, { requireKnown: true })`, so an untracked id returns `ok:false` **with a reason** instead of `{ok:true, model:"<your own string>"}`, and an unknown model reports `status:"unknown"` rather than a fabricated `"suspended"`. Useful, and still not a residency source: **there is no `region` in it.**

## The prerequisite, and it is not ours to guess

**Can `@broberg/ai-sdk` report, per response, which provider/model/region actually answered — including after a fallback fired?**

If it cannot, that is a **gap to file against ai-sdk** (extend it, never work around it), not something to approximate here. Asked before any code; their answer goes in this file verbatim.

## Why the core already permits this without a shape change

`run()` yields an async iterable, so a policy is a transform over it. Nothing in F079.1 forecloses this, and nothing was built for it speculatively — which is the whole reason this is a card in Backlog rather than code that shipped today.

## Non-goals

- **No detector.** No word-list, no phrase-matcher, no clinical vocabulary in the package.
- **No jurisdiction table** baked into `@broberg/chat`. The route reports; the consumer declares; the package compares.
- Not a moderation product. This is a seam, not a policy library.
