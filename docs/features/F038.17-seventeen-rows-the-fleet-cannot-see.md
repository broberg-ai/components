# F038.17 — 17 inventory rows never reach the surface the fleet is told to read first

**Status:** In progress · **Epic:** F038 (Discovery) · **Written:** 2026-09-08
**Ordered by:** Christian, 2026-09-08 — «byg de 17 usynlige rækker»

## Motivation

`CLAUDE.md` orders every session in ~30 repos to do this **before wiring any
cross-cutting capability**:

> **Browse the whole map FIRST — one fetch:** `GET https://discovery.broberg.ai/ai`

Measured 2026-09-08, in production:

```
inventory rows total                    71
rows with no `pkg` field                17
of those, appearing in /llms.txt         0
```

`scripts/build-onboarding.mjs:28` — `.filter((x) => x.pkg)`. One clause, and it
drops a quarter of the inventory from `/ai`, `/llms.txt`, `/llms-full.txt` and
`/onboarding`. Confirmed live, not in build output: `curl /llms.txt | grep -ci
podcast` → **0**, while `/api/search?q=podcast` → 1.

So the surface whose entire job is answering *"do we already have something that
does X?"* has been answering for the npm-shaped quarter of the question.

## What the 17 actually are — and why "just show them" is the wrong fix

| status | n | what it means |
|---|---|---|
| `planned` | 15 | does not exist yet |
| `moved` | 1 | F027 → became upmetrics |
| `shipped` | 1 | `cms-podcast` — real, usable, just not an npm package |

**Listing all 17 as available would be the worse defect.** A row that reads like
a capability you can use, for something that does not exist, is the webpush
precedent: *a roster naming something nobody can install is worse than one that
is merely behind.* `@broberg/mail-identity` is deliberately absent from the
roster today for exactly this reason.

But silence is not right either. A session searching for "podcast manager" gets
nothing back and concludes the fleet has nothing — when in truth it is **planned,
owned by cms**, and the right move is to talk to them rather than build a second
one. That is the reuse this whole repo exists for, lost to a filter.

## Scope

**Three states in the map, not two** — the same rule buddy landed on for
`ask_peer` and `secret-scan` for `scanned`:

1. **Shipped, npm** — unchanged. `npm i @broberg/x`.
2. **Shipped, not npm** (`cms-podcast`) — listed in the same map, in a section
   that says plainly there is nothing to install and names how to reach it.
3. **Planned / moved** — a separate, clearly-labelled section: name, owner, and
   the explicit sentence that it **does not exist yet**, so the reader talks to
   the owner instead of either using it or re-building it.

### Non-goals

- Not touching `oneLiner`, the 150-char cap, or any existing package row.
- Not adding planned items to `/api/packages` — that endpoint means *installable*.
- Not inventing a new field. Status already exists on every row.

## Reuse

Nothing to reuse — this is Discovery's own generator, in the repo that owns it.
Checked: no `@broberg/*` package renders inventory surfaces.

## Acceptance criteria

1. All 17 currently-invisible rows appear in `docs/llms.txt`. Asserted by name,
   per row, not by a count — a count passes if 17 of the wrong rows appear.
2. Every `planned`/`moved` row carries an explicit not-yet-built marker **in the
   same line as its name**, so a reader who skims one line cannot mistake it for
   something available. Asserted per row.
3. **No planned row appears in `/api/packages`.** That endpoint means
   installable, and this card must not widen it. Asserted against the live route.
4. Package rows are byte-identical to before, apart from the new sections —
   proven by diffing `/llms.txt`'s package block before and after.
5. A guard fails if someone re-adds a `pkg`-only filter, or if the invisible-row
   count in `llms.txt` ever returns to zero. **Proven RED by mutation** before
   being trusted.
6. Verified LIVE after deploy, not in build output: `curl /llms.txt` contains
   `cms-podcast` and at least one planned row with its marker.
