# F038.17 — 17 inventory rows never reach the surface the fleet is told to read first

**Status:** Done · **Epic:** F038 (Discovery) · **Written:** 2026-09-08
**Ordered by:** Christian, 2026-09-08 — «byg de 17 usynlige rækker»

## Motivation

`CLAUDE.md` orders every session in ~30 repos to do this **before wiring any cross-cutting capability**:

> **Browse the whole map FIRST — one fetch:** `GET https://discovery.broberg.ai/ai`

Measured 2026-09-08, in production:

```
inventory rows total                    71
rows with no `pkg` field                17
of those, appearing in /llms.txt         0
```

`scripts/build-onboarding.mjs` — `.filter((x) => x.pkg)`. One clause, and it drops a quarter of the inventory from `/ai`, `/llms.txt`, `/llms-full.txt` and `/onboarding`. Confirmed live, not in build output: `curl /llms.txt | grep -ci podcast` → **0**, while `/api/search?q=podcast` → 1.

So the surface whose entire job is answering *"do we already have something that does X?"* has been answering for the npm-shaped quarter of the question.

## What the 17 actually are — and why "just show them" is the wrong fix

| status | n | what it means |
|---|---|---|
| `planned` | 15 | does not exist yet |
| `moved` | 1 | F027 → became upmetrics |
| `shipped` | 1 | `cms-podcast` — real, usable, just not an npm package |

**Listing all 17 as available would be the worse defect.** A row that reads like a capability you can use, for something that does not exist, is the webpush precedent: *a roster naming something nobody can install is worse than one that is merely behind.* `@broberg/mail-identity` is deliberately absent from the roster today for exactly this reason.

But silence is not right either. A session searching for "podcast manager" gets nothing back and concludes the fleet has nothing — when in truth it is **planned, owned by cms**, and the right move is to talk to them rather than build a second one. That is the reuse this whole repo exists for, lost to a filter.

## What shipped

**Three states in the map, not two** — the same rule buddy landed on for `ask_peer` and `secret-scan` for `scanned`:

1. **Shipped, npm** — unchanged. `npm i @broberg/x`.
2. **Shipped, not npm** (`cms-podcast`) — listed in the same map, in a section that says plainly there is nothing to install.
3. **Planned / moved** — a separate, clearly-labelled section: name, owner, and the explicit statement that it **does not exist yet**, so the reader talks to the owner instead of either using it or re-building it.

The marker sits on the **same line as the name**, deliberately: a reader who skims one line must not be able to mistake a plan for a capability.

Both the machine map (`/llms.txt`, `/llms-full.txt`) and the **human page** (`/onboarding`) carry it.

## Three findings from the review gate, all mine

**1. The AC was narrower than the defect.** This plan-doc named four affected surfaces; the acceptance criteria covered `llms.txt` alone. So the first cut shipped with `/onboarding` at 0 of 17 and every check green — with a mutation-proven guard on top, which is what made it look finished. The guard now asserts **both** surfaces.

**2. The badge wrapped to three lines.** `.v` had no `white-space:nowrap`. The rule had been in the page for months and was never exercised, because the only thing it had ever held was a version string — `v0.7.0` cannot wrap. This card put words in it.

**3. Seven of seventeen cards described themselves.** `oneLiner()` falls back to `nm` when `desc` is thin, and a planned row's desc *is* thin: "PWA setup" → "PWA setup". Not fixed by writing descriptions — desc text is the **owner's** to write — but by suppressing a line that pretends to be one.

## Non-goals

- Not touching `oneLiner`, the 150-char cap, or any existing package row.
- Not adding planned items to `/api/packages` — that endpoint means *installable*.
- Not inventing a new field. Status already exists on every row.

## Reuse

Nothing to reuse — this is Discovery's own generator, in the repo that owns it. Checked: no `@broberg/*` package renders inventory surfaces.

## Acceptance criteria

1. All 17 currently-invisible rows appear in `docs/llms.txt`, asserted by name per row — a count passes if 17 of the wrong rows appear.
2. Every `planned`/`moved` row carries an explicit not-yet-built marker in the same line as its name.
3. **No planned row appears in `/api/packages`.** That endpoint means installable, and this card must not widen it.
4. Package rows byte-identical to before, apart from the new sections.
5. A guard fails if someone re-adds a `pkg`-only filter, or if a row goes missing from **either** surface. Proven RED by mutation.
6. Verified LIVE after deploy, not in build output.

All six met. Guard: `scripts/check-nonpkg-rows.mjs`, in `pnpm test` and in the CI `check` job the deploy `needs`. Four mutations across two rounds, all killed.
