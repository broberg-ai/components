# F081.3 — The liveness check only works on my Mac

**Status:** In progress · **Epic:** F081 (mutation-harness safety) · **Written:** 2026-09-01

## What happened

Publish run `33489536202` (tag `mail-v0.10.0`) went red on `gate / workspace`, and
every one of the 39 publish jobs was skipped. The gate did its job: nothing
shipped from a red tree. But the red was mine, and it was two lines long:

```
✗ a LIVE pid reads as still running, and says to wait
✗ a pid REUSED by another process reads as stale, not as still running
```

Both fell into the same branch — *"pid EXISTS, but I could NOT check it is the
same process (start time unreadable)"*.

## Cause

`.githooks/pre-commit` layer 0 (F081.1) converts two timestamps to epoch seconds:

```bash
marker_epoch() { LC_ALL=C date -j -u -f "%Y-%m-%dT%H:%M:%S" "${1%%.*}" +%s 2>/dev/null; }
proc_epoch()   { LC_ALL=C date -j    -f "%a %b %d %T %Y"    "$started" +%s 2>/dev/null; }
```

`date -j -f` is **BSD**. The CI runner is Ubuntu, where `date` is GNU and wants
`-d`. Measured on this Mac, the two dialects are mutually exclusive:

```
lstart: [Tue Sep  1 11:02:57 2026]
GNU date -d  : date: illegal option -- d      (exit 1)
BSD date -j  : 1788253377
```

So on Linux **both** conversions return nothing, `m` and `p` are empty, and every
live pid — recycled or not — lands in the "could not check" branch.

## Why this is the epic's own failure, not a portability nit

The hook fails **safe**: it blocks the commit and says in as many words that it
could not check. No secret slipped through, no mutant was committed, and the red
gate stopped the release rather than letting it out.

But this epic exists because *a check that cannot tell "nothing is wrong" from
"I did not look" always reads as the reassuring one*. The four-state design was
the answer to that. On the platform CI actually runs on, those four states are
one state wide — and I built it, tested it on the one OS where it works, and
called it done. The instrument I built against this failure had the failure in it.

## Fix

One helper per timestamp, GNU dialect first, BSD as fallback. Ordering matters
only for tidiness — on each platform exactly one branch can succeed, and the
other exits non-zero without output.

```bash
marker_epoch() {                       # ISO-8601 from the marker entry
  LC_ALL=C date -u -d "${1%%.*}Z" +%s 2>/dev/null && return 0
  LC_ALL=C date -j -u -f "%Y-%m-%dT%H:%M:%S" "${1%%.*}" +%s 2>/dev/null
}
proc_epoch()   {                       # `ps -o lstart=` -> epoch
  started="$(LC_ALL=C ps -o lstart= -p "$1" 2>/dev/null | sed 's/^ *//;s/ *$//')"
  [ -n "$started" ] || return 1
  LC_ALL=C date -d "$started" +%s 2>/dev/null && return 0
  LC_ALL=C date -j -f "%a %b %d %T %Y" "$started" +%s 2>/dev/null
}
```

`LC_ALL=C` stays on **both** `ps` and `date`, and is still load-bearing: on a
Danish-locale Mac `ps -o lstart=` prints `tir.  1 sep.` and neither dialect
parses it. That was measured in F081.1 and has not changed.

## Reuse

`discovery.broberg.ai/api/search?q=cross-platform date parsing` and
`?q=process liveness` return nothing that owns this. Correct: it is nine lines
inside one repo's git hook, and the only thing "shareable" about it is a fact,
not a module — **`date -j -f` is BSD, `date -d` is GNU, and no machine speaks
both.** A package for that would be a dependency where a comment does the job.

**Reused from inside this repo:** the four-state design and the marker contract
come from F081.1 unchanged; this card only makes the states reachable on Linux.

**The thing worth propagating is the SKIPPED outcome, and it is a pattern, not
code.** A check whose precondition does not hold on this machine must report
"not measurable here" as its own outcome — never merge with "measured, nothing
wrong". Any fleet repo whose harness has a platform-, locale- or
network-dependent case has the same hole. Filed as a fleet note rather than a
package, because the value is one sentence and a package would be five files
around it.

## Non-goals

- **Do not weaken the two assertions.** They are correct; they found a real hole.
  A red test means the wire is broken.
- No `/proc/<pid>/stat` path. It is Linux-only, so it would need the same
  two-branch structure while being harder to read.
- No new dependency, and no Node rewrite of a hook that must run before Node is
  guaranteed present.

## Verification

The Linux half **cannot be proven from this machine.** macOS proves the BSD
branch and that the GNU-first ordering does not break it; only a green
`gate / workspace` run proves the other. The run id goes on the card — an
argument that it "should work now" is not evidence.

One assertion is added, and it is the general one: the epoch helpers must return
a **number** for the test's own pid on whatever platform the test is running on.
That turns "this OS has no working dialect" from a silent slide into the
could-not-check state into a red line naming the cause.

## Consequence

This is what blocked `@broberg/mail@0.10.0` (F005.13). That release is finished
and correct; it is waiting on a green gate, not on more work.
