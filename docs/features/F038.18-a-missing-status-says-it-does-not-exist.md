# F038.18 — a missing status renders as NOT BUILT YET

**Status:** Ready · **Epic:** F038 (Discovery) · **Written:** 2026-09-14

## Motivation

Christian asked for a roster row for voice-engine. The row was written from the
owner's own words and landed here:

```
## Planned — NOT BUILT YET (17)
- **voice-engine — speech, voices & who-spoke-when** (L3) · ⛔ NOT BUILT YET (planned)
  — nothing to install, nothing to import · owner: voice-engine
```

That is false. cardmem runs real meetings through voice-engine today. The row was
not the problem.

### Measured, 2026-09-14

```
non-package rows                18
rendered "⛔ NOT BUILT YET"      17
  ...carrying an `s` field        1   (F027, s:"moved")
  ...with NO status at all       16
```

`scripts/build-onboarding.mjs:56`

```js
status: r.s || "planned",
```

A missing value becomes a confident claim. Line 377 then renders it:

```
⛔ NOT BUILT YET ({status}) — nothing to install, nothing to import
· owner: {owner} — ASK THEM before building a second one
```

### The entry contradicts itself in two consecutive lines

This is why it survived: every reader saw the half that was right.

```
- **Trail — second-brain / RAG** (L3) · ⛔ NOT BUILT YET (planned) —
  nothing to install, nothing to import · owner: trail
  The fleet's cross-session second-brain + RAG … Save to it / search it via
  buddy's trail_save / trail_search MCP tools
```

The label says there is nothing to import. The line under it names the two verbs
you import it with.

### Why this is the expensive direction

F038.15 fixed a surface that **understated** what it held — a reader who followed
it got less than there was, and paid one extra fetch. This one tells a reader a
capability **does not exist**. The cost is a rebuild of something we already run,
by a session that will never learn it had an alternative: it asked, and it was
told no.

Same family as the rest of the week — an absence is not a zero, and a two-valued
channel cannot carry three states. The channel here is a status string; the third
state, *nobody has said*, is being rendered as the more alarming of the two it has.

## Scope

1. **The renderer stops inventing a status.** No `|| "planned"`. A row with no
   `s` renders as an explicit unknown, visibly distinct from both shipped and
   not-built, and never carries "nothing to install, nothing to import".
2. **A seal**, proven red first: restore the default and the check fails, naming
   the line.
3. **Triage all 17 with their owners.** A status is the owner's to give.
4. **A mechanical contradiction check**: a NOT-BUILT label above a description
   that names an endpoint, an MCP verb, an image ref or an install line is a
   failure of the build.

### Non-goals

- **Not** marking everything shipped. F009, F021, F030 and others are genuinely
   planned patterns; flipping them inverts the same defect and sends a reader to
   install something nobody built.
- **Not** deriving a status by reading an owner's repo. A recent commit proves
  activity, not that a capability is callable by someone else. Four rows are
  named above on evidence; the rest wait for their owners.
- **Not** touching the npm-package rows. They carry `s` and `ver`, and the
  roster-vs-npm check already guards them.

## Reuse

Discovery reuse check run against `discovery.broberg.ai/api/search` for
"inventory status", "roster", "catalogue": no `@broberg/*` package owns roster
rendering. `scripts/build-onboarding.mjs` and `scripts/inventory-data.mjs` are
this repo's own single source and the only consumers. Nothing to adopt; nothing
to extract — the fix is local to the generator that produces our own surface.
