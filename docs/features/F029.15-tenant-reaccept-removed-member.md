# F029.15 — @broberg/tenant: a removed member can re-join with their old, used invitation

Parent: F029 (@broberg/tenant). Security finding from mailworker (intercom #52845; cardmem's review of mailworker, run 01a1fba5, finding H1).

## What is wrong (confirmed in packages/tenant/src/index.ts, acceptInvite)
When `invite.usedAt` is set and `invite.usedBy === user.id`, the code calls `store.addMembership(membership)` again — "heals a half-finished earlier accept". It checks neither that the invite has expired nor that the membership still exists. So a user an admin has removed re-creates the membership, with the old role (admin included), with no time limit.

## Fix (proposal, owner may overrule)
1. Expiry is checked before the reuse branch.
2. Reuse of a used invite is idempotent only while the membership still exists (return it, write nothing); if it is gone, refuse with `used`.
3. The one legitimate case — a crash between `markInviteUsed` and `addMembership` — heals only inside a short, named window after `usedAt` (HEAL_WINDOW_MS). The window is a security/usability trade-off and is documented in the README.

## Proof
A test that is red today (accept, remove, accept again), the cases above, three mutants (drop the membership check, drop the window, move the expiry check), the hono route answering the same, and a release report to every consumer because behaviour moved (D-b7eb14).
