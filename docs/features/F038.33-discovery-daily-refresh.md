# F038.33 — Discovery opdaterer sig selv hver dag

## Hvorfor
Christian 23/10 2026: «Lav et cronjobs job der kører automatisk og henter data fra alle repo for at opdatere dine data.»

Målt samme aften: flåde-scannet (hvem bruger hvilke pakker) kører allerede dagligt i GitHub Actions (`fleet-deps.yml`, 04:17 UTC) og committer når grafen ændrer sig, hvilket udløser en udrulning. Men npm-data (udgivet, Trusted Publisher; F038.31) hentes kun når siden bygges — en pakke udgivet fra et andet repo (ai-sdk, lens, …) vises derfor først ved næste udrulning. Og discovery-workflowets stifilter (`inventory-fresh.yml`) kender ikke aftenens nye moduler.

## Scope
- `schedule` (dagligt, efter fleet-deps) + `workflow_dispatch` på discovery-workflowet; en ikke-push-kørsel udruller allerede uanset stier.
- Stifilteret udvides med `scripts/site-chrome.mjs`, `scripts/npm-meta.mjs`, `docs/npm-meta.json`, `data/fleet-deps.json`.

## Valg af ur
GitHub Actions-schedule, samme som fleet-deps: $0 og kræver ingen vågen session eller Mac (F083-constraint). cronjobs.webhouse.net + buddy er vejen når en SESSION skal vækkes for at træffe beslutninger; her er der ingen beslutning at træffe.

### Non-goals
- Hyppigere end dagligt.

## Reuse
Intern CI.

## Rollout
Commit → manuel workflow_dispatch → mål live → næste morgen: planlagt kørsel grøn.
