# F007.18 — renderConsent får { request, sub } og må være async

> **Udløser:** jam intercom 3743, 22/10 2026. Blokerer et ejer-godkendt mockup i jam (mockup 01a160d7 v2, kort jam-F005.9): Jams egen samtykkeside viser den indloggede bruger (navn, mail, profilbillede) og er på brugerens eget sprog (gemt i en cookie).
> **Status:** backlog — ikke bygget.

## Problemet

`renderConsent?: (info: ConsentInfo) => string` (src/oauth-web.ts) kaldes synkront med kun `clientName, redirectHost, scopes, action, fields, lang`, hvor `lang` er en fast `consentLang`. Siden kan derfor hverken vide hvem der er logget ind eller læse brugerens sprog.

## Valgt form

```ts
renderConsent?: (info: ConsentInfo, ctx: { request: Request; sub: string }) => MaybePromise<string>;
```

- `request` er den indkommende `/authorize`-Request (cookies, Accept-Language).
- `sub` er præcis det forbrugerens `authorize`-callback lige returnerede — appen slår selv brugeren op.
- Resultatet awaites, så opslaget i appens database kan være asynkront.

**Fravalgt:** et frit `consent?`-felt på `AuthorizeDecision` (brugerdata ville så skulle hentes i callbacken og sendes gennem pakken — to steder at lede); en `AsyncLocalStorage`-omvej hos forbrugeren (jam har selv afvist den).

## Non-goals

- Standardsiden (`renderConsentPage`) ændres ikke.
- Samtykke-tokenet og flowet fra F007.14 ændres ikke.

## Sikkerhed

Intet nyt indhold når browseren uden om appens egen funktion; `sub` kommer fra callbacken, ikke fra requesten. Kaster appens funktion, svarer `/authorize` med fejl og udsteder ingen kode.

## Rollout

Minor-version af `@broberg/mcp`, release-rapport til jam (porter mockuppen ovenpå).

## Reuse

Hører i `@broberg/mcp/oauth-web`. Ingen ny afhængighed.
