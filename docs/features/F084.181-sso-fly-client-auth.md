# F084.181 — @broberg/sso: login uden hemmelig nøgle (Fly OIDC som klient-bevis)

> **Udløser:** bid intercom 3890, 22/10 2026. BID's F084.180 «login uden hemmelig nøgle» er i drift (ea5a846, ship dark).
> **Status:** backlog.

## Hvad BID allerede kan

En app på Fly bytter sin authorization code på `/oauth2/token` uden `client_secret` ved at sende

```
client_assertion_type=urn:broberg:params:oauth:client-assertion-type:fly-oidc
client_assertion=<Fly OIDC-token med aud = https://id.broberg.ai/oauth2/token>
```

`aud` er token-ENDPOINTET (ikke issuer), så et billet-token ikke kan genbruges som login-bevis. Klienten står hos BID til `token_endpoint_auth_method: fly_oidc` og er bundet til præcis én Fly-org og -app.

## Hvad der bygges

`ssoRoutes({ …, clientAuth: "fly" })` (kerne + Hono-adapter): ved token-udvekslingen hentes et Fly OIDC-token fra Fly's lokale endepunkt med `aud` = BID's token-endpoint, og det sendes som `client_assertion` i stedet for `client_secret`. Genbrug `TicketClient`-mekanismen (den henter allerede Fly-tokens), men med en anden `aud`.

- Standard (`clientAuth` udeladt eller `"secret"`) er uændret.
- Ingen tavs fallback til `client_secret`: fejler Fly-tokenet, fejler login (ét browsersvar, navngiven årsag i loggen — D-2e7f7e).

## Hvorfor det er værd at gøre

En `client_secret` er en hemmelighed der kan lække og skal roteres. Med Fly-identiteten beviser appen sig selv med noget kun dens egen maskine kan få udstedt, og hemmeligheden kan slettes.

## Rollout

Minor-version af `@broberg/sso`. Release-rapport til BID og alle kendte forbrugere før nogen bedes opgradere (D-4d0783). BID slår den første app om (cms-fysio-work eller beacon), et login måles, og først derefter slettes appens hemmelighed.

## Reuse

Hører i `@broberg/sso`; genbruger dens Fly-token-hentning. Ingen ny afhængighed.
