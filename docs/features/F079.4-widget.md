# F079.4 — The widget, and an honest note about when to build it

> Parent: [F079 — `@broberg/chat`](./F079-chat.md)

## What it is

The visible chat surface, for React (Stack A) and Preact (Stack B): streaming bubbles, **handoff to a human**, a feedback prompt (*"was that what you were looking for?"*), transcript download, unread badge, expand, and source-citation badges that **default off**. The Dinero surface from Christian's six screenshots, generalised.

## ⚠️ Neither of the two consumers who are waiting needs it

This is the finding, and it should decide the order rather than be discovered halfway in.

| Consumer | Their surface | Needs the widget? |
|---|---|---|
| **cms** — first consumer, Christian's decision | Their admin chat already has a UI (`chat-interface.tsx`). They are swapping the **engine**. | **No** |
| **fd-sundhed** — first customer | Admin chat inside their own `AdminShell`, their own components. | **No** |

Both need the **engine** — core, adapters, retriever, and history management — plus `@broberg/chat/client` to read the stream into their own UI. All of that exists except [F079.9](./F079.9-history-management.md), **which is the one cms explicitly cancelled their temporary floor for and is now waiting on.**

**The widget serves the surfaces that come later:** Eir's replacement (a public visitor chat) and the employee chat on mockup screens 4 + 4b. Both are after the admin chats prove the module.

So: worth building, worth building **well**, and not the thing that unblocks anybody today. Written down so the sequencing is a decision rather than an accident.

## The one part that is not "just UI"

**`@broberg/chat/client` has no stall detector.** It reads SSE with zero dependencies and waits patiently forever.

> A stream that stops silently is indistinguishable from a slow answer.

That sentence is already in our own README, about somebody else's bug. It is also true of our client — and trail's engine 502'd to its own health endpoint for **~75 minutes** the night this was written, so it is measured rather than imagined.

The widget therefore uses **`@broberg/seti-client/sse`** for the half-open-stream watchdog rather than re-rolling one — the fleet rule, and this is exactly the primitive it exists for. A stalled stream must surface a **distinct state**, never an answer that simply never arrives.

## Handoff is built first

It is what sanne missed most, and it is the control that makes every other failure survivable: when the assistant cannot help, the visitor reaches a **person** instead of retrying. Routed through `@broberg/notify`, never a hand-rolled webhook — and a failure to notify is surfaced to the visitor rather than swallowed.

## Decisions carried in from the survey

- **Citations default OFF.** Eir's prompt *forbids* citing so it sounds like Sanne remembering rather than a database looking up; Dinero deliberately cites. Both are right for their own product, so it is a switch — with the reason recorded so nobody "fixes" it later.
- **The transcript download gives the user what they SAW, not what the model saw.** If compaction shrank what was sent, the download still holds the original turns verbatim. cms's rule; conflating the two deletes people's work in good faith.
- **The unread badge counts what ARRIVED while the panel was closed**, taken from the frame stream rather than from the component's own state. A count that can only agree with itself is not a count.

## House rules that apply without being asked

Every interactive element gets a semantic `data-testid` (that is what lets Lens drive it at all) and **real feedback** — `:hover`, `:active`, a loading indicator past 100 ms, a post-action confirmation, an error state. **No native dialogs or native controls**: no `alert`/`confirm`/`prompt`, no bare `<select>`, no native date or colour input.

React and Preact are **one implementation over one shared table of cases**, the same way `/next` and `/hono` are — *fix one half of a pair* is a measured fleet defect. Both are `peerDependencies` with `>=` ranges, never carets, and the package still declares no runtime dependency of its own.

## Non-goals

- Not a design system. It renders with the consuming site's tokens.
- Not live-support tooling. Handoff means *reaching* a human, not an agent inbox with queues.
- Not the engine. Everything it shows comes from the frame stream.
