# F103.5 — @broberg/realtime: en libsql-/polling-bus

**Bestilt af:** helpdesk (#4643, 25/10 2026). Ligger i Backlog under F103 og bygges når helpdesk skal på flere maskiner.

## Motivation
realtime har to busser: `memoryBus` (én maskine) og `postgresBus` (flere maskiner via LISTEN/NOTIFY). helpdesk kører libsql/sqld og har ingen Postgres. Målt 25/10: deres API kører på én maskine, så memoryBus er korrekt nu — men den dag de skalerer, når hændelser ikke på tværs af maskiner, og det fejler tavst.

## Scope
`libsqlBus(client, { pollMs?, retentionMs? })` med samme kontrakt som de to andre busser:
- publish → INSERT (kanal, type, id, data) med seq tildelt af databasen (autoincrement), ikke af klokken.
- subscribe → poll `seq > sidst sete`, lever i rækkefølge.
- egen hub får hændelsen præcis én gang (gennem bussen, som i dag — aldrig både lokalt og via bussen).
- oprydning efter `retentionMs`.

## Non-goals
- Erstatte postgresBus.
- LISTEN-lignende push på libsql (findes ikke).
- Bygge det før helpdesk har brug for det.

## Arkitektur
```
hub A publish ─► INSERT row (seq) ──┐
                                     ├─► poll seq>last ─► hub A, hub B ─► deres strømme
hub B publish ─► INSERT row (seq) ──┘
```

## Reuse
Discovery: realtime er selv flådens realtidspakke (F103); ingen eksisterende libsql-bus. Genbruger `RealtimeBus`-kontrakten og postgresBus' testsuite («several machines»). Klienten gives ind af forbrugeren (ingen ny dependency), som postgresBus får `sql`.

## Rollout
Minor-version af realtime. Release-rapport (D-b7eb14) til helpdesk + jam. helpdesk verificerer på to maskiner.
