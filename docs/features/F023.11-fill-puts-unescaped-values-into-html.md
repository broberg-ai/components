# F023.11 — `fill()` puts unescaped values into HTML

**Status:** Ready · **Epic:** F023 (`@broberg/mail-core`) · **Written:** 2026-09-03

## Proven

Against the built package, 3 September 2026:

```js
fill("<p>Hej {name}</p>", { name: '<a href="https://phish.example">Log ind</a>' })
// <p>Hej <a href="https://phish.example">Log ind</a></p>
```

The anchor is in the mail.

```ts
/** Replace {token} placeholders with values. Unknown tokens are left as-is. */
export function fill(template: string, vars: Record<string, string | number>): string {
  return template.replace(/\{(\w+)\}/g, (_, key) => (key in vars ? String(vars[key]) : `{${key}}`));
}
```

## Why this is worse than F023.9, which is why it is filed higher

A brand colour is normally a constant in a config file, and only becomes
attacker-influenced in a multi-tenant deployment. **`vars` is dynamic by
definition** — it is the customer's name, the booking reference, the message they
typed. Every value that reaches `fill()` is exactly the class of data that must be
escaped, and none of it is.

And the consumer is already on its way: **cardmem is building the mail template
store this week**, and the F023 epic brief names `{{token}}` substitution as its
core mechanic. `fill()` is the function they will reach for.

## The docstring is half the defect

> *Replace {token} placeholders with values. Unknown tokens are left as-is.*

It says nothing about escaping. `escapeHtml` and `escapeAttr` sit **forty lines
up in the same file** — so a reader who sees them concludes this package thinks
about escaping, and the silence here reads as *"not needed"* rather than *"not
done"*. Silence next to visible care is worse than silence alone.

## Reuse

Discovery checked (`?q=escape+html`, `?q=template+token`, `?q=sanitize`).
`@broberg/cms-inline-edit` sanitises rich-text HTML for a browser and
`@broberg/secret-scan` redacts credentials from text — neither is an HTML-escape
primitive, and neither should be pulled in for a five-line `replace`.
`escapeHtml` already exists **in this file** and is the correct dependency. The
reuse answer here is *use what the package already has*, which is the one the
code failed to do.

## Design

```ts
fill(template, vars)       // escapes every value
fillHtml(template, vars)   // does not — the name says so at the call site
```

Mirrors `paragraph` / `paragraphHtml`, which already exist in this file with
exactly this split. **No options bag:** an escaping flag has to default to
something, and the wrong default is invisible at the call site — which is the
property that produced this defect in the first place.

**Escape by default even though that is the breaking direction.** A consumer
passing markup into `fill()` sees literal tags and reports it within minutes; a
consumer whose customer name renders as markup finds out from a customer.

## Non-goals

- Not a general sanitiser. `bodyHtml` stays caller-escaped and documented as such.
- Not changing the `{token}` syntax or the leave-unknown-as-is behaviour — that
  is relied upon, and changing it under cover of a security fix is how a fix
  acquires a second, unannounced change.

## Verification

- The payload above, **verbatim**, must render as visible text.
- Unknown tokens still pass through — asserted, because it is existing behaviour
  and the escaping change must not quietly alter it.
- **The docstrings must reach `dist/*.d.ts`.** A warning on a non-exported symbol
  is stripped at build and vanishes while every test stays green; this package
  has already been bitten by exactly that. Read the built file and assert the
  sentence positively.
- Mutation: remove the escape from `fill` → the payload test reddens. Make
  `fillHtml` escape → its own test reddens. Two distinct tests, so the pair
  cannot silently collapse into one function.
