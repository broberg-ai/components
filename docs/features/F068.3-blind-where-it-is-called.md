# F068.3 — The guard is blind in a pre-commit hook, where the interesting file is new by definition

**Status:** Ready · **Epic:** F068 (`@broberg/greppable`) · **Written:** 2026-08-31 · **Filed by:** beacon (#24474)

## Motivation

`checkGreppable` builds its universe from `git ls-files -z`, which lists only
**tracked** files. A file that exists on disk but has not been `git add`ed is
outside the guard entirely.

**Reproduced here before accepting the report** — fresh repo, one tracked clean
file, one untracked file carrying a real NUL byte:

```
git status              ->  ?? untracked.js
checkGreppable({cwd})   ->  { ok: true, scanned: 1, skipped: [], offenders: 0 }
```

`ok: true` about a file it never opened.

## Why this is the package's own thesis, one step to the left

F068.1 added `scanned > 0` on torrent-search-api's argument that *"a green check
that never looked is worse than no check, because it CLOSES THE QUESTION."*

That clause is satisfied by scanning the **wrong** files. We closed the
empty-universe case and left the incomplete-universe case open — and the output
cannot tell them apart, because it was accurate the whole time: *"scanned 319 of
319 tracked files"*. The word `tracked` was doing all the work and nobody read it
as a limitation.

## beacon's precedent, which is why this is urgent rather than tidy

They wrote the guard, ran it (313 files, all visible), and staged **afterwards**.
The file containing the NUL was the one file the commit was about — and the only
one the guard did not look at. CI caught it one push later.

Their sentence, kept verbatim because it explains why the failure is structural
rather than unlucky:

> En tæller der ikke tæller det man er ved at lave, er en tæller der bekræfter en
> tilstand man forlod for et minut siden.

And the general form: **a pre-commit hook is this tool's most obvious use, and in
a pre-commit hook the interesting file is new by definition.** The guard is blind
exactly where it is called.

## Scope

**In:** `git ls-files -z --cached --others --exclude-standard`; tests for both
axes on untracked files; the ignored-path negative control; a success line that
states the universe it examined; publish and tell beacon the version.

**Out:**

- Changing the predicate (NUL ∪ invalid UTF-8). F068.1 measured it and both
  halves are load-bearing. This card changes **which files** are examined.
- Making it a flag. A guard that sees half the files by default is the defect,
  not a preference — an opt-in would leave every existing consumer wrong.
- F068.2's independent-count work. Related (both are about the universe being
  self-reported) but a separate story.

## Reuse

Nothing to check: this is a defect in a package `components` already owns, and
the fix is a git flag. No new capability, nothing to adopt.

## Not affected — checked in the same turn

Relaying a defect without searching your own repo is an unrun search, so:

| | |
|---|---|
| `@broberg/greppable` | **HIT.** This card. |
| F061.6 CI secret guard | reads **committed blobs** deliberately — untracked files are correctly outside its universe |
| `.githooks/pre-commit` | covers that window: a new file being added **is** in the staged diff, asserted by an existing test |

The gap is greppable's alone.

## Rollout

Patch release. Two consumers are on the defective behaviour today: beacon (running
a local copy, explicitly declining to layer over the package) and **this repo** —
components' own CI runs `npx --yes @broberg/greppable@0.1.0`, so we are a consumer
of our own defect.

## Verification

1. Untracked NUL file → found. Proven RED on published 0.1.0 first.
2. Untracked latin-1 file (no NUL) → found. Both axes, not just the reported one.
3. `.gitignore`d paths → still not scanned, proven by the COUNTS, not by the run
   staying green.
4. Mutations: plain `ls-files` reddens the untracked cases and nothing else;
   dropping `--exclude-standard` reddens the ignored-path control. Two distinct
   red sets.
5. Re-run the untracked fixture against the **published** tarball, since that is
   what our CI and the fleet install.
