# F082.13 — components off its own vulnerable Better Auth and vite

**Ordered by:** Christian 28/11 2026 on the Decision Board: «Better Auth og vite først, så F085.5».

## Found by
advisory-watch v1.1.0 (F082.11) on components' own lock, repository-advisory source only:
- better-auth 1.7.7 (dev dependency of packages/auth): GHSA-4wq4-2ppv-q3hg critical, GHSA-q747-mqgr-4gh7 high, GHSA-fmh4-wcc4-5jm3 high — all fixed in 1.7.16.
- vite 5.4.21, pulled by vitest 2.1.9 in ~60 packages: GHSA-p4f5-76q4-ffq7 critical (RCE via `__vite-browser-external`), fixed only from 6.4.6 — 5.x has no fix.

## Approach
- better-auth + @better-auth/passkey → ^1.7.28 in packages/auth devDependencies. NOT 1.7.29: it was published today and pnpm's `minimumReleaseAge: 4320` (F115, 3 days) refuses it; no published advisory is fixed after 1.7.16 (checked 28/11), so 1.7.28 carries every known fix.
- vite: a root pnpm override `"vite@^5": "^6.4.6"` instead of moving 60 packages to vitest 3 — kept only because the whole package suite (test + typecheck) is green with it. If it were not, the fallback is the vitest 3 move.

## Not here (finding for the owner)
@broberg/auth's peer range `better-auth >=1.6.22` still lets a consumer install a vulnerable Better Auth. Raising it is a consumer-facing change — his call.

## Reuse
The repo's existing `pnpm.overrides` (zod) — same mechanism.
