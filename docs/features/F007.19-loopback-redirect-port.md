# F007.19 — en lokal callback med tilfældig port må ikke afvises

## Hvorfor
buddy målte 19/11 2026 (#51731), mens ejeren så fejlen: Claude Code kan ikke logge ind på mailmcp.webhouse.net → `{"error":"invalid_request","error_description":"redirect_uri not registered for this client"}`.

Claude Code bruger CIMD: `client_id=https://claude.ai/oauth/claude-code-client-metadata`, hvis `redirect_uris` er `http://localhost/callback` og `http://127.0.0.1/callback` **uden port**. Programmet lytter på en port det vælger ved opstart og sender `redirect_uri=http://localhost:<port>/callback`. `/authorize` i `oauth-web.ts` sammenlignede eksakt, så porten fik hvert login til at fejle. Rammer alle MCP-servere på opskriften.

## Rettelse (RFC 8252 §7.3)
`redirectRegistered(registered, requested)`: eksakt match, ELLER for en **http-loopback**-redirect (`localhost`, `127.0.0.1`, `[::1]`) ignoreres porten — scheme, host, path og query skal stadig matche eksakt; et fragment afvises. Ikke-loopback forbliver eksakt. Token-udvekslingen sammenligner fortsat med præcis den redirect der blev brugt ved /authorize.

## Non-goals
- Ændre `/register`-reglerne eller tilladte værter.

## Rollout
Patch 0.11.2 → rapport til buddy + mail-mcp (+ dns-mcp) → mail-mcp opgraderer → mål et rigtigt Claude Code-login.
