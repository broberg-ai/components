# F005.16 — Three broken mails reached a paying customer, and none came from a template

> Parent: [F005 — Mail sending (Resend)](F005-mail.md) · proposed by sanne, intercom #27039, 2026-09-09.

**Status:** Backlog · **Priority: high** · a consumer is running a hand-rolled copy today

## The three measurements

Each one a mail that looked finished right up until it was in an inbox.

| # | defect | what the customer saw |
|---|---|---|
| 1 | relative `href="/da/shop/…"` | Outlook read it as a file path — *"Den angivne fil blev ikke fundet"*. Click-throughs lost for months before anyone reported it. |
| 2 | unfilled `{{placeholder}}` | the subject line arrived as literally `{{subject}}` |
| 3 | `cid:` with no attachment | a broken square where the logo belongs |

A relative URL is *valid* on a web page — the browser knows the domain. In a mail there is no domain to resolve against. The template was right in every case; the context was different.

## Why this is our layer

sanne's argument, and it holds: **none of the three originated in a template.** Defect 2 was a caller not supplying a key. Defect 3 was a script grabbing the transport directly and skipping the function that attaches the logo. So a per-template check misses all three.

It has to sit where the finished content **and** the real attachments exist at the same moment — and that is `send()`.

Verified here rather than taken on report:

- `MailAttachment.contentId` exists at `src/index.ts:41`, and its own doc comment reads *"For inline images referenced as `cid:<contentId>` in the HTML"*. **The package already documents the exact relationship whose absence caused defect 3, and checks it nowhere.**
- There is no content validation in `send()` today. None at all.

## The design is sanne's warning, not a caveat on it

> `mailto:` og `tel:` SKAL slippe igennem — vi havde tidligere en vagt der lavede dem om til `#`.

They shipped a guard that broke the two links a customer needs most. **A guard that rejects too much gets switched off, and then it protects nothing.** So every check needs both directions asserted, per scheme, by name — that is the acceptance condition, not a nicety attached to it.

## The rollout risk is ours, and it is bigger than theirs

`send()` is the fleet's **single mail chokepoint**. A guard that is too strict in one app is that app's bug. A guard that is too strict here is *every* app's mail stopping at once, at whatever hour the release lands.

So: **report-only first.** The check runs, returns what it *would* have blocked, and blocks nothing. Enforcement is opt-in per mailer, and no consumer is enforced into it merely by upgrading.

sanne's own first run is the argument for that ordering: **red on two templates, and both turned out to be unrealistic test fixtures rather than customer defects.** An integrity check cannot tell those two apart — only a human reading the output can, and only if the output exists before the blocking does.

This is the same shape as everything else in this epic: *"nothing is wrong"* and *"I could not check"* must not be the same answer. A message with no HTML, or HTML that will not parse, reports the check as NOT PERFORMED — never as clean.

## Reuse

This card **is** the reuse rule executing. sanne built the capability locally — ~120 lines, pure, no I/O, 12 tests — because a paying customer had already received two broken mails and a fix waiting on an npm release does not help today. That is the correct emergency call.

Then they filed it instead of keeping it, in their own words: *"det er en hand-rolled kopi af en fleet-kapabilitet, og reglen siger EXTEND frem for work around — derfor spørger jeg."*

Their code and 12 tests are offered: `sanneandersen site/src/lib/mail/forsvarlig.ts`, plan-doc `F116-ingen-brudt-mail-forlader-huset.md`. Start from their cases — every one is a mail that actually reached a real recipient, which no fixture we invent can claim.

## Not binding

The related rule sits as `proposed` in sanne's Decision Register (`01a08632`) and has **not** been approved by Christian. It binds nobody. The three measurements stand on their own; this card does not assume the rule will be adopted.

## Non-goals

- Rendering or previewing mail. This reads the finished payload; it does not become a mail client.
- Link *reachability*. We check that a URL is absolute, not that it answers — a network call inside `send()` is a latency and failure surface on the fleet's mail path.
- Replacing per-template tests. This catches what templates cannot, which is the three defects above; it does not make template tests redundant.

## Rollout

1. Ship the check **report-only**, default on, blocking nothing.
2. Run every `@broberg/*` template and fixture through it. Triage each red in this plan-doc by name — real defect or unrealistic fixture.
3. Offer enforcement as an opt-in per mailer.
4. sanne deletes their local copy and runs on the package. If it survives, the drift this card exists to remove survives with it.
