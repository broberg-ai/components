# F029.13 — TenantSwitcher: keyboard-drivable menu (D-4cd764)

## Why
buzzalert (#5141, 27/10 2026) measured in production (app-shell 0.11.1) and confirmed in 0.25.0's dist: the TenantSwitcher menu only listens for Escape. No ArrowUp/ArrowDown between `tenant-switcher-item-*`, and focus stays on the button when the menu opens. That breaks the owner's decision D-4cd764 (every pick-list is keyboard-drivable: arrows move, Enter chooses, Escape closes). It blocks buzzalert-F014.13 AC3.

## Scope
- Roving focus inside `bas-tenant__menu` (`packages/app-shell/src/preact.tsx`, `TenantSwitcher`).
- Open → focus the active item (fallback: first enabled item).
- ArrowDown/ArrowUp move between enabled items, wrapping; Home/End jump to first/last.
- Enter/Space choose (native button activation — items are `<button>`s).
- Escape closes and returns focus to `tenant-switcher-button`.
- Disabled (suspended / busy) items are skipped.

## Non-goals
- No shared roving-focus hook across other app-shell menus (none exists today; not requested).
- No visual change.

## Reuse
Discovery: no existing roving-focus primitive in `@broberg/*`; app-shell is the owner of this control, so the fix lands here (extend, not work around).

## Tests
`test/tenant-switcher.test.tsx` gains keyboard cases (open focus, arrows with wrap and skip, Home/End, Enter chooses, Escape returns focus) and the package's mutation harness gains a mutation that removes arrow handling.

## Rollout
Patch/minor release of `@broberg/app-shell` via tag; release report to buzzalert with the version (D-b7eb14), stated as a possibility for other consumers (D-5f65b6).
