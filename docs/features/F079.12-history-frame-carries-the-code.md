# F079.12 — The history frame carries English prose and no code

> Story under **F079 — `@broberg/chat`**. From cms's live history step-down run in their production container, 2026-08-28 — the second of the two real-provider measurements we agreed.

## First: our own prediction, proven for the first time anywhere

```
--- window ---
history frames : reduced(3), reduced(5), reduced(7), reduced(9), reduced(12)
error frames   : 0
marker         : GONE
last answer    : «Jeg kan ikke opsummere noget, medmindre du giver mig noget at opsummere.»
```

The README has warned since F079.10 that `window` **fails by succeeding** — it drops the user's opening instruction and everything looks normal.

**It is worse than we wrote.** The model had forgotten the *whole* conversation and said so politely, with **zero errors**. A user does not read that as *"the system threw my context away"*. She reads it as *"this assistant is unreliable"*.

Their first run never reached the ceiling — only `warned` — and **the probe said "PROVES NOTHING" of its own accord**. They lowered the limit rather than writing something flattering about a result that did not exist.

## The defect: a developer's sentence reached a customer

Our `note` went **verbatim** to an end user — mid-conversation, in Danish, with a customer: an English sentence describing a mechanism instead of telling her what to do. cms has fixed their side (`363a2071`), and they are explicit that our notes are not wrong *for who they are written for*.

**But the reason they passed the prose through is ours.** Verified in our source before acting:

```ts
// src/index.ts:209
| { type: "history"; action: "warned" | "reduced" | "failed"; note: string; dropped?: number }

// src/index.ts:382
yield { type: "history", action: "failed", note: outcome.note };   // outcome.reason DROPPED
```

The three reasons that F079.9 and F079.11 went out of their way to keep separate — `compaction_failed`, `cannot_reduce`, `overhead_exceeds_limit` — **all arrive as the same `action`**, and `reduced` never carries `strategy`. A consumer who wants to say something in their own language has **nothing to switch on but the English string**.

So the state we were careful to preserve inside the module is thrown away at the exact boundary where somebody needs it.

## The fix is smaller than what was proposed

cms suggested a `userMessage` key. Their diagnosis is right; the fix is smaller: **the codes already exist — we simply do not send them.**

```ts
| { type: "history"; action: "warned" | "reduced" | "failed"; note: string;
    dropped?: number; reason?: HistoryFailureReason; strategy?: HistoryStrategy }
```

**We ship no user-facing prose.** We do not know the consumer's language, tone or audience, and a sentence we invented would need translating anyway. The code is ours; the words are theirs.

## And their fourth finding was against themselves

Their marker check was **case-sensitive**. The model wrote «Bananflue», so the first run reported that `window` had LOST the instruction when it had been preserved — **a finding against us that did not exist, reported with numbers.** Their thirteenth instrument error of the day, caught only because the probe *also* said "proves nothing" in the same run.

That is the day's ratio again: the instrument is wrong before the subject is.

## Still outstanding — and it must not read as covered

The **`compact` half**. Their `maxInputTokens` was 260, at which one turn alone exceeds the whole limit, so it correctly reported `cannot_reduce` and never got to show its value. **Not our bug**, and they said so plainly rather than letting a finding that looks like something it is not cost us an hour.

They are re-running with a limit low enough to trigger reduction and high enough for one turn to fit. Until that lands:

| | |
|---|---|
| `window` loses the opening instruction | **MEASURED** — mistral-small, 5 reductions, 0 errors |
| `compact` preserves it | **NOT measured** |
| `cannot_reduce` as its own state | useful in practice, measured — it told them the problem was not the old messages |

## Non-goals

- Not translating anything. Not guessing a consumer's tone.
- Not a second vocabulary beside `reason`.
- Not re-running the 65-tool or multi-round cases; agreed with cms as lower value than this.
