# F035.12 — 0.6.0 fixed the half that was measured

**Status:** Ready
**Parent:** F035 — `@broberg/secret-scan`
**Found by:** the auto-review gate on F035.11 · **re-verified here** against published `0.6.0`

---

## 1 · The digit branch has no floor — still corrupting the corpus

```
'Kodeord: 2'      -> 'Kodeord: [REDACTED:announced-secret]'
'secret: v2'      -> 'secret: [REDACTED:announced-secret]'
'password: nr.3'  -> 'password: [REDACTED:announced-secret]'
'api key: v3'     -> 'api key: [REDACTED:announced-secret]'
```

buddy measured that a **digit-free** candidate under 16 characters is prose. I
implemented the **unmeasured converse** — that any digit makes a candidate a
secret. Version references, ordinals and numbered items are ordinary Danish and
English prose.

**So 0.6.0 fixed exactly the half that had numbers behind it, and left the half
that did not.** That is the finding, and it is more useful than the four strings.

The floor is **not derivable from their data** — they measured digit-free
candidates only. So it is provisional, it says so in the same sentence, and buddy
is asked for the digit-bearing measurement. A guess in the voice of the derived
`16` would be the worse mistake.

## 2 · A quoted key is flattened — and this pre-dates 0.6.0

```
'API key: "sk-ant-api03-AAAA…"'  ->  'API key: [REDACTED:announced-secret]'
findings: anthropic-api-key, announced-secret
```

The format pass correctly produced `"[REDACTED:anthropic-api-key]"` *inside the
quotes*; the announced pass then matched the whole quoted token, because the
`(?!\[REDACTED:)` lookahead only fires when the marker is the **first character**
of `\S+`, and overwrote it with the generic marker. The redacted text no longer
says what kind of key it was.

`README:163` states the opposite as fact, and the F035.11 test asserts the
invariant only on the unquoted fixture — green on the one shape that happens to
work.

**Widen the lookahead. Do not special-case quotes:** a fix that lists quote
characters leaves brackets, parentheses, and every delimiter nobody thought of.

## 3 · The two entry points still disagree

```
hasAnnouncedSecret('password: AKIAIOSFODNN7EXAMPLE')  -> true
redactSecrets(same).findings                          -> [aws-access-key-id] only
```

Routing both through `plausibleSecretValue` fixed **one** of the two reasons they
can diverge. The other is that `hasAnnouncedSecret` runs on **raw** text while
`redactSecrets` runs the announced pass **after** the format pass has substituted
a marker.

My comment says they agree. The claim is broader than what was fixed — the same
shape this repo has now named eight times. Either make it true or narrow it.

## 4 · A README sentence is now inverted

```
redactSecrets('Adgangskode:\nJeg glemte den', {announced:true})  ->  untouched, findings []
```

`README:160`: *"One visibly-marked word, never a silent miss — and both halves are
tested."* It is now **precisely** a silent miss.

And there is **no "Upgrading to 0.6.0" section**, though 0.3.0 and 0.4.0 both have
one and 0.4.0's exists for exactly this shape of change. A consumer upgrading
reads the README, sees nothing, and keeps believing `Adgangskode: correcthorse`
is caught. Booked in this repo one day earlier as *"0.6.0 breaks input that used
to reach your CSS, and I did not say so"*.

## 5 · The threshold is pinned by nothing

Changing `16` to `24` leaves **all 141 tests green**. Every announced fixture
carries a digit so it never reaches the length branch; the only length-branch
fixture is 25 characters and the longest rejected one is 6. The harness then
prints `0 uncaught` — a completeness claim it cannot support.

**A threshold no test can move is a magic number wearing a measurement's
clothes.**
