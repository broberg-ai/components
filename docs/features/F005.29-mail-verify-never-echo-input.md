# F005.29 — @broberg/mail/verify must never echo its input

Parent: F005 (mail sending). Reported by mailworker (intercom #53177), measured in production on 21/11: `checkSendingPermission({apiKey, from})` — an object instead of the string it expects — returns a result whose `domain` and `summary` contain the whole object, API key included. A wrong call logs the key.

## Where it echoes (packages/mail/src/verify.ts)
- `verifySendingDomain`: `domain: rawFrom` and `JSON.stringify(rawFrom)` in `summary`.
- `checkBrandReadiness`: `domain: rawFrom` and `JSON.stringify(rawFrom)` in `warnings`.
- `checkResendDomain`: `String(rawFrom)` in `domain`, and `detail` from `senderDomain`'s message.
- `senderDomain`: `JSON.stringify(from)` in the thrown message.

## Fix (proposal)
One helper decides what may be repeated: a non-string is described by its TYPE only; a string is truncated and anything key-shaped (`re_…`, `sk_…`, long tokens) becomes `[redacted]`. Every echo goes through it. A non-string argument to `senderDomain` throws a TypeError that names the type, never the value.

## Proof
Red-first test over all five entry points with an object carrying an API key, an array, a number, null, a key-shaped string and a long string; `JSON.stringify(result)` must not contain the key. Existing tests unchanged. Mutants: redaction removed, type check removed, input echoed again.

## Release
Patch 0.26.1, release report to every consumer (error-case output moved).
