# F013.7 — A Gravatar outage reads as “no avatar”, and a name in brackets reads as `L(`

> Parent: [F013 — Gravatar Connector](F013-gravatar.md). Filed by **moovyy** on the day they adopted `@broberg/gravatar` 0.1.0.

## Two findings, and measuring them found three more

moovyy adopted the package today — they had hand-rolled it, and Christian caught it. `gravatarHash` matches their own SHA-256 byte for byte, so the core is right. They filed two defects instead of building around them.

Measuring those two here turned up **three more**, including one where the code contradicts its own doc comment.

### 1. `gravatarExists()` collapses three outcomes into two — *theirs*

```ts
const res = await fetch(url, { method: "HEAD" });
return res.ok;
} catch { return false }
```

“The network failed” and “Gravatar answered 503” both become `false` — which reads as **“there is no picture”**.

And you *cache* that answer. You have to: otherwise you ask Automattic on every page render. So a ten-second hiccup at Automattic costs a user their avatar until the cache expires, and the call-site has no way to know it was ever asked a question it could not answer.

This is the family the fleet has spent the week on: **a missing value degrading silently into a confident answer.**

### 2. `getInitials()` takes the first character without checking it is a letter — *theirs*

Measured in their production surface today: the user **“Lens (verifikation)”** rendered as **`L(`** in the avatar circle. A punctuation-led token is not rare in a display name — brackets, hyphens, a trailing title.

### 3. The email branch contradicts its own doc comment — *found here*

The comment says *“first two chars of the email **prefix**”*. The code does `email.substring(0, 2)` on the **whole address**:

```
getInitials(null, "x@webhouse.dk")  → "X@"
getInitials(null, ".hidden@x.dk")   → ".H"
```

It only *looks* correct because most addresses happen to start with two letters. `cb@webhouse.dk → "CB"` is luck, not design.

### 4. A whitespace-only name returns two spaces, not `??` — *found here*

```
getInitials("  ") → "  "
```

The `'??'` fallback is **unreachable** for it: a string of spaces is truthy, so the name branch runs, and `substring(0,2)` of the *untrimmed* name is two spaces. The avatar circle renders blank and nothing reports a problem.

### 5. `getInitials("((  ))") → "()"` — *found here*

## A deliberate non-fix

```
getInitials("Jens Hansen, direktør") → "JD"
```

It takes the **title** as the surname. Truncating at the first comma would fix the Danish *“Name, Title”* convention — and **break** the equally common *“Surname, Firstname”* form that plenty of systems export.

Two conventions, opposite fixes, no way to tell them apart from the string alone. **Left alone and documented**, so it is not later mistaken for an oversight.

## The shape of the fix

`gravatarLookup(email, size?)` → `'yes' | 'no' | 'unknown'`

| Result | Meaning |
|---|---|
| `404` | `no` — genuinely no avatar |
| `200` | `yes` |
| everything else (5xx, throw, timeout, surprise status) | `unknown` — **do not cache this as a no** |

`gravatarExists()` stays, unchanged in behaviour, delegating to `lookup === 'yes'`. Its doc now says plainly that it **cannot** distinguish “no avatar” from “we could not ask” — so a caller who caches it is told what they are caching. Backwards-compatible, exactly as moovyy proposed.

`getInitials()` splits on non-letter/non-digit (`\p{L}\p{N}`, unicode-aware), cuts the email at `@`, and lets `'??'` actually be reachable.

### The negative control that matters

A `\p{L}` class that quietly excluded CJK or accented Latin would pass **every ASCII test** and break real users. So `李 明 → 李明` and `José → JO` are asserted as first-class cases, not as afterthoughts.

## Reuse

Nothing to adopt — this is a fix to a package `components` already owns. What it demonstrates is the rule working in the other direction: moovyy is holding their own three-outcome check on top of `gravatarUrl` until this ships, **marked temporary in code with a reference to this card**, rather than shipping a parallel implementation that would drift.

## Also worth stating

moovyy's closing note, which costs nothing and saves the next reader a type error: the core is **async** because it uses `crypto.subtle` — correct for isomorphism, but a Node-only consumer expects sync. That belongs in the README rather than in a stack trace.

## Rollout

Additive minor, `0.2.0`. `gravatarLookup` is new; `gravatarExists` is unchanged for existing callers. `getInitials` changes output for inputs that were previously **wrong** — documented, and every previously-correct case is asserted to still hold.
