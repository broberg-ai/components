# F079.14 — collect one run into one answer

**Status:** Ready · not started · **Epic:** F079 (`@broberg/chat`)
**Written:** 2026-09-11 (dansk tid) · **Filed by:** helpdesk

## They retracted their own premise first

Their card of 8 September said the engine *“is built to STREAM to a user;
generate-without-delivering is a shape the engine does not have.”*

```ts
Chat.run(input) → AsyncIterable<ChatFrame>
```

It delivers nothing. `createChatHandler` is what turns the stream into an HTTP
response. Draft-without-sending has existed since the engine shipped.

Their sentence, and the direction is the expensive one:

> **A consumer who believes a capability is missing builds it themselves.**

Same shape as the secret-scan finding earlier today, pointing the other way: there
a package looked like it answered a question it does not, here a package looked
like it lacked a capability it has.

## The real gap

There is no *“collect one run into a finished answer”*. Every consumer that wants
ONE answer rather than a stream writes the same loop. Theirs is ~60 lines, and
**four of the decisions in it are not obvious**:

| # | pitfall | what it costs |
|---|---|---|
| 1 | `done.reason` must be read | max-rounds gives a half draft that looks whole — and a human can approve it |
| 2 | an `error` frame (scope `model`) must **throw** | the engine emits it and then ends with reason `complete`; a naive collector stores `[error] HTTP 500` as the answer **and reports it finished** |
| 3 | tool results read for sources, non-binary | five states, because an empty source list otherwise covers four different things — and “Trail did not answer” means the draft was written BLIND |
| 4 | the spend cap settles only AFTER a round with tool calls | an answer with no tool calls cannot hit it — worth knowing before believing you measured it |

**Pitfall 2 is the one that reaches a person.** It is a success-shaped non-answer
inside our own package: an error, stored as the answer, reported as complete.

## The shape

```ts
collect(chat, input) → { text, frames, done: reason, toolResults }
```

**RAW structure, not an interpretation** — helpdesk's boundary, and it is right.
The source extraction and the five knowledge-states are THEIR domain and do not
belong in the package. A package that interprets forces every consumer to
un-interpret.

## Reuse

Discovery checked per F217 (`chat`, `stream collect`, `ai response`). The engine
is ours and the loop can only live beside it — nothing to adopt. The reuse finding
is the inverse of the usual one: a capability that EXISTS was recorded as missing
in a consumer's card for three days.

## Starting point

`apps/core/src/chat/enkelt-svar.ts` in helpdesk, card `helpdesk-F006.7`. Offered.

## Non-goals

- **Source extraction and knowledge-states.** Consumer domain. Five states are
  right for a support desk and wrong for a marketing site.
- **Reducing `done` to a boolean.** That is this repo's two-valued-channel defect
  in a new place — four reasons, four values.
