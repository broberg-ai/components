# F105.8 — En hygiejne-kørsel må aldrig udrulle ældre kode

> Story under F105. Kritisk fejl målt af cardmem 23/10 2026 (#4199).

## Hvad skete
Motoren bygger koden på den sha kørslen blev startet på, scanner og udruller. cardmems kørsel startede på 9e79dca2; mens buildet kørte (6+ min), landede en almindelig CI-udrulning af e6dc8467 (v2929). Motoren udrullede så sit image (v2930) oven på — produktionen gik tilbage til 9e79dca2. Alt grønt; ingen så det før /health blev læst.

## Rettelse
Lige før `flyctl deploy`, to spærrer — hver af dem er nok til at springe over:
1. **Nyere release:** appens nyeste Fly-release (flyctl releases --json) er oprettet efter kørslens start → nogen har udrullet undervejs.
2. **Branchen er gået videre:** kørslen er startet på default-branchen, og `git ls-remote` viser en anden sha nu → nyere kode kan være udrullet.

Skip = status `skipped`, `detail.skip_reason: superseded` + hvad der vandt. Ikke rødt: der er intet galt, kørslen er bare for gammel. Kan releases ikke læses → skip (aldrig udrul i blinde).

Beslutningen i `scripts/image-hygiene-superseded.mjs` (testbart), workflowet leverer kun tal.

### Non-goals
Ingen ændring af scanningen eller rød/grøn-reglerne.
