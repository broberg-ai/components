# F099.9 — Chat readers for ChatGPT and Claude: the WHOLE conversation, and an incomplete clip says so

> Story under F099 (@broberg/web-clipper). Priority high. Effort M. Owner order 13/10.

## Motivation
- Owner, 13/10: «ja, tag chat-læserne til web-clipper nu». Earlier (via trail #3090): «vi skal kunne clippe en 500 meter lang webside».
- trail #3089 (measured, Lens flow-run 19a890e5): a ChatGPT share clip got 24,129 characters (6 user + 7 assistant turns) — the bottom only; ≥8 long answers missing. ChatGPT VIRTUALISES the thread: ~8 messages are in the DOM at a time.
- jam #3157: 0.4.0 exports no chat readers, so Jam's clipper sends a ChatGPT page as one «page» unit with no anchor → consent_required → the popup shows NOTHING («Den blinker blot hurtigt og siger ikke noget»).
- The owner noticed a saved ChatGPT HTML page is empty. That is the same cause from the other side: the page ships an almost empty shell and renders the conversation with JavaScript from data it fetches. The content is not locked; it is in the data, not in the HTML.

## Design
**Read the data, not the DOM.** The content script runs inside the page, logged in as the user. It asks the page's OWN backend for the conversation — the same request the page makes — and gets every turn at once, however long:
- **ChatGPT** (`chatgpt.com/c/<id>`): session token from `/api/auth/session`, then `/backend-api/conversation/<id>`. The answer is a tree (`mapping`, `current_node`); walk from `current_node` up via `parent` to get the branch the user is looking at. Keep only user/assistant text; drop hidden, tool, system and search messages; merge consecutive assistant parts into one turn.
- **Claude** (`claude.ai/chat/<id>`): organisation from `/api/organizations`, then `/api/organizations/<org>/chat_conversations/<id>?tree=True&rendering_mode=messages`; walk from `current_leaf_message_uuid` via `parent_message_uuid`.
- **Fallback:** if the data request fails or its shape is not what we expect (these are not public APIs and can change), read what is in the DOM and mark the clip INCOMPLETE. Never guess a shape.
- **Share links** (`/share/…`): DOM fallback, marked incomplete, until measured otherwise.

**Completeness on the Clip:** `completeness: { complete: boolean; source: "data" | "dom"; reason?: string }`. Only a full data read is `complete: true`. The popup shows a warning for anything else.

**Never silent:** consent_required with no anchor → «Siden er ikke en samtale»; the done-line says how many turns were sent; `text` overrides on ClipperPopup (jam: «Ingen steder at gemme»).

**htmlToMarkdown** exported from /extract — the article extractor's Turndown setup, moved not changed, so consumers never roll a copy.

### Rejected
- **Scrolling the thread and collecting** as the main path: slow, visibly scrolls the user's page, and still cannot prove it got everything. Kept only implicitly as «what the DOM has» in the fallback.
- **Saving the page HTML**: the shell has no content (owner's observation).
- **Claiming complete on a DOM read**: violates the owner's «et ufuldstændigt klip må aldrig se komplet ud».

## Scope / non-goals
In: the two readers, completeness, popup messages, htmlToMarkdown, text overrides. Not in: other chat sites, generic infinite-scroll pages (the broader «500 m page» case — separate card if wanted), Jam/Trail destinations.

## Reuse
Extends @broberg/web-clipper itself (Turndown already a dependency). No new package.

## Risk
The data endpoints are unofficial. A shape change must degrade to an INCOMPLETE clip, never a wrong complete one — tested with a negative control. Verified in a real logged-in browser by a consumer (Lens cannot log into ChatGPT/Claude for us).

## Rollout
Minor release (0.5.0), release report to trail + jam.
