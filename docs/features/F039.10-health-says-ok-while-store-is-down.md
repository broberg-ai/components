# F039.10 — Discovery answered 500 for 25 minutes while /health said ok

## Motivation
Reported by helpdesk 26/10: `POST /api/enroll` answered 500 twice. The Fly logs show every DB-backed route on discovery.broberg.ai answering 500 in 0–1 ms with `ECONNREFUSED` from 12:42Z to 13:10Z (13:42–14:10 dansk tid).

Measured:
- machine `8dd597aed211e8` reached npm but NOT the Turso host (`bun fetch` from inside the machine: ERR)
- machine `830d13f7945638` and the Mac reached it (200)
- Fly's check on 8dd5 stayed PASSING, because `/health` returns `{ok:true}` without touching the store — so the proxy kept routing traffic to a machine that could serve nothing
- the 0 ms answers: `enroll.ts` keeps the first init promise in `_init`; when it rejects, every later call returns that same rejection. Even if the network heals, the machine stays broken until restart.

Mitigated live by stopping 8dd5 (reversible: `flyctl machine start`).

## Scope
1. `getEnrollStore()` resets `_init` on rejection, so the next request retries.
2. `/health` runs a cheap `SELECT 1` against the store (short timeout) and answers 503 `{ok:false, store:"unreachable"}` when it fails. No store configured = still healthy.
3. Confirm `fly.toml`'s check targets `/health`, so Fly takes an unhealthy machine out of rotation.

## Non-goals
- Not a retry/backoff layer inside every route.
- Not a fix for Fly's host networking — that is Fly's; we only stop routing to it.
- No change to enroll semantics or the response shapes of other routes.

## Architecture
`enroll.ts`: `_init = (async () => {...})().catch((e) => { _init = null; throw e; })`. Add `ping()` to the store (`SELECT 1`). `server.ts` `/health`: `getEnrollStore()` → null → ok; else `Promise.race([store.ping(), timeout(2000)])` → ok / 503.

## Dependencies
Turso (existing), Fly http check (existing fly.toml).

## Reuse
Discovery reuse check: this is a fix inside Discovery's own health route and store init — no shared @broberg capability applies (searched mentally: no @broberg health-check primitive owns app-specific store probes). Nothing to adopt.

## Rollout
Tests + mutation → commit → push → the discovery workflow deploys → verify live `/health` and an authed `/api/sessions/<x>` = 200 → tell helpdesk to re-enroll.
