# F110.13 — legal.broberg.ai koldt på én maskine, og sites cacher

> **Ordre:** ejeren 1/11 2026, ordret: «Hvorfor skal broberg-legal have 2 maskiner? Kan du ikke lave det sådan at den den er kold og slukkes hver gang den ikke anvendes? De sites der anvender API skal kunne cache de data lokalt og kun af og til checke om der er nye data. Vores 5 data pakker / filer opdateres jo ikke dagligt. Jeg GIDER ikke spilde penge på unødvendig luksus»

## Målt
broberg-legal: 2 maskiner (1 kørende, 1 stoppet), v1, `min_machines_running = 1` → én maskine kører altid. Svar caches kun 5 min (`max-age=300`); ETag/304 findes for JSON, ikke for HTML-siden.

## Rettelse
- `min_machines_running = 0` (auto_stop/auto_start beholdes): maskinen stopper når den ikke bruges og starter ved første kald (koldstart ~1–2 s `[Likely]`).
- Én maskine: udrulning med `--ha=false`, og den overskydende fjernes.
- Cache: `public, max-age=86400, stale-while-revalidate=604800` på JSON og HTML; ETag = contentHash på begge; `If-None-Match` → 304. Teksterne ændres kun ved en udrulning, så et døgn er sikkert; en site genvaliderer billigt med ETag.
- `/health` får `no-store`.
- Docs: sites cacher og genvaliderer; npm-pakken `@broberg/legal` har teksterne indbygget og kalder slet ikke servicen.

## Ikke i scope
CDN foran servicen.

## Reuse
Eksisterende `apps/legal`; ingen ny pakke.
