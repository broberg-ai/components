# F040.2 — `@broberg/mail-templates` 0.1.0

> **Ordre:** Christian 21/10 2026, ordret: «Byg den fælles mail-templates pakke nu».
> **Udløser:** beacon (intercom 3672, F008 mailskabeloner pr. tenant) skal have versionerede, redigerbare skabeloner pr. tenant efter cardmems F298-blokmodel. `@broberg/mail-core` 0.9.0's README peger allerede på `@broberg/mail-templates` — som giver 404. Uden pakken bliver beacon femte kopi.

## Hvad ændrer sig i forhold til F040's plan

F040 (juni) pegede på xrt81's `resolveMailTemplate/renderMailBody` som frø. Siden har **cardmem bygget F298** — en blokmodel aggregeret fra fire projekters MÅLINGER (fd-sundhed, sanne, vn-leker, trail). Den er det bedste frø, fordi hver regel i den er betalt for i drift. **Frøet er derfor cardmem `packages/shared/src/mail-template.ts` + `mail-render.ts` + `mail-classes.ts`**, ikke xrt81. F040's override-model (standard i koden + override pr. tenant, `isCustom`) lægges ovenpå, fordi det er dét beacon beder om.

cardmem skrev i F298 «NOT adopted: a shared template store package» — det står stadig: pakken er IKKE et lager. Den er motoren. Lagringen bliver hos værten.

## Scope (0.1.0)

**Schema (zod):** `MailBlock` (paragraph · heading · note · button · divider · html), `MailBrand` (alle felter valgfri; farve og font-stack AFVIST ved injektion, ikke escaped), `MailCopy`, `MailTemplate` = `{purpose, subject, blocks, preheader?, brand?, copy?}`. cardmem-specifikke felter (audience, sourcePath, referenceHtml, invite-kontrakten) er IKKE med — cardmem udvider skemaet med `.extend()`.

**Render:** `renderBlocks`, `fillPlaceholders`, `fillPlaceholdersRaw`, `renderTemplate` — uændret rækkefølge (render → fill; knap-URL fyldes før og går gennem `checkUrl`), `notes` og `missing` som i F298. `derivePreheader`, `checkUrl`, `escapeHtml`, `escapeAttr`, `MAIL_CLASSES`.

**Byggeklodser stikkes ind (`MailPrimitives`).** `@broberg/mail-core` importerer `node:fs` ved modul-start; cardmem målte at en browser-bundle så fejler ved `vite build`. Pakken importerer derfor IKKE mail-core — værten sender `{heading, paragraph, noteBox, cta}` ind. Ingen fallback: en fallback ER en anden implementering.

**Override-opslag (F040):** `resolveTemplate(standard, override?)` → effektiv skabelon; `listEffectiveTemplates(standarder, overrides)` → `[{purpose, effective, default, isCustom}]` + `unknownOverrides` (et override for en purpose der ikke findes i koden navngives, tabes ikke stille). Override = delvist `MailTemplate` uden `purpose`.

**Versionering:** `canonicalContent` + `hashContent` (SHA-256, Web Crypto). Værten gemmer versioner; pakken giver det fingeraftryk de sammenlignes på.

## Non-goals

- Lagring, migrationer, editor-UI — værtens.
- Afsendelse — `@broberg/mail`.
- Skallen (`renderShell`) — `@broberg/mail-core`.
- At flytte cardmem over — cardmem beslutter selv, efter 0.1.0 er ude.

## Afhængigheder

`zod` (som cardmem). Peer: ingen. Dev: `@broberg/mail-core` (testen kører med de rigtige byggeklodser).

## Reuse

- **Discovery:** pakken findes ikke (404 på npm); `@broberg/mail-core` er skallen og genbruges via indstik; `@broberg/mail` er afsendelse. Ingen ny udbyder-integration.
- **Frø:** cardmem F298 — kopieret med ophav i kommentarerne, ikke genopfundet.

## Rollout

1. Pakken + tests (AC'erne) + mutationer.
2. Første udgivelse lokalt med ejerens OTP (ny pakke), derefter Trusted Publisher + publish.yml-job.
3. Discovery-række.
4. Besked til beacon og cardmem med version og API.
