# F042.4 — PSD input for @broberg/media-transform

**Requested by:** vn-leker 27/11 2026 (intercom #56593, VN F007.25 AC1). D-ad16af: VN builds no local workaround; components extends the package.

## Why
VN's suppliers deliver hi-res product images as Photoshop files. The shop needs a WebP preview (~1600 px longest edge). sharp/libvips does not read PSD.

## Approach
- Detect PSD by magic bytes `8BPS` (also PSB, same magic).
- Read ONLY the composite (merged) image with `ag-psd` (pure JS, MIT, deps pako + base64-js): `readPsd(buf, { skipLayerImageData: true, skipThumbnail: true, useImageData: true })`. ag-psd needs a canvas factory even for ImageData; we register one that returns plain `{ width, height, data }` and never a canvas (layers/thumbnails are skipped, so no canvas is needed).
- RGBA → `sharp(raw, { raw: { width, height, channels: 4 } })` → the existing variant pipeline (resize/encode unchanged). EXIF orientation does not apply.
- 16-bit composites are scaled to 8-bit; 32-bit (HDR float) and unsupported colour modes throw `PsdUnsupportedError`.

## The black-image trap (measured 27/11)
A PSD saved without «Maximize compatibility» has no real composite: ag-psd returns an all-black RGBA buffer without complaint. Photoshop records this in image resource 1057 (`versionInfo.hasRealMergedData = false`). When that flag is false we throw `PsdNoCompositeError`; VN writes it to its import log. When the resource is absent (non-Adobe writers), the composite is trusted.

## Limits (documented)
- CMYK → RGB is ag-psd's naive conversion, no ICC profile: fine for a preview, not colour-accurate.
- The whole file is held in memory (layer pixels are skipped).
- `initializeCanvas` is module-global in ag-psd; we set a canvas-free factory on first PSD.

## Tests
Fixtures generated with ag-psd's writer (committed): 8-bit RGB with composite (red), one with `hasRealMergedData:false`, 16-bit RGB, CMYK. Asserts pixel colour of the output, size, the named errors, and that non-PSD behaviour is unchanged. Node + Bun.
