# F067.8 — A notification tap lands on the wrong screen on iOS

**Status:** Backlog · **Epic:** F067 (`@broberg/webpush`) · **Written:** 2026-09-07
**Raised by:** trail (intercom #26338), against 0.5.0

## Motivation

trail's owner, with the phone in his hand:

> «Når jeg trykker på denne APN så kommer jeg godt nok ind i PWA, men jeg kommer
> ikke til en relevant skærm.»

Their engine sent a correct address (`/kb/<id>/sources`). The last link — ours —
dropped it.

trail measured it in our published `dist`. **I verified it in the source myself**
(`packages/webpush/src/sw.ts:151-178`) rather than taking a peer report at face
value. It holds, and it is worse than reported.

```ts
for (const c of all) {
  const wc = c as WindowClient;
  if ('focus' in wc) {
    await wc.focus();
    if (navigate && 'navigate' in wc) {          // ← PATH A
      try { await wc.navigate(navigate); }
      catch { /* cross-origin or detached — ignore */ }   // ← PATH B
    }
    return;
  }
}
if (navigate) await clientsApi.openWindow(navigate);
```

## Two silent paths, not one

This is the half trail could not measure without an iOS debugger. They said so
explicitly and were right not to guess — so here is the part that does not need
a device to establish, because it is a property of our own code:

| | what happens | what a consumer sees |
|---|---|---|
| **A** | `'navigate' in wc` is **false** — iOS does not implement `WindowClient.navigate`, so the call is skipped entirely | nothing. No throw, no catch, no log |
| **B** | the method exists and **rejects** | nothing. The empty `catch {}` swallows it |

**Both end identically.** "It routed" and "it did nothing" are the same
observable outcome, on every platform, for every consumer. That is why nobody
found this by reading the code: it looks perfectly sensible.

Which of A or B fires on iOS does not change the fix — but it does change the
*claim*, so the plan does not assert one. trail's own caveat, kept.

## Scope

**Post the destination to the app before falling back.**

```ts
for (const c of all) {
  const wc = c as WindowClient;
  if ('focus' in wc) await wc.focus();
  wc.postMessage({ type: 'webpush:navigate', navigate });   // NEW
}
// then the existing navigate() / openWindow() fallback, unchanged
```

An app with a router handles the message and routes itself — faster everywhere,
and the only path that works at all on iOS.

### Non-goals

- **Not removing `navigate()`/`openWindow()`.** Replace, prove, then remove — and
  there is nothing to remove here anyway: they are the fallback for a consumer
  that does not listen for the message.
- **Not a breaking change.** A consumer who ignores the message gets exactly
  today's behaviour.
- Not solving iOS badge or subscription-expiry behaviour. Separate cards.

## Two clients is necessary and NOT sufficient — trail measured it

trail hit our second bug in their own local copy, in a **different form**, and
the correction to our AC is theirs:

> Min `sw.ts` await'ede `focus()` MIDT i løkken, før postMessage. Et afvist
> focus ville have kastet ud af den async-blok, så vinduerne bagefter aldrig fik
> ruten. Samme udfald som jeres `return`, anden mekanisme.

**A fixture with two clients that both focus fine PASSES their broken code** — it
reached both windows; it would only have failed if the first had rejected. So two
clients catches *our* `return` and misses *their* `await`, and the two live in the
same three lines.

**The fixture must have two clients AND the first must reject `focus()`.** That is
AC#1. They have it measured and mutation-proven both ways
(`apps/admin/src/sw-notificationclick.test.ts`) and offered it — take theirs
rather than writing a weaker one.

The general shape, worth keeping: *the post that carries the payload must happen
before anything that can fail.* `return`, `throw`, and an `await` that rejects are
three doors to the same room.

## The `return` is also wrong, and it is a second bug

The loop `return`s after the **first** focusable client. With several windows
open, the rest are never told. The message must go to **all** of them — the
`postMessage` belongs before any early exit.

Found while reading for trail's report; recorded here rather than filed
separately because it is the same three lines.

## Reuse

Nothing to reuse — this IS the shared package. Checked Discovery for a second
push primitive that might already own click-routing: `@broberg/webpush` is the
only one, and `@broberg/notifications` (F074) is deliberately about counting, not
delivery.

## Acceptance criteria

1. `handleNotificationClick` posts `{ type: 'webpush:navigate', navigate }` to
   **every** matched window client, before any `navigate()`/`openWindow()` call
   and before any early return. Asserted with **two** clients in the fixture —
   one client passes today by accident.
2. The existing fallback still runs for a consumer that does not listen:
   `navigate()` when available, `openWindow()` when there is no client at all.
   Asserted separately, so the additive claim is proven and not assumed.
3. **The silence is gone.** A `navigate()` that throws, and a client without the
   method, are distinguishable from a success — by an `onNavigateFailure` hook or
   an equivalent the consumer can observe. **Mutation-proven:** restoring the
   empty `catch` must redden a named test.
4. Every one of the three above proven RED first. AC#1's test must fail against
   0.5.0's handler.
5. The README says plainly that iOS does not implement `WindowClient.navigate`,
   and shows the three-line listener a consumer adds. A capability nobody knows
   to listen for is not shipped.
6. trail switches to the published version and **deletes their local copy** —
   they built this in their own `sw.ts` today and asked to hand it back. Their
   confirmation is the AC; a local fork of a shared package is the drift the
   inventory exists to prevent.

## What is NOT claimed

Nobody here has an iOS debugger. AC#1–#4 are provable in a test harness with a
fake `WindowClient`; **that iOS then lands on the right screen is trail's to
confirm on the device**, and until they do, this fix is reasoned rather than
observed. Said out loud because a green suite on a fake client is exactly the
kind of proof that reads as more than it is — a stub cannot disagree with you.
