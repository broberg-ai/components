# F115.9 — security-gate reads Cargo.lock and Package.resolved

Parent: F115 (supply-chain and code security). Requested by cardmem (intercom #52617) from the F427.3 fleet baseline.

## Why
The fleet gate (security-gate, tag v1.0.3) reads pnpm-lock.yaml, package-lock.json and bun.lock. buzzalert, drive and fd-sundhed also ship Cargo.lock or Package.resolved. Today those files are named as `unsupported-lockfile` and BLOCK — correct (unmeasured is never green), but the only way out for a repo is a dated ack. A repo cannot fix a missing parser; the engine can.

## Decision (agent proposal, owner may overrule)
Build both parsers. OSV.dev covers crates.io and SwiftURL. Keep `unsupported-lockfile` blocking for every family still without a parser.

## Not in scope
yarn.lock, go.sum, poetry.lock etc. stay named-as-unsupported until a repo needs them.

## Proof
Fixtures with a known-vulnerable crate / Swift package (red) and a clean one (green); unit tests; selftest case; mutants killed.
