# F099.12 — A headless clipper engine; the sites draw their own popup

> Story under F099. Priority high. Status: backlog — owner direction 13/10, waiting for his go to build.

## Motivation
Owner, 13/10: «hvorfor er det reelt set dog der skal styre den del. Det jeg så der var smart i en fælles pakker er blevet et åg over hovedet på mig og 2 andre agenter. Design skal styres af det site der ejer Web Clipper du skal tage dig at backend og data etc.»

Today `ClipperPopup` (in /ui) owns layout, texts and styling, so every design wish from Jam or Trail (fixed height, a status line, a text) goes through components and a release. That is the yoke. The value of the shared package is the engine: login (BrobergID, background login, no cookies), reading the page (chat readers, whole conversations, artifacts, completeness), and sending (fingerprints, chain, retries, consent).

## Design
- New export: a headless engine — `createClipper(options)` (framework-free state machine) + `useClipper` (Preact hook on top). It exposes state (phase, targets, chosen target, clip result incl. `sent`, `completeness`, consent pending, error) and actions (login, logout, choose, clip, consent). No elements, no CSS.
- `ClipperPopup` is rebuilt ON the engine, so the reference UI can never drift from it; it stays for anyone who wants a ready popup, marked optional in the README.
- Jam and Trail draw their own popup on the engine when they choose; nothing forces them to move.

### Rejected
- Deleting `/ui` now: a naked cutover — Jam and Trail ship on it today. Replace, prove, then (maybe) remove.
- More options/props on ClipperPopup for every design wish: exactly the yoke.

## Reuse
Extends @broberg/web-clipper; no new package.

## Rollout
Minor release; report + a short «draw your own popup» guide to jam and trail.
