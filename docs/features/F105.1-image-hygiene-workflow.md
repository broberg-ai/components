# F105.1 — Den genbrugelige image-hygiejne-workflow

Se epicen `docs/features/F105-image-hygiene-engine.md` for hvorfor og kontrakten med cardmem.

## Scope
- `.github/workflows/image-hygiene.yml` som `workflow_call` med inputs `app` (Fly-app), `config` (sti til fly.toml, default `fly.toml`), `dockerfile` (valgfri), `reason` (`nightly|manual`) og secret `FLY_API_TOKEN`.
- Trin: checkout → flyctl → `flyctl deploy --build-only --push --no-cache --image-label hygiene-<sha>-<run>` → `flyctl auth docker` → Trivy JSON mod imaget → `scripts/image-hygiene-decide.mjs` → udrul `--image` hvis ikke blocked → meld status.
- `concurrency: image-hygiene-${{ inputs.app }}`.
- Beslutning i et rent script med tests.

## Rapportering
Afventer cardmems svar på hvordan en GitHub-kørsel melder uden delt nøgle. Indtil da: job summary + en `status.json`-artefakt med kontraktens felter.

## Non-goals
Renovate (F105.2), natstyring (cardmem).
